# SourceMaker 0.8.1 本地修复记录

2026-10-28，仅本地修改、测试和打包；不提交、推送 GitHub，不发布源文件。

## 新截图：Gaze 的证书错误

同一台机器、同一网址复现：Python 默认系统信任报 `SSLCertVerificationError`，校验码 20，缺少本地签发者；使用 Mozilla 根证书或系统与 Mozilla 合并信任时均返回 HTTP 200。证书元数据显示签发者为 Cloudflare TLS Issuing ECC CA 4，证书并未过期。

修复是在桌面 HTTP 获取、脚本接口请求和可选 AI 接口中显式使用合并证书信任，声明 certifi 依赖，并通过 PyInstaller 明确收集证书数据。继续检查证书链和主机名；不启用不安全连接，不更改系统证书库。

Gaze 读取恢复后发现了另一处问题：语义 article 卡片及根目录哈希作品路径未被识别，旧规则反而匹配到 `/filter` 导航。现在读取约 153 个同站候选，排除外站广告卡片。详情随后返回“安全验证”页面，且后续部分请求出现 HTTP 429；完整制源仍未通过，不能宣称 Gaze 已能直接保存可用源。

## 其他修复

- 空 `<h1>` 不再覆盖有效 `<title>`；两者为空时可使用已识别作品标题，后续仍必须验证选集和媒体。
- 统一识别安全验证、人机验证、访问验证及常见英文验证标题。桌面 HTTP、浏览器采集和生成 JS 均返回明确验证提示，不把验证页当成作品。
- 浏览器会话已连接后，详情需要人工验证时保留会话并显示继续入口；完成后点“已完成，继续制作”重新检查。
