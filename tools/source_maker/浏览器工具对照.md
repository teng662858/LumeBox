# 浏览器工具怎么帮助制源

制源需要“读到网页 → 找到作品列表 → 提取详情和选集 → 找到媒体或图片 → 生成符合 App 协议的代码并验证”。浏览器工具主要解决前半段，不会自动让所有网站成为可用源。

## 工具对照

以下核对于 2026-10-27。同名仓库较多，链接限定了这里讨论的项目。

| 工具 | 用途 | 对制源的价值与本次处理 |
| --- | --- | --- |
| [iv8](https://github.com/HanZzzzz000/iv8) | Python 中运行 V8，模拟 DOM/BOM 等浏览器环境，无需启动完整浏览器 | 适合有针对性的 JS 环境兼容研究。模拟环境仍有边界；本次没有替换真实浏览器，也没有新增 iv8 依赖 |
| [Browser MCP / ai-browser-mcp](https://github.com/ywleeo/browser-mcp) | 本地 MCP 服务配合 Chrome 扩展，让 AI 读取页面、点击、滚动和输入 | 适合 AI 辅助观察登录后的页面。0.8.0 尚未接入此扩展协议，当前选择 Microsoft Playwright MCP 作为首个 MCP 引擎 |
| [PilotBrowseMCP](https://github.com/EndymionLee/PilotBrowseMCP) | AI 操作真实 Chrome，探索网站、形成并复用操作手册 | 可帮助复杂流程分析。本工具已有有界点击、滚动、等待动作；本次没有接入其手册解释器或 AI Agent |
| [MCPBrowser](https://github.com/cherchyk/MCPBrowser) | 基于 Puppeteer 的 MCP 浏览器服务，支持渲染和人工验证后的页面读取 | 与现有真实浏览器采集重叠；没有另外打包一套 Puppeteer 服务 |
| [crawl4ai-mcp（jeffmm）](https://github.com/jeffmm/crawl4ai-mcp) | 将 Crawl4AI 的网页搜索、单页/多页及深度抓取提供给 AI | 适合资料采集；Markdown 清洗不能代替制源所需 DOM、选集和媒体校验。现有批量制源使用 Scrapy；本次未新增 Crawl4AI 引擎 |
| [Playwright MCP](https://github.com/microsoft/playwright-mcp) | 将 Playwright 的浏览器操作和结构化页面快照提供给 AI | 0.8.0 实际接入 0.0.83 的 stdio 初始化、工具发现、导航和页面求值；支持隔离 Edge、当前 DOM、加载操作及制源验证。需 Node.js 和附带安装脚本；MCP 通道尚无 JSON 响应体记录 |

MCP 是 AI 调用工具的协议；MCP 服务本身不是会独立理解所有网站的 AI。0.8.0 另有可配置 AI 辅助：用户提供 Chat Completions 兼容接口、模型和密钥，点击发送后才向该服务提供精简网页结构，接收 CSS 规则并做本地兼容检查，由用户应用后再验证链路。这是有界规则建议流程，尚不是任意工具自主探索的 Agent。未配置、未点击 AI 分析时不会调用模型。

## 现在怎样使用

1. 先输入有封面的作品列表页，点击“开始制作”。
2. 页面动态加载、需要登录或验证时，点击“用浏览器重试”，手动完成后点“已完成，继续制作”。
3. 后来在同一浏览器中找到了更合适的列表页，点“读取浏览器当前页”。支持推荐 Edge、Playwright、Selenium 和内置浏览器；不支持 Scrapling 的临时抓取页。读取不会先导航回旧首页。
4. 需要点击加载更多、滚动或观察 JSON 响应时，使用“高级设置 → 浏览器操作 / 接口记录”。接口记录仍只辅助适配，不自动当作可用接口。
5. 检查通过后保存。继续制作时点“制作下一个源”，也可直接换网址后开始。重置会取消旧任务并清空站点设置，已经保存的源文件与默认保存目录保留。
6. 固定规则识别失败时，可点主界面“AI 辅助识别”。先检查列表结构；需要详情/选集规则时，在已连接浏览器中进入对应页面，再选相应页面用途。详细设置见 [README](README.md)。

当前页快照只用于本次入口识别；导出的源仍按入口网址重新获取页面。若列表只能靠复杂手动操作出现，需要配置可重复的加载动作或另外适配，不能只凭一次快照保证手机可用。Windows 登录态不会自动传到手机。

## 截图中的错误意味着什么

- “没有识别到内容链接”：可能只有静态外壳，或列表结构没有被识别；浏览器采集可能有帮助。
- “当前可能是导航、人物或分类页”：候选链接没有通过详情/选集验证；应确认真实作品卡片和列表入口。
- “HTTP 403”：服务器拒绝了当前请求；需人工验证、登录或确认站点可访问，换一个 MCP 不保证恢复。
- “没有识别到章节或播放线路”：读到列表不代表播放器协议已适配，需要进一步分析公开页面/接口。

以上是根据截图文字做的分类，不代表截图中各网站已经逐站修复或实际播放验证。

## 开发验证

在本目录运行 `python -m unittest discover -s tests -v`，验证连续导出、旧任务丢弃、站点设置清理、当前页入口识别与跨站/大小限制。

运行 `python app.py --engine-check ../../build/source-maker/engine-check-0.7.9.json`，用本地教学页面验证浏览器真实 DOM、加载动作、响应记录和当前页读取。`build.ps1` 完成依赖检查、测试与 EXE 打包，EXE 的 `--self-test` 验证打包后资源和界面。
