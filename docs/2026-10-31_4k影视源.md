## 二、可用的结构

| 用途 | 路径 | 实测 |
|---|---|---|
| 栏目 | `/movie`、`/tv`、`/anime` | 服务端单页：48 / 68 / 33 条，`?page=` 不换内容 |
| 全量片库 | `/filter?page=N` | 30 条/页，**真分页**（第 10 页、第 100 页内容不同，第 300 页空） |
| 搜索 | `/search?q=<词>` | 命中数写在页面里（`找到 3 个结果`）；`q=凡人` 3 条、`q=战争` 11 条 |
| 详情/播放 | `/play/<slug>` | 标题、og:image、meta description、分集按钮（`data-line/data-episode/dataid`） |

卡片：`<a href="/play/<slug>" data-vod="…">` + `<img data-src="封面" alt="标题">`。
搜索页的卡片块比列表页长得多（描述整段在里面），所以解析按「下一个 `/play` 链接」切段，不依赖 `</a>` 位置
（先按 `</a>` 切会漏掉搜索页的全部结果，这个坑在第一版里踩过并已修）。

**筛选**：`/filter` 页的筛选项是 Alpine 前端交互，参数不进 URL（除了 `?page=`），
所以 `filters()` 如实返回空组，不硬编一套看着能用、实际不生效的标签。

## 三、播放：为什么本源给的是「网页播放器」

`/play` 页每个分集只给一个 `dataid`，真正的播放地址是前端现算的：

```
/static/wasm/nbmovie_wasm.js  →  build_play_url(dataid, slug, 清晰度, userlink)
   → /video/play?p=<dataid>&v=<slug>&q=<清晰度>&s=<32hex>&t=<ms>&k=<base64>
   → JSON: {"code":200,"data":{"quality_urls":[{"url":"https://oss.douyinbit.com/m3u8/<32hex>.m3u8"}]}}
```

用 Chrome（headless + CDP 钩 `fetch`）实测到的结论：

1. **s 是必须的**：拿页面里的真实 URL 直接重放 → 200 + 真 m3u8；把 `s` 改成 32 个 0 → **403「你没有权限」**。
2. **s 只随 (dataid, slug, t) 变**：把 wasm 里的 `Date.now` 钉死后反复调用
   `build_play_url(...)`，改清晰度 720/1080、改 userlink 都不影响 s；改 dataid 或 t 就变。
3. **k 不是签名**：它只是 userlink 的双层编码，`base64(xor(salt, base64(xor(salt, "时间戳:vodID=260"))))`，
   游客传 `'0'` 时原样输出 `'0'`（页面上的 `userlink:'X1VUXENZVAQHBg4FCgc7IUlZU0k='` 解出来就是
   `1793501674:vodID=260`）。
4. **salt 找到了，s 的算法没破**：从 wasm 数据段取出明文 `nbmovie2024secretkey`，
   但 s 不是 `md5/sha1/sha256(p + slug + t [+ salt])` 的任何排列/HMAC 组合
   （用 wasm 自身的输出做了两轮穷举：1 万+ 种拼接、1.3 万种 HMAC/前后缀，全部不匹配），
   wasm 里也没有 md5/sha256 的特征常量 —— 算法本身在 wasm 函数体里，沙箱又跑不了 wasm。
5. **m3u8 本身是裸的**：`https://oss.douyinbit.com/m3u8/d8bf5028db4411b9a222f73a56f4748e.m3u8`
   实测 200 + `application/vnd.apple.mpegurl`；但文件名不可由 dataid 推导（试过 md5(dataid/slug/vodID/salt) 全部不中）。

所以本源**不复制签名、也不假装能直连**：`content()` 返回 `kind: "webplayer"`，把源站的
`/play/<slug>` 交给 App 的网页播放器，由站点自己的 wasm 现算签名、拉 m3u8。
分集在站点是前端切换（URL 不带集数），所以 `chapters()` 只给一项「网页播放（共 N 集，在播放器里选集）」。

## 五、限制

- **播放走网页播放器**：不产出直连 m3u8；在 App 的网页播放器里由站点自己解析。选集要在播放器下方点。
- **分类页没有分页**：`/movie`、`/tv`、`/anime` 服务端固定一页；要翻页用「全部影片」（`/filter?page=N`）。
- **搜索要先有会话**：首次直接请求 `/search` 会返回 0 条，本源在空结果时先摸一次首页再重搜（多一个请求）。
- **筛选不支持**：站点筛选项是前端交互，URL 里没有可拼的参数。
- **签名失效**：若站点换 wasm 或换 salt，网页播放器仍由它自己更新，本源不受影响；受影响的是列表/详情解析
  （改版时按新 HTML 调 `parseCards` / `parseEpisodes`）。
- 站内是公开影视聚合站，非 18+，`contentCategory` = `movie`。
