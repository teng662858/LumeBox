# TVBox 聚合配置导入

入口：设置 → 内容与订阅 → TVBox 聚合配置导入。导入目标为视频板块，支持本地 JSON、在线配置地址和粘贴 JSON。

## 使用

读取配置后先预览全部条目，可以按采集、Python、直播或不兼容筛选，也可以搜索名称和接口地址。默认勾选可识别的条目；可取消全选后只安装需要的源。底部悬浮按钮显示所选数量，长列表滚动时仍可提交。

导入采用最多四个任务并行，逐项显示结果；某个下载或脚本加载失败不会阻止其他条目。导入期间可停止后续任务，已经完成的安装保留；覆盖已有同 ID 源前统一确认。导入成功表示源已保存并通过对应运行环境加载，不等于源站、封面和所有播放当前可用。

## 支持范围

| 配置类型 | 支持内容 | 边界 |
| --- | --- | --- |
| `sites` type 1 | 常见苹果 CMS JSON 采集接口 | 实时分类、分页、搜索、详情、多线路分集；站点私有采集协议仍需专用适配 |
| `sites` type 0 | 常见 CMS XML/RSS 接口 | `class/ty`、`list/video`、CDATA 和 `dd flag` 播放线路 |
| `sites` type 3 + Python URL | 下载原始 Python 字节并交给已有 Spider 引擎 | 包含 `.py` 路径及 `?sb.py` 等后缀提示；仍受站点依赖和 iOS Python 能力限制 |
| `lives` 列表地址 | M3U、TVBox TXT；JSON 内联频道分组 | HTTP(S) 频道、多线路、频道分组、搜索和分页；UDP/RTMP 等协议逐项跳过 |
| M3U 属性 | `group-title`、`tvg-logo`、`http-user-agent/referrer`、EXTVLCOPT、URL 后的请求头 | 不导入 EPG、时移和其他客户端专用播放器设置 |
| JAR/CSP | 预览中显示不兼容原因 | 不下载、不在 iOS 执行 Java/Android 插件 |

配置里的 `spider/parses/rules/doh/hosts/flags/ijk/ads` 不会作为可执行指令应用，预览说明里列出。媒体直链交给现有播放器；HTTP 网页播放地址交给现有网页播放器，无法解释的私有令牌显示可读错误。

本地文件中的相对网络路径没有在线基址，会列为不兼容；在线配置中的相对路径按配置 URL 解析。空地址不会被误判为配置文件自身。视频配置不能通过普通订阅入口跨板块导入漫画。

## 保存、更新与恢复

- 采集／直播以元数据头和 `LumeTVBox` 数据描述保存，真实请求通过宿主 `LumeHttp` 发出。XML、JSON 和频道列表由原生 Dart 适配器解析，不把配置 JSON 当作 JavaScript 执行。
- 频道身份根据分组和名称生成，列表换序后不会把旧频道 ID 指向另一个频道。
- Python 保留原始字节，包括 PEP263 编码；配置 `ext` 写入单独头部并作为 Spider 初始化参数，在宿主配置应用后仍保留。
- 从导入页添加的 Python 源记录真实 Python 地址；更新原始脚本时重新保留 TVBox 名称、ID、版本指纹和扩展参数。来源为在线聚合配置的条目可重新展开配置，按 ID 更新。
- 普通订阅解析也能识别 TVBox 配置并生成类型明确的源，不会把 JAR、Logo 或解析器地址当成源下载。含不兼容或失败条目时，不以不完整清单删除旧源。
- 源描述和 Python 包装随现有源备份／恢复链路保存。第三方整包没有自动发布到维护源仓库；新增维护源仍须逐站完成站点与媒体验证。

## 用户文件实测

只读解析桌面三份原始 JSON，没有把用户文件、第三方 Python 脚本或现场日志提交进项目。

| 文件 | 原始条目 | 识别结果 |
| --- | ---: | --- |
| 海量采集聚合接口.json | 285 | 283 个采集候选，2 个 CSP 不兼容 |
| 海量py聚合接口.json | 307 | 306 个 Python 候选，1 个 CSP 不兼容 |
| 海量直播聚合接口.json | 186 | 186 份直播列表地址，数量不等于频道数 |

生产适配器实站抽测：樱花接口返回 33 个分类、20 条列表、样本 18 个选集，内容入口返回视频 URL；样本封面为 `206 image/png`。该样本媒体在本机 curl 探测出现 TLS 握手错误（exit 35），未确认起播，不能据目录成功宣称播放成功。

用户提供的一份远程 M3U 返回 HTTP 200；真实解析得到 119 个频道、4 个分组，跳过 1 个不支持条目，并保留其 `iPhone` User-Agent。上述均为抽样，不代表整个集合已逐源验证。

## 验证与模拟器

Flutter 回归覆盖 TVBox 解析和页面、JSON/XML 五入口、分页搜索参数、多线路、订阅、既有源管理、设置、Python 通道与契约。Python 宿主增加了 TVBox 扩展参数在配置覆盖与 GBK 原始字节下保留的测试。

结果：Flutter 专项 **102 项通过**，Python 宿主 **27 项通过**，完整 `flutter analyze --no-pub` 无问题。Android x64 调试预览 APK 构建、安装和启动成功，模拟器内已实际选择用户采集 JSON，显示 285 项／283 个候选，并成功导入所选的一个采集源。

```powershell
flutter test --no-pub test/tvbox_import_test.dart test/source_subscription_sync_test.dart test/source_packages_test.dart test/source_contract_test.dart test/source_manager_test.dart test/settings_page_test.dart test/python_source_channel_test.dart
python tool/test_python_sources.py
flutter analyze --no-pub
```

Android 模拟器为 `LumeBox_Pixel_8_API_36`。专用预览入口 `tool/tvbox_preview.dart` 使用同一个正式导入页面和实际 CMS／直播适配器，可保存预览源并浏览真实接口。预览包没有 CPython，Python 导入明确失败并提示在 iOS 验证，不伪造成功；正式 App 的平台限制没有因此放开。

```powershell
flutter emulators --launch LumeBox_Pixel_8_API_36
flutter build apk --debug --no-pub -t tool/tvbox_preview.dart --target-platform android-x64
```

本项目 Android 启动入口使用图标别名，Flutter CLI 的 `run` 活动识别未找到启动项时，可先构建，再使用 Android SDK 的 adb 安装 APK 并启动 `com.lumebox.app/com.lumebox.app.MainActivity`。调试构建单独允许 HTTP 测试源，发行版网络配置保持独立。用户的三份配置在模拟器下载目录中分别保存为 `tvbox-cms.json`、`tvbox-python.json`、`tvbox-live.json`。

iOS 最低目标仍为 18.0。本轮为导入能力和 Android 交互预览，没有生成 iOS IPA，也未完成 iPhone 真机验收。
