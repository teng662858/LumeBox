## 二、麻豆TV 接口逆向（可复用）

### 1. 基本信息

- 前端：React + umi + antd，「麻豆TV」SPA（`b5wesi2.xyz`，`umi.624c1e14.js`，1.25MB）
- 后端：`https://spi.d5c4a712.com`（`jsonUrl === apiUrl`，写在 bundle 的 `UmJv` 模块里）
- 全部接口 POST，`Content-Type: application/json`，请求体与响应体都加密

### 2. 加密（AES-256-CBC）

```
key = "Vq234zBeSdGgYXzVTEfnnjjdmaTkk7A4"     // 32 字节
iv  = "-p9B[~PnPs" + suffix                  // 10 + 6 = 16 字节
padding = PKCS7，输出 base64（OpenSSL formatter）
suffix  = 客户端随机生成的 6 位字母数字，同时放在请求头 `suffix`
```

请求体：`{"post-data": base64(AES(JSON.stringify(payload))) }`
响应体：`{"suffix":"<6位>","data":"<base64>"}` → 用响应里的 suffix 解出明文 JSON

### 3. 签名

```
pair   = 每个 key=value（跳过 undefined/null/空串）→ "k=v" 数组
inner  = pair.sort().join("&")
salt   = "m}q%ea6:LDcmS?aK)CeF287bPvd99@E,9Up^"
encode_sign = md5(inner + "&" + salt)
timestamp   = 秒级时间戳（参与签名）
```

### 4. 已验证可用的接口

| 接口 | 参数 | 返回 |
|---|---|---|
| `/video/channel` | `{}` | `code 0`，60 个频道：id/name/desc/image/total |
| `/video/tags` | `{}` | `code 0`，标签表（热门推荐 99、国产 62…） |

### 5. 尚未打通

- `/video/list`、`/video/ranking`、`/video/listcache`、`/video/watchvideopreview` 均返回 `code 1002 参数错误`
- `/video/info` 走通路由但参数名不对
- 下一步只有一条路：**抓到 SPA 路由组件的实际请求体**（对话里 `u({...})` 的实参）。主包没有，需在浏览器里实际点开列表页抓 XHR，或把 `umi.js` 里 `n.d(t,"m",…)/n.d(t,"K",…)` 的导出逐个回填调用链

## 三、黄桃短剧 / 91成人短剧 的会话桥（记录，勿重复踩）

`window.__cloudfrontCompat` 声明了 `endpoint:"/api/edge/request"`，运行时 `edge-cache-runtime.js` 会：

1. 在 localStorage 存会话（`__edge_persistent_session_v1__`，含 `token`）
2. 每次 fetch 被拦截 → 改成 `POST /api/edge/request`，body 为
   `{method, path, body: base64(原文), content_type, visitor_id}`，头带 `Authorization: Bearer <token>`
3. 服务端按真实 Host 决定是否启用；未携带合法 token 时返回
   `{"__edge":{"code":400,"type":"error"},"msg":"请求无法处理"}`

未持会话直接取 m3u8 → `403`（带 Referer 无效）。App 播放器目前只支持 header，不支持 Cookie 会话，所以这条路要先解决"播放器如何带会话"才能落地。

## 四、结论与下一步

1. **麻豆TV 只差最后一步**：拿到 `/video/list` 的请求体参数名即可成套（频道 60 个、总数上万）。建议在浏览器里打开 `b5wesi2.xyz` 列表页，F12 → Network → 找 `spi.d5c4a712.com` 的 `/video/list` 请求，看 `post-data` 解密后的字段（或用本文件的解密脚本直接解抓到的响应）。
2. **短剧两家**：要么放弃，要么先给 App 播放器加 Cookie/会话透传能力，再回来说。
3. 其余 5 组：技术或内容性质上都不适合做源，已给原因。
4. 91md：不建源，理由见矩阵最后一行。
