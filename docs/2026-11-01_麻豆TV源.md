## 一、为什么值得做

- 60 个厂牌频道：麻豆传媒映画（2555）、糖心（1188）、蜜桃传媒（1020）、天美传媒（838）、91制作（556）、91茄子（202）、探花系列（297）、SWAG（261）、JVID、日本AV-4K（1833）、高清动漫（1339）、国产三级片、推特福利姬……
- 列表接口一次返回 `total: 25002`、`last_page: 251`（`list_row=100` 时），每页条数自选。
- **条目自带 HLS 直链**，不需要登录、不需要会员、不需要二次解析。

## 二、接口协议（Chrome CDP 抓真实请求后逐字段还原）

### 1. 请求/响应外壳

```
POST https://spi.d5c4a712.com/<接口>
headers: suffix: <6 位随机字母数字>, Content-Type: application/json, Origin/Referer: https://b5wesi2.xyz

body:    {"post-data": base64(AES-256-CBC(JSON 明文))}
响应:    {"suffix":"<6 位>", "data":"<base64>"}
```

### 2. 密钥与 IV

```
key = "Vq234zBeSdGgYXzVTEfnnjjdmaTkk7A4"      // 32 字节 → AES-256
iv  = "-p9B[~PnPs" + suffix                    // 10 + 6 = 16 字节
padding = PKCS7
```

请求用「请求头里的 suffix」拼 IV；响应用「响应体里的 suffix」拼 IV。

### 3. 签名

```
明文必须带：
  timestamp   = Date.now()（毫秒）
  encode_sign = md5( 过滤空值后的 "k=v" 数组.sort().join("&") + "&" + SIGN_SALT )
SIGN_SALT = "m}q%ea6:LDcmS?aK)CeF287bPvd99@E,9Up^"
```

> 坑：`timestamp` 是**毫秒**。早前用秒级时间戳会一律返回 `{"code":1001,"msg":"签名错误"}`。

### 4. 已验证接口

| 接口 | 参数 | 返回要点 |
|---|---|---|
| `/video/channel` | `{}` | `data[]`：id / name / desc / image / total |
| `/video/listcache` | `{page, list_row, type:2, channel?}` | `data.{total,per_page,current_page,last_page,data[]}`；条目含 `id/title/thumb/video_url/comefrom/comefrom_title/tags` |
| `/video/info` | `{id}` | 单个作品，同样带 `video_url` |

- `channel` 是**字符串**频道 id；不传就是全站。
- `type` 必须给 `2`（给 1 返回 0 条）。
- `keyword` / `tag_id` / `search` 等参数服务端一律忽略 → **没有搜索能力**，源里对 `keyword` 直接抛可读错误。

## 三、源实现要点

- 沙箱没有 `atob` / `Buffer` / `crypto`，所以源里自带纯 JS 的 base64、UTF-8 编解码、AES-256-CBC 加解密和 MD5。
  - AES 查表与加解密来自 `sources/video/cf3.js`（按大括号配平精确抠出，未改逻辑）；
  - MD5 是新写的紧凑实现，已用 `node:crypto` 对 6 组输入（含中文与含盐串）逐字节比对一致。
- 分类 = `/video/channel` 的 60 个频道 + 「全部」。
- 列表 = `/video/listcache`，`PAGE_SIZE=24`，`hasMore = current_page < last_page`。
- 详情 = `/video/info`；选集只有一项「播放」；播放 = 条目 `video_url`（带 `Referer: https://b5wesi2.xyz/`）。
- 列表返回的 `video_url` 会缓存到 `known`，`content()` 优先用缓存，省一次接口往返。
