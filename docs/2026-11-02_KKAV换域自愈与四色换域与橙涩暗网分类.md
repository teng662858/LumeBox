## 一、KKAV：旧域 /api/* 406，主站已换到 32auqm

| 项 | 实测 |
|---|---|
| 旧主站 `www.85fazc.com` | 根路径 200 但**只是一张跳板页**（1999 B），`/api/*` 全部 **406**（截图那句错误就是它） |
| 跳板页内容 | `eval(decodeURIComponent('url2%2Epush%28%2232auqm%2Ecom%22%29…'))` → 解出 `32auqm.com` |
| 新主站 `www.32auqm.com` | 302 → `/index.htm`（uni-app H5，3200 字符）；`/api/config/ini` 8169 B、`/api/movie/tags` 1926 B、`/api/movie/home_sections` 16 KB、`/api/movie/list` 10.8 KB，**全部 200 + XOR2 信封** |
| 播放 | 列表自带 `h264mp4url`，`down.baidu.com` 改写为 `down.mm7878.com` 后 **206 video/mp4（262 KB）** |
| 封面 | `smallpic` 的 `sq.2277ww.com` 仍连不上 → 同路径换 `fengmian.gszy12348.com/data/`，200 image/jpeg |

改法（v1.2.0）：

- `BASE_URL` → `https://www.32auqm.com`，`mirrors` = `[32auqm, 85fazc]`；
- 新增**两段式域名发现**：
  - `SEED_HOSTS`（真站）：`probeHost()` 用 `/api/movie/tags` 校验「200 + 含 `"enc"`/`"d":"`」，过了才算真站；
  - `JUMP_HOSTS`（只回跳板页的旧域 `85fazc / 73tfhk / 37tmrj / ttss66`）：先看 `reply.url` 的 origin
    （旧域可能直接 302 到新域），再从正文解 `url2.push("新域")`，逐个探活；
  - 命中写 `host.json`（12 小时）；失败写 `discover.json` 退避 10 分钟；
- `call()` 遇到非 200（换域那一刻）会清主机缓存 + 清退避，重走一遍发现链再取一次。

复验：

```
node tools/lume-source-check.mjs sources/video/kkav.js      → PASS，32 分类 / 20 条 / mp4 206
# 手选旧域（模拟旧订阅里存的 85fazc）：
categories(domain=85fazc) → 85fazc/api/movie/tags 406 → 自动落到 32auqm 200
# 连 SEED 也拿掉（强制跳板页路径）：
categories(domain=ttss66, SEED_HOSTS=[]) → ttss66 406 → 85fazc 跳板页 200 → 解析出 32auqm → 200
```

## 二、四色视频：y1c5w / q5h7m 整站 302 到 m9y7a

| 项 | 实测（2026-11-02 22:2x） |
|---|---|
| `www.y1c5w.top` / `www.q5h7m.top` | 含 `/index/home.html` 在内**整站 302** → `https://www.m9y7a.top/enter/index.html`（进入页 4513 B） |
| `www.m9y7a.top` | `/index/home.html` **200 + 75 016 B + 有 video-item**（真首页） |
| `www.zie2.com` | 本机 TLS 握手失败（境外 + 被墙），仍只作跳转服务种子 |

问题根因：v1.1.0 的自发现只走「站方跳转服务 good.0827.la」这条路（`JUMP_SEEDS`），
而两条腿里更可靠的那条没实现——**旧域 302 的最终地址就在 `reply.url` 里**，脚本当时只把它当「进入页」丢掉。

改法（v1.2.0）：

- `SITE` / `mirrors[0]` → `https://www.m9y7a.top`，旧域仍在表里（能跳就能自愈）；
- `fetchFrom()` 返回 `moved`（`reply.url` 的 origin，且与请求主机不同）；
- `getText()` 遇到 `gate` 且带 `moved` 时，把那个 origin 插到下一台试（上限 3 次），成功即 `rememberHost()`；
- 跳转服务保留为兜底。

复验：

```
node tools/lume-source-check.mjs sources/video/d9y1w.js    → PASS，27 分类 / 20 条 / m3u8 206 + #EXTM3U 32.9 KB
# 手选旧域（模拟用户当前拿着 y1c5w）：
home(domain=y1c5w) → y1c5w/index/home.html 302→ m9y7a/enter/index.html
                   → m9y7a/index/home.html 200 75016 B → 出 3 块
flutter test test/d9y1w_source_test.dart                   → 4 个用例全过
  （新增「旧域 302 到新域时按最终地址自愈（不依赖跳转服务）」；
    原「主域只剩进入页换镜像」「全废问跳转服务」两条按新主域改写）
```

## 三、橙涩视频：暗网板块里的分类（子分类）

站点「暗网」页（前端 `js/darkWeb-B8H-aILg.js`）的数据是 `findClassifyList({needVip:true})`，
游客 token 只回 **一条**：

```json
{"classifyId":11,"classifyTitle":"暗网流出","type":3,"needVip":true}
```

`type` 枚举（`js/video-9NzzKweB.js`）：0 Normal / 1 单列 / 2 频道 / **3 子分类** / 4 短剧 / 5 排行榜。
`type=3` 在站点上是「子分类聚合页」：点进去先列子分类，再进子分类视频。实测子分类：

```
GET /api/video/findSubClassify {classifyId: 11}   (GET，参数 AES 加密同上)
→ 126 圣水滋养 / 127 恐怖电影院 / 128 黄金盛筵 / 129 全球禁片 / 130 重口调教
POST /api/video/findSubClassifyVideos {classifyId: <子分类 id>, page, pageSize}
```

（`findSubClassifyVideos` 的参数就叫 `classifyId`，传 `subClassifyId` 会报错。）

所以 v2.1.1 里点「暗网 · 暗网流出」只能看聚合流，站点上那 5 个分类在 App 里根本看不到。

改法（v2.2.0）：

- `loadCats()` 记下每个分类的 `type`；对 **暗网板块（needVip）里 `type===3`** 的分类调一次
  `findSubClassify`，展开成独立分类项：id `sc<子分类 id>`、标题 `暗网 · 圣水滋养` 这种；
- 展开结果一起进分类缓存（`chengshe.cats3`，key 换版本避免旧缓存不带子分类）；
- `list()` 增加 `sc<id>` 分支 → `listSubClassifyVideos`；
- 顶层 `c11`（暗网流出聚合）保留，内容与子分类不同（子分类 126 首条 167181、129 首条 167663、聚合首条 167181 但含两类）。

复验：

```
node tools/lume-source-check.mjs sources/video/chengshe.js   → PASS，18 分类（13 顶层 + 5 暗网子分类）
categories() → hot / serial / c15 / c18 / c1 / c19 / c20 / c3 / c21 / c2 / c4 / c5 / c11
              + sc126 暗网 · 圣水滋养 / sc127 恐怖电影院 / sc128 黄金盛筵 / sc129 全球禁片 / sc130 重口调教
list(sc126) → 20 条，首条 167181；list(sc129) → 20 条，首条 167663（两分类不同）
detail(167181) → canWatch=false，reasonType=5（DarkNet），标签「暗网」
content(167181) → pic.tbem.org/…/hls/….m3u8，200 + #EXTM3U 33.5 KB（AES-128 index.key 可取）
```

## 四、限制

- 三个站都靠随机/轮换域名，域名表会继续老化；本源都做了自愈，但**跳板域本身被墙**时仍需用户点
  「源设置 → 打开发布页 / 打开最新地址」；
- 橙涩的 `findClassifyList {needVip:true}` 对游客只回一条暗网分类；若站点给「永久至尊」账号回更多，
  本源会把它们一并按 `type=3` 展开（逻辑已通用，不需要再改）；
- 橙涩普通分类（国产/欧美/AV…）在站点上也是 `type=3` 子分类页，但顶层 `findClassifyVideos` 已能给聚合流，
  所以只展开了暗网板块，避免分类栏被 100+ 项淹没。
