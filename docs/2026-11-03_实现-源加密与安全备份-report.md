# 源加密能力与安全备份

日期：2026-11-03。范围、授权与时间线见 [security-scope.md](analysis/arcane-rex/security-scope.md)。普通兼容性逆向与安全实现，flavor = null。

## 已实现的行为

1. 猫源同步 `crypto` 经有预算限制的宿主桥执行原生算法；安全随机数来自系统熵源，失败时不回退伪随机。
2. 配置手动导出必须设置并确认密码；备份采用 PBKDF2-SHA256（210,000 轮、随机 16 字节 salt）及 AES-256-GCM。派生密钥放在独立 isolate 计算；恢复先认证解密和校验全部结构，再修改配置。旧版明文备份仍可导入。
3. 自动备份、恢复前快照使用本机密钥加密；应用内旧明文快照在启动维护或访问备份目录时原子迁移。源账号、密码、扩展设置、Cookie、源代理及阅读库中的运行时设置在 SQLite 中认证加密，打开旧库时迁移并清理 WAL/空闲页中的旧内容。
4. REXENC v2 的官方取钥、AES-GCM 认证解密和原生 QuickJS 执行已接通；源库继续保存加密原文，明文不回写。原有导入身份、设置、更新路径保持一致。

本机主密钥在 iOS 使用 Keychain 的 AfterFirstUnlockThisDeviceOnly 属性，在 Windows 使用当前用户 DPAPI 保护后保存；不把原始主密钥写入配置或导出备份。新设备恢复使用带密码的手动导出文件；自动备份仅用于原设备。外部保存过的旧明文导出文件不会被应用远程改写，需重新导出加密版本。

## 猫源 API 范围

| 类别 | 支持 |
| --- | --- |
| 摘要、HMAC | MD5、SHA-1、SHA-224、SHA-256、SHA-384、SHA-512；二进制输入、Buffer/编码输出 |
| 对称加解密 | createCipheriv/createDecipheriv；AES-128/192/256 的 CBC、ECB、CTR、GCM、CFB-128、OFB；PKCS7 或关闭填充；GCM AAD 与认证标签 |
| RSA | PEM PKCS1/PKCS8/SPKI；publicEncrypt/privateDecrypt/privateEncrypt/publicDecrypt；PKCS1 v1.5、OAEP 自选摘要和 label、NO_PADDING；RSA PKCS1 v1.5 签名/验签 |
| 派生 | PBKDF2、HKDF、scrypt，包含同步与回调形式；限制轮数、输出和内存成本 |
| 随机 | randomBytes、randomUUID、randomInt、randomFill/randomFillSync、getRandomValues；randomInt 使用拒绝采样，随机填充修改原 Buffer/TypedArray |

这是明确的常用 Node API 兼容范围，不是完整 OpenSSL/Node 运行时：未实现任意非 AES/RSA 算法、RSA-PSS、EC 密钥 API 或所有 WebCrypto 操作。Cipher 当前为有界缓冲实现，update 累积输入，final 返回结果；不能当作无限流 Transform 使用。单次数据受脚本/宿主预算和大小上限约束，仍不开放文件、端口或进程。

## REXENC 协议与实际源验证

Arcane 的内容密钥加载函数从信封读取 `mkv` 和 `kb`，向固定 HTTPS 官方服务 `https://api.rexnow.tv/api/widgets/key-session` 发送 JSON，响应的 `key` 是 Base64 编码的 32 字节 AES 密钥。对应原始函数虚拟地址：contentKey `0x100404f3c`；请求闭包 `0x100405e60`；响应 key 读取 `0x10040636c`；GCM open 调用 `0x100404bb8`。前轮 IPA 身份与 SHA-256 见 [Arcane 分析](2026-11-03_逆向-Arcane-REX兼容分析-report.md)。

本实现校验 v=2、alg=A256GCM、mkv=rex-1、IV 12 字节、kb 60 字节及密文长度。服务请求使用独立宿主客户端，不继承源 Cookie、账号请求头、WebView 会话或 URL 重写；不跟随取钥重定向。密钥只在加载器内存短期缓存（15 分钟，最多 32 项），并发同信封请求合并；失败不缓存，认证失败清除对应缓存，销毁引擎清理密钥。响应大小限制 16KB。

## 验证和限制

最终相关回归 **201 项全部通过**，覆盖 crypto、数据库迁移、阅读设置、备份与空设备恢复、源账号设置、源存储、猫源原生运行时、REX、参数及备份密码 UI。全项目 `flutter analyze --no-pub --fatal-infos lib test` 无问题；`git diff --check` 通过。另做五份原文件的真实加载（5 项通过），以及两份源的在线详情/选集/地址解析（各 1 项通过）；这些在线检查不代替离线回归。

Windows QuickJS 原生桥本轮已重新编译。桥接修复包括同步 JSValue 返回值的 C++ 包装所有权、消息字符串释放和参数检查；使用重编译产物再做原生验证。iOS Keychain 代码复用已有原生注册文件，最低目标继续为 iOS 18.0；本机没有 Xcode，未生成 IPA、未执行 iOS 真机视频解码。

原生/域名可达性与播放鉴权仍必须按具体站点验证。以上在线通过的是播放地址解析，不把它写成已经完成真机连续播放。没有新增、改写或发布订阅源，因此本轮不涉及源仓库与 CDN 的双线路内容更新。
