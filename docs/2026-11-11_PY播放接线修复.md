# PY 播放接线修复

诊断包来自 iOS 1.0.306。截图中的播放源为橘汁视频4K（`python_22601802e0bf0f350993e2f2`）；另有红果本地地址超时，以及多个远端媒体地址在 AVPlayer 装载失败的记录。日志不能证明所有源站地址本身可用。

本次只修改 App，不修改用户提供的 PY 文件：

- 预启动必须检查错误快照；准备中或接手前失效的实例释放后重新创建，不能标记为已装载。
- 首次播放、恢复和下一集预载共用缓存装载入口。缓存地址失败时保留原始请求头直接重试原始地址；只有直接装载成功才在本次会话内绕开该资源的缓存。
- 为自建 Python 服务及媒体缓存添加精确的 `127.0.0.1` / `localhost` ATS 例外。依据 [Apple 的 ATS IP 地址说明](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking)，不放开全局 HTTP。
- Python `requests` 桥接将宿主连接失败和超时转为对应的 `RequestException` 子类，让原脚本已有的备用线路和重试逻辑生效。
- 图标模式删除下集按钮下方的小字；无剧集目标或目录已确认末集时隐藏该按钮，保留长按续播状态入口。

验证包含缓存异常返回及抛出异常的回退、错误预启动实例、末集目录状态、播放器页面和 PY 通道回归。六个普通影视原始 PY 文件另做离线加载、依赖和分类检查，金牌覆盖离线搜索至取流。离线用例不能代替所有源的真机联网播放；iOS 原生配置需安装包含本次修改的新构建验证。
