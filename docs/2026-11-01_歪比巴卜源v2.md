# 2026-11-01 歪比巴卜源 v2.0.0（改成「按集打开播放器」）

站点：歪比巴卜（wbbb1.com；发布页 `xn--clr79vmzkema.com`）。苹果CMS v10 + 自定义主题。

## 一、v1.0.0 的问题

`content()` 返回的是 `{kind:'webplayer', url: '/detail/{id}.html'}` —— **打开的是详情页**，
那是片库页（简介 + 线路列表），不是播放器，所以用起来「不像在播放」。
章节也只有一条「网页播放（N 条线路，在页面里选）」。

## 二、v2.0.0 做了什么

1. **解析播放源与分集**：详情页 `#y-playList` 里有 `data-dropdown-value="高清C"|"蓝光B"|"BF有广"|"LZ有广"…`
   的 tab（带集数），下面按同样顺序跟着若干个 `module-play-list` 分集面板（`/vplay/{id}-{sid}-{nid}.html`）。
   本源把 tab 名与面板按顺序对上，**线路 × 分集全部展开**成章节，例如
   `高清C · 1080P · 第 1 集` / `蓝光B · 1080P · 第 1 集` / `BF有广 · HD · 第 1 集`。
2. **按集打开站点播放器**：`content()` 取这一集的 `/vplay/{id}-{sid}-{nid}.html`，读出 `player_aaaa` 里的
   密文 `url` 和 `link_next`，拼出站点 `parse.js` 自己用的播放器地址：
   `https://xn--qvr2v.850088.xyz/player/?url=<密文>&next=//<域名><下一集>&title=<标题前半段>`
   → 交给 App 的网页播放器。**打开就是这一线路这一集的播放器**，不再落回详情页。
3. 兼容两种 `player_aaaa`：电影页是原样 JSON，剧集页是转义过的 JSON 字符串（`\"flag\":…`）。

## 三、解析接口签名（已逆出，实测被服务端接受）

播放器把整条 query 当 `url` 传给解析接口：

```
Q      = <密文> + '&next=' + ('//' + 域名 + link_next   或   '//')
key22  = md5(Q) 取后 20 位 hex 再拼 ' P'                 （站点里的 calculate）
key    = base64( rc4(key22, md5(Q + 'stray')) )           （enplay）
vkey   = base64( rc4(key22, 秒级时间戳 + md5(key22 + 'stray')) )
ckey   = base64( rc4(key22, md5('<播放器域名>' + 'stray')) )
POST https://xn--qvr2v.850088.xyz/player/api.php {url:Q, key, vkey, ckey}
```

- `aesplay` 就是**标准 RC4**（用 `aesplay(key,"abc")` 与 Node 的 RC4 逐字节比对确认）。
- 实测回显：`{"code":200,"url":"Smw1unKD…","type":"mp4",...}`；`key`/`ckey` 错一个即 **nginx 404**，
  `vkey` 传错仍可 200 —— 说明服务端只校验 key/ckey。

**没有继续做原生播放的原因**：解析接口回的那段 `url` 是**二次加密**的（响应同时下发
`aes_key` / `aes_iv`，由播放器页面自己的混淆 JS 现解）。逐一试过 RC4（key22 / aes_key / 全 query）与
AES-128-CBC/ECB（key=aes_key、iv=aes_iv / 前 16 字节 / 全零、有无 padding），解出来都不是可播地址。
所以本源**不伪造 `video()`**，仍走网页播放器，但把「打开哪一集」这件事做对了。

## 四、验证

```
node tools/lume-source-check.mjs sources/video/wbbb.js
=== [PASS] 歪比巴卜
  home 24 条 / categories 4 / list 72 条 / detail ok
  chapters 4 条（高清C · 1080P · 第 1 集 …）   ← 线路 × 分集
  content webplayer → https://xn--qvr2v.850088.xyz/player/?url=…&next=…&title=…
```

手动复验：`/vplay/115768-3-1.html`（剧集）→ `from=abc`、密文 171 字符、`link_next=/vplay/115768-3-2.html`，
拼出的播放器地址 **HTTP 200 / 2756 B**（播放器外壳，内部由站点 JS 起 Artplayer）。

## 五、限制

- 播放仍是 App 的**网页播放器**（不是原生 video）：媒体地址的二次加密未破。
- 站内搜索被 WAF 拦，沿用本地索引（浏览过的条目可搜）。
- 部分线路的解析服务会抽风（`api.php` 时而 404/解析失败），换一条线路即可。
