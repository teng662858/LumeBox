# 系统播放器与 Aether 卡死排查

> 此文记录前一轮小修。该轮原生检查、模拟器检查及当时的构建随后通过，但用户已授权进一步替换播放链路。当前实现和功能边界见 [原生视频播放页重建](2026-11-12_原生视频播放页重建.md)，下文旧文件和命令仅用于保留排查经过。

用户在 1.0.319 反馈：系统播放器起播很慢，起播后播放页控件不能点击；切换 Aether
卡死并闪退。本轮修复代码中可确认的阻塞与取消缺口，尚不能据此认定真机闪退已解决。

## 证据与改动

| 证据 | 发现 | 处理 |
| --- | --- | --- |
| 用户诊断 ZIP，App 1.0.319 | AVPlayer 装载 20606ms，随后触发 buffered-startup-stalled；MPV 接管后 859ms 进度推进 | 不把这些阶段等同于 Aether 崩溃，也不把全部等待归到一个原因 |
| FVPVideoPlayer 初始化和 seek | 主线程同步读 asset.duration；seek 用毫秒目标比较原始 time value | 使用 item 的已有时长，仅允许读取已加载的 asset 时长，统一毫秒比较 |
| 原生音轨 API | 同步读取 media selection group | iOS 宿主改用异步加载的 presentation 通道 |
| presentation 状态轮询 | Dart 超时不会取消仍在加载的原生任务 | 同一 item 只保留一个在途状态读取 |
| Aether 停止回归 | stop 原先排在正在等待的 load 后，不能取消它 | stop 绕过队列、取消装载等待；原生代次拒绝旧装载完成 |
| Aether 显示与事件桥 | 快照与时钟重复更新字幕，多个时钟分别发送完整快照；释放时未显式解绑 view | 合并为至多每 100ms 一次快照与字幕更新，释放先解绑显示面 |
| 两种 Apple 原生画面 | 视频面没有交互需求 | Flutter IgnorePointer 与原生禁用触摸，所有播放操作交给 Flutter |

[Apple 的异步媒体加载说明](https://developer.apple.com/documentation/avfoundation/avasynchronouskeyvalueloading)
明确指出未加载属性的同步读取会阻塞调用线程；远程媒体读取不得放在界面主线程等待。

## 验证

本地 77 项播放器回归通过，涉及 Aether 装载/停止/释放、AVPlayer 请求头/缓冲/跳转、
内核切换恢复、手势与展示设置。新增 Aether 用例在原生 load 一直不返回时要求 stop
及旧 load 在 1 秒内收尾，并能加载新媒体，旧任务晚到不覆盖新状态。

改动 Dart 文件与模拟器集成用例静态分析通过。原生检查新增未知时长的行为验证，
四内核模拟器用例增加真实画面上方按钮在起播、播放、暂停和跳转后的点击断言。
本次提交时 iOS 原生及模拟器验证尚未执行，随后由 check-playback 工作流执行。

```powershell
flutter test --no-pub test/aether_player_test.dart test/player_kernel_params_test.dart test/player_switch_recovery_test.dart test/playback_presentation_test.dart test/player_gestures_test.dart
flutter analyze --no-pub lib/core/player/av_player.dart lib/core/player/aether_player.dart test/aether_player_test.dart integration_test/playback_smoke_test.dart

```

## 边界

原始诊断包没有 Aether 的 iOS crash/ips 堆栈，无法确认是 watchdog、内存终止还是
其他原生异常。此次代码修复与模拟器用例不替代用户设备、原视频和实际网络复验。
集成测试通过 Flutter 注入点击，不能单独证明 UIKit 真机触摸投递正确。
未知/直播时长没有有限值时返回 0，不为获取时长阻塞初始化。未改变缓冲上限、最低
iOS 18 目标、源脚本与私有订阅。原始日志、诊断包及临时产物不提交。
