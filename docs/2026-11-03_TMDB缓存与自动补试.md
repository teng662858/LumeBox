# TMDB 缓存与自动补试

2026-11-03。本次修改 App，不改源订阅。

- 详情页按源 ID、条目 ID 和列表标题保存已确认的 TMDB 资料缓存。再次进入同一条目时，可在源详情请求结束前先显示该缓存；源返回标题、年份、影片类型后继续按原规则复核。未建立过此缓存的条目，首次仍需等待源信息及 TMDB 请求。
- 缓存身份使用结构化键，并包含 API/图片线路和图片尺寸配置，避免只凭片名复用其他源、其他条目或旧图片配置的缓存。
- TMDB 资料在内存缓存更新后即可返回界面，磁盘写入仍串行排队，可以通过 flush 等待，不阻塞首次显示。损坏缓存按未命中处理。
- 单次 HTTP 的连接、响应头和响应体共享 12 秒预算，避免连接和读响应分别占用完整预算。原有请求级重试仍生效，因此该预算不代表整个匹配流程最多 12 秒。
- 网络错误、HTTP 429/5xx 或未找到匹配时，控制器等待 2 秒补试一次。持续失败不循环；关闭详情、配置变化、重新匹配及手动选中条目时，通过序列检查/取消定时器避免旧补试覆盖新结果。
- 同名歧义、年份冲突、401 鉴权失败和无效响应不自动反复尝试。没有实际 TMDB 条目的作品仍需手动查找或保留源站资料，不能保证所有作品都能匹配。

针对性回归验证同条目提前显示缓存、不跨源复用、空结果自动恢复、最多补试一次、歧义不补试及关闭后取消；同时运行 TMDB、手动匹配、连接、设置及视频详情回归。此验证使用模拟响应，不代表 iPhone 到实际 TMDB/代理线路的测速结果。需安装包含本次提交的 App 构建才能生效。
