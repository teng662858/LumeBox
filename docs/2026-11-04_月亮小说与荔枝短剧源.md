## 一、月亮小说（yueliangxiaoshuo.com）

- PHP 渲染的静态 HTML，含 **R-18 分区**，全部免费、不用登录。
- 频道：新书 `/novel/new?p=N`（30 条/页，实测可到 p=100）；榜单
  `/novel/ranking?mode=daily|weekly|monthly|rookie|total` + `r18=0|1|2`。
- **筛选**：分级（全部 `r18=1` 50 条 / 普通 `r18=0` 22 条 / R-18 `r18=2` 25 条），
  实测三档首条分别是「豪乳老师刘艳 / 将进酒 / 朱颜血」，互不相同。
  `r18` **只对榜单生效**（`/novel/new?r18=2` 与不传完全一样），源里只在榜单通道用它，文件头写清了。
- 详情：`/novel/series/{id}`（书，h1 = 书名，目录 30 章/页，`?p=N`，实测一本 1385 章要 47 页）；
  单章 `/novel/show/{id}`（正文 `div#novel-body` 的 `<p>`）。
  列表条目两种落点都有，源里用 `series:{id}` / `show:{id}` 区分。
- 搜索 `/search/novels?q=&p=`。
- 章节目录 6 路并发抓取（1385 章 4.5 秒），封顶 60 页。
- 实测：`content` 取「豪乳老师刘艳 第五部 第九十四章」= 3017 字、363 ms。

## 二、荔枝短剧（liz01.com）

- Nuxt3 + SSR 首屏的 **AI 成人短剧**站。
- 频道 `/category/`（48 部）、`/original/`（荔枝原创 37 部）、`/featured/`（荔枝精选 48 部）；
  题材 `/en/tag/{slug}/`（站上 30 个，源里放 24 个中文标题）。
- 播放：单集页 `/en/drama/{id}/ep-{n}/` 的 JSON-LD `VideoObject.contentUrl` =
  `/api/v1/cdn/video/{uuid}/manifest.m3u8?t=…&sign=…`（SSR 现签）。
  实测直接 GET → **206 + application/vnd.apple.mpegurl + `#EXTM3U`**（22,969 B master），
  不需要 Referer、不需要登录。签名带 `t`，所以每次取流都现开单集页。
- **封面是 AES-128-CBC 密文**：`media.lizdj009.com/{uuid}` 返回 `application/octet-stream`，
  头 8 字节 `fb6a4453…`；用站点 config 的 `imageAesKeyHex ea19c21e85d768da4165f5964ab886b2` /
  `imageAesIvHex f4d53ecbc273901e0d9cd7848233c702` 解出来是 **真 JPEG（ffd8ffe0）**。
  源里用 `lume-enc://aes-cbc/6hnCHoXXaNpBZfWWSriGsg/9NU-y8JzkB4NnNeEgjPHAg/<url>` 交 App 原生解密。
- 列表/详情标题与封面从页面头部的 **JSON-LD ItemList** 取（`/category/` 没有 ItemList，走卡片）。
- 限制：排序（Latest/Hottest/Most Saved/Most Liked）是前端按钮，`?sort=` 实测不生效 → 不声明排序组；
  频道都是单页 37–48 部，没有翻页控件。

## 四、69shuba.com：本次没有交付（附证据）

用户给的 `https://www.69shuba.com/` 在本机对所有路径都回 **Cloudflare managed challenge**：

```
GET https://www.69shuba.com/                                      → 403 「Just a moment...」（5.6 KB 挑战页）
GET https://www.69shuba.com/book/90442.htm                        → 403 同上
GET https://www.69shuba.com/txt/90442/41051913                    → 403 同上
GET https://www.69shuba.com/modules/article/search.php?searchkey= → 403 同上
镜像 www.69shu.com / 69shuba.com / 69shuba.cx / tw.69shuba.com    → 403 或 DNS 失败
69shuba.org / 69shu.io                                            → 403 Forbidden（非本站）
69shu.pro                                                         → 200 但是跳板页（27 KB，无正文）
封面域 cdn.cdnshu.com                                             → 200（图片可直连）
```

- 这属于「全站 CF 挑战」，按约定只能抛 `NEED_WEBVIEW_VERIFY` 交 App 网页视图过校验；但**本机没有任何
  通道能在挑战之后取到真实 HTML**，`lume-source-check` 会 100% 失败，等于交一个没法验证的源 ——
  写源规则第 8 条（五入口 + 播放实测缺一不可）过不了，所以没进 catalog、没进订阅。
- 站点结构（挑战页之外通过渲染抓取看到的部分）：书页 `/book/{id}.htm`、目录 `/book/{id}/`、
  正文 `/txt/{书号}/{章节号}`、分类 `/novels/class/{n}.htm`、榜单 `/novels/hot`、总表 `/all.html`；
  且页面是 **GBK 系编码**（渲染抓回来的正文是 GBK 乱码），App 侧要靠 `SourceTextDecoder` 的
  gb18030 通道解码（iOS 走平台 MethodChannel，其他平台会退回 `utf8.allowMalformed` 变乱码）。
- 要做成可用源，需要：① 先用 App 网页视图过一次挑战并保存 Cookie；② 确认 iOS 侧 GBK 解码；
  ③ 再把 `/book/{id}.htm` → `/txt/{书}/{章}` 的解析接上。这两步都没法在本机闭环验证，所以本次只留结论。
