# 看剧AI（kanju24.com）做源记录

2026-10-31 · 源文件 `sources/video/kanju-ai.js`（id `kanju_ai_video`，v1.0.0）

## 一、站点形态

React SPA，首页外壳只有 3.6 KB（`<div id="root">` + 三个 JS 分块），所有数据走**同源 JSON 接口** `https://kanju24.com/v1/*`。
发布页/备用域名：`kanju.ai`、`kanju13.com`、`www.kanju24.com`（实测同一套壳、同一接口、同一份内容）；
`/v1/runtime/bootstrap` 里的 `canonical_host` 是 `main.kanju13.com`（本机 TLS 握手失败，未进 mirrors）。

## 二、请求签名（本站最关键的一层）

不带签名直接请求 → `401 {"code":"invalid_request_signature","message":"Missing request signature."}`。

算法在 `/assets/movie-card-runtime-*.js`（`Gi()`/`Qi()`）：

```
msg = METHOD + "\n" + pathname + search + "\n" + timestamp + "\n" + nonce
x-ai-movie-signature = hex(HMAC-SHA256(key, msg))
x-ai-movie-timestamp = Date.now()
x-ai-movie-nonce     = 16 字节随机 hex（32 个字符）
key = 557d0e4ae929f438da6bd84412374e6086b8af09b3fed54bf22601d5bf8c54a0
```

实测只校验这三个头：把 `x-ai-movie-build-version`（站点每天变，`dianyingtiantang-v2026.10.30.2-…`）、
`client-name`、`protocol-version`、`Origin`、`Referer` 逐个删掉或填假值，仍然 200 —— 所以源里**不写版本号**，
站点发版不影响本源。

沙箱没有 `crypto`/`atob`，源的 `sha256Bytes` / `hmacSha256Hex` 是纯 JS 实现；
先用 Node `crypto` 对 16 组向量（空串、55/56/64/200 字节、含中文、真实签名消息）逐条核对，再上真接口。

## 三、数据面

| 用途 | 接口 | 实测 |
|---|---|---|
| 首页板块 | `GET /v1/feed/home?scope=public&mode=preview&sections=6&cards=12` | 6 个板块（大家都在看/韩剧在追/日剧上新/美剧续看/国产新剧/高分电影），每块 12 张卡，131 KB |
| 列表/搜索/筛选 | `GET /v1/browse/catalog?[kind|q][&genre|area|language|year*][&sort][&page][&limit]` | 20 条/页，`pagination.has_more` 真实；`limit=50` 可用；`q=庆余年` 17 条 |
| 详情 | `GET /v1/catalog/{av_id}` | 21 KB：标题/简介/演员/导演/poster/remarks + 全集 `episodes[]`（每集带 `token`） |
| 分类表 | `GET /v1/runtime/bootstrap` → `catalog_ui.catalogs[].rows` | 分类/地区/语言/年份/状态/形式/排序，站点改表本源跟着变 |
| 线路 | `GET /v1/playback/resolve/{episode_token}` | 每集 3–62 条线路 |
| 换流 | `POST /v1/playback/resolve-line?view=compact {"ticket":"…"}` | 201 + `line.url` |

分类（`kind`）：`series` 电视剧 / `movie` 电影 / `anime` 动漫 / `variety` 综艺 / `short_drama` 短剧；
不传 `kind` 就是混合全部。`genre` 多选站点不认（`genre=古装,爱情` 返回 0 条），源里取第一个。

## 四、播放：两套线路（这是「VIP 怎么放」的答案）

`resolve` 返回的 `line_options` 分两类：

| 类型 | 数量（以《嫁金钗》第 6 集为例） | 取法 | 成本 |
|---|---|---|---|
| `resolve_mode:"direct"` | **25 / 34** | `url` 本身就是 m3u8（红牛、新浪、极速、量子、暴风…第三方资源站） | 免费、不需要登录 |
| `url_kind:"resolve_ticket"` | 9 / 34 | `POST /v1/playback/resolve-line` 换地址（官方 1080P/4K、优酷、腾讯…） | 要游客会话，按档位扣 30000–60000 token |

实测：

- 直链：`hn.bfvvs.com`、`play.xluuss.com`、`vv.jisuzyv.com` 等 `206 + application/vnd.apple.mpegurl + #EXTM3U`；
  有的线路会 403（`cdn.yzzy31-play.com` 实测 403），所以源里**逐条探活**，拿到 2 条可用就返回（默认取权重最高的那条，其余进 `qualities`）。
- 票券：《嫁金钗》第 6 集匿名直接换 → `401 playback_user_session_required`；
  `POST /v1/users/anonymous {"anonymous_id":"…"}` 拿游客 Cookie 后再换 → `201`，
  `line.url = https://sign.site.zshtys888.com/file.m3u8?ucode=…&red=2`（200 + `#EXTM3U`），
  `quota_delta.used_tokens = 30000~60000`。
- 额度：`GET /v1/users/me/quota` → 游客 `limit_tokens 900000`、每日重置（`reset_at` UTC 16:00 = 北京 24:00）。
  按 45000/集算约 20 集/天。用尽后接口 402，源里给可读错误。
- 同一 `anonymous_id` 重复 `POST /v1/users/anonymous` 返回同一 user（实测两次都是 `user_b775c3a6-…`），
  所以源里把匿名 id 与 Cookie 一起存进本源的 fs，只建一次账号，**不刷号养额度**。

结论：默认路径是「第三方直链」——不登录、不扣额度；官方 1080P 只在直链全挂时兜底，
用户也可以在「线路偏好」里改成官方优先。

## 六、限制与失效预案

- **直链依赖第三方资源站**：某条线路 403/404 很正常，源里逐条探活 + 兜底官方票券；如果某天直链全挂，
  会自动改用官方线路（扣额度）。加新线路不需要改脚本——站点给的 `line_options` 自己会变。
- **官方线路有每日额度**：游客 900000 token/天，按集扣除。用完只能等次日重置，或换直链。
- **签名 key 轮换**：站点换 key 时接口返回 `invalid_request_signature`，源里会直接提示去新 `main-*.js` 里抄 `lo="…"`。
- **接口形状变化**：列表/详情字段名（`cards` / `episodes` / `line_options`）变了会体现为「列表为空」或
  「这一条在站点上还没有可播放的分集」，届时按新响应改 `itemOf` / `loadChapters`。
- **18+**：站里有「午夜剧场」成人入口（要登录 + 成人确认），本源只做公开 `catalog`，不碰那部分，
  因此 `contentCategory` 是 `movie`，不登记 18+。
