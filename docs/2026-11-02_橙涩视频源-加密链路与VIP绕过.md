# 橙涩视频源（chengshe_video）：AES 接口链路与 VIP 绕过

日期：2026-11-02 · 站点：`https://6s9b2f4hkmbh.xyz`（随机域名，会换）· 源：`sources/video/chengshe.js`

## 一、站点结构

Vite + rolldown 构建的 H5（`/js/index-CowCG-Nj.js` → `bootstrapApp` → 200+ 懒加载 chunk），
`/_app.config.js` 声明 `VITE_GLOB_API_URL=/api`。线路体系：

1. **line 域名池**（30 个 `.cc`）写在 `js/line-boot-wAiKwNdG.js` 的 `J` 常量里；
   逐个 `GET https://<line>//` 返回分发 JSON：
   ```json
   {"status":"success","result":"https://qtrvqim.p04x0hyl.cc/","pool":"https://qtrvqim.47svemtl.cc/,…"}
   ```
2. 候选 API 域名用 `GET <domain>/api/sys/findLive` 探活（200 + `{"code":200,…}` 即命中）；
   选中的域名缓存在 `LIVE_API_DOMAIN` 24 小时内先探活，失败才重选。
3. CDN 域名由 `GET /api/sys/findDomain` 下发：`imageCdn: pic.tbem.org / pic.tqonth.com`、
   `mp4Cdn: play.tbem.org / play.tqonth.com`、`videoCdnList`（只有 id，用于线路切换）。

## 二、加密链路（前端 `images-components-*.js` 拦截器原样复刻）

| 环节 | 规则 |
|---|---|
| 请求参数 | `t = Date.now()`（13 位毫秒串）；`salt = t`；`key = iv = t + "000"`（16 字节）；AES-128-CBC/PKCS7；Base64 → `encData` |
| 请求头 | `t`、`s = md5(t.slice(3,9))`、`app=cs`、`vn=2.6.0`、`deviceid`、`permissions=<token>` |
| 响应解密 | `encData` 用 `key = iv = token.slice(2,18)`（16 字符，**倒序**）解 AES-128-CBC |
| 匿名登录 | `POST /api/user/tryLogin {deviceId}` → **明文** JSON：`{userId,token,freeWatches,vipType…}` |

沙箱里没有 `crypto` / `atob`，源内自带 MD5、AES-128-CBC（加解密双实现）与 Base64；
已用 Node `crypto` 交叉验证：同输入密文逐字节一致，MD5 一致，往返解明文一致。

## 四、VIP 核查（按 `docs/VIP处理约定.md`）

| 检查 | 实测回显 | 结论 |
|---|---|---|
| 详情是否下发播放地址 | 匿名账号 `GET /video/findVideoById?videoId=155154` → 200，`videoUrl`/`access` 齐全 | 命中第 1 条：地址就在接口里 |
| 是否有前端遮罩 | 详情 `canWatch:false`、`reasonType:3`（未解锁态），播放页据此弹「购买金币/观影券」 | VIP 只是 UI 状态 |
| 非会员能不能取流 | `access` 换 `/api/dec/m3u/ios/access.m3u8` → **200 `application/vnd.apple.mpegurl`**，1181 B，含 `#EXT-X-KEY:METHOD=AES-128` 与 4 个分片 | 能，**不受 canWatch 限制** |
| key/分片可取 | key 200（16 B）、首个分片 200（`video/mp2t`，3,451,504 B） | 整链可播 |
| 会员体系管什么 | `freeWatches:3`、`vipType:0`、`/tran/buy/video`、`/video/userCoupon`、`/sys/findVipProductList` 属于交易侧 | VIP/金币只锁购买动作，不锁播放 |

**结论**：无需会员态、无需买券，也不需要爆破 `freeWatches`——播放地址对匿名账号全域开放。

## 六、限制

- **搜索不可用**：`/search/content` 传 `keyword` + `searchType` 仍返回 400（参数/签名未公开），
  源里 `list({keyword})` 给可读错误，不静默返回空。
- 落地域名是随机串（`6s9b2f4hkmbh.xyz`），会换；源内 line 池自发现 + 12h 缓存，
  用户也可在源设置里换成新的落地域名。
- 封面 `content-type` 是 `text/base64.jpg` 但内容是 WEBP 二进制，App 按图片解码正常。
- 播放是 AES-128 HLS（`#EXT-X-KEY` 由播放器自动取），列表页 20 条/页。

## 七、踩坑记录（给后续源复用）

1. `LumeSource.storage.get/set` 是**异步**的：当同步用会拿到 `[object Promise]`，
   表现为「明明没缓存却像有缓存」，直接跳过登录。
2. `LumeSource.http.post(url, body, options)` 的 **body 在第二个参数**；写成
   `post(url,{headers,body})` 会把对象当 body 发出去。稳妥用 `http.request({url,method,headers,body})`。
3. Base64 解码**不能**把 `=` 一起过滤掉，否则尾部会多解出字节，明文尾部残留乱码 →
   `JSON.parse` 报 `Unexpected non-whitespace character after JSON`。
4. CDN 直连 m3u8（`play.tbem.org/...`）一律 403，必须走 `/api/dec/m3u/ios/access.m3u8` 换流。
