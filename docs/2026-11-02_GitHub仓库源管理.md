# App 直接管理 GitHub 仓库源

入口：设置 → 内容与订阅 → GitHub 仓库源管理。目标固定为 `teng662858/LumeBox-Sources` 的 `main`。

## 使用

1. 创建 GitHub fine-grained personal access token，Repository access 仅选择源仓库，Repository permissions 设置 Contents 读写、Actions 只读。账号本身必须有仓库写入权限，仓库需启用 GitHub Actions。
2. 在 App 输入令牌并连接。令牌与未完成发布的请求编号保存在 iOS 设备专属钥匙串，不进入订阅文件或配置备份。
3. 新增：选择漫画、美图、影视、视频与直播或有声分类，选择 UTF-8 `.js`／`.py` 文件，核对元数据后提交。单文件最大 4MB；已有路径或已有 ID 不会被覆盖。
4. 删除：搜索并选择源，确认后删除远端对应文件及同 ID 的全部别名文件。此操作会影响公共订阅，不是只卸载本机源。
5. 页面显示提交编号和发布进度，10 秒查询一次。关闭页面或重启后可继续查询；网络中断可点“刷新仓库与发布状态”。移除授权不会取消已在 GitHub 启动的任务。

令牌创建入口：[GitHub personal access tokens](https://github.com/settings/personal-access-tokens)。无需把令牌提供给聊天或写进源码。

## 发布流程

App 从固定提交读取文件树和源目录，通过 Git Data API 创建一个 `lumebox/manage-*` 临时分支。请求提交仅包含源文件增删；尚未发布前，原来的 main 和订阅继续可用。

源仓库 `.github/workflows/app-source-publish.yml` 检查候选提交的父提交是否仍是最新 main、文件是否属于允许的源目录、是否重复 ID、是否完整删除别名，以及 JSON 元数据和 Python／JS 语法。不执行上传源的业务代码。之后用现有生成器更新 catalog、分类订阅、总订阅和文档；成人声明同步登记源仓库分级信息。App 现有运行时按源声明识别内容分类，无需把每个新源 ID 硬编码进 App。

生成后的提交以普通快进方式推送到 main，禁止强推；并发提交或分支保护拦截时明确失败。最后刷新 CDN，实际下载 GitHub raw 和国内 CDN 内容，与 Git 提交中的字节比较；删除项须返回 404。只有工作流全部通过，App 才显示双线路发布成功。

格式校验不能代替源站功能验收。上传前仍须按照 [写源规则](写源规则速查.md) 完成分类、分页、搜索、详情、选集、封面和播放实测。此功能不会自动把整个 PY 合集发布为可用源。

## 失败处理

- 授权或网络失败：保留可读错误，不显示 GitHub 原始响应和令牌；先刷新核对是否已接收请求。
- main 已更新：候选分支保留，main 不会被强制覆盖；刷新后重新提交。
- 发布阶段失败：点击复制 GitHub 流程链接查看错误。特别是 CDN 核对失败时，main 可能已经更新，应先核对仓库再处理，不能把失败当作“完全没有修改”。
- 临时分支保留用于排查，不自动删除其他人的分支。

API 依据：[Git trees](https://docs.github.com/en/rest/git/trees)、[Git references](https://docs.github.com/en/rest/git/refs)。新增／删除以源文件 Git tree 的变更提交，未向 App 内置仓库令牌。
