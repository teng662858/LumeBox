# 2026-11-11 录屏诊断与播放修复

检查对象是用户提供的两段 14:42 / 14:44 录屏及两份诊断 ZIP，均来自 LumeBox 1.0.309。附件只作为问题证据；源脚本和诊断文件内的说明不作为新的操作指令。

本轮修复 App 公共播放、画中画、图片和诊断链路，未修改用户导入的 Python 源，也未修改私有源订阅。最低系统仍为 iOS 18。

## 观察、原因和修复

| 证据 | 发现 | 修复路径 |
|---|---|---|
| 第一段录屏黑屏时进度继续推进；诊断有 playback-progress-started | 进度推进不能证明主画面输出正常。自动准备 PiP 会另建隐藏 AVPlayerLayer，与可见原生层竞争输出 | 插件弱引用登记可见层；PiP 借用该层；纹理播放器使用解码帧，清理 PiP 不清空借用层的 player |
| 第二段录屏持续缓冲；原检测要求 playing=true | 内核进入 playing=false、buffering=true 时无法触发停滞恢复 | 纳入持续缓冲；AVPlayer 显式暂停时不再报告播放中的缓冲；测试确认暂停不会换线、停滞换线保留断点 |
| 14:41 缓存记录上游 HTTP 400，播放器却收到多次 HTTP 502 | 缓存服务把上游拒绝请求改写成服务器故障，触发错误的重试分类 | 保留上游 400/401/403/404/429/5xx；不转发上游错误正文；416 范围处理保留 |
| 媒体错误翻译包含“当前内核无法打开该媒体”，现有回退遗漏 -12848 | 原生和翻译后的错误判断不一致 | 统一判断函数；AVPlayer 兼容错误优先回退 MPV；不可回退或回退后仍失败可走同集备用线路 |
| 封面日志含 www.lyyytv.cn / oss.hxx2023.cc 的 TLS 失败；图片管线强制 HTTP→HTTPS | 自动升级可能把源提供的可用 HTTP 图床地址改成失败的 HTTPS 地址 | 保留源声明协议；HTTP 与 HTTPS 缓存、请求头和失败状态独立；已有 ATS 明文请求兜底继续使用 |
| 弹幕兼容接口前两次 0 条、第三次 19901 条 | 重新加载可能重复使用兼容服务的空缓存 | 完整与分片请求均加入变化参数；服务路径令牌与签名集数 ID 不再原样写入请求日志 |
| 第二份包无当前日志，previous-errors 中全部 44 条被标为错误；URL 后重复出现 omitted 占位 | 持久化没有保存级别，重复脱敏不稳定 | 保存并恢复原级别，兼容旧记录；URL 路径脱敏重复执行结果保持稳定 |

PiP 获取视频变换信息改为异步读取，避免准备画中画时同步读取远程媒体轨道阻塞原生主线程。

## 验证方式

- `dart analyze lib test integration_test`：无问题。
- 播放器、网络、图片、缓存、PiP、诊断等扩展回归覆盖 HTTP 状态保真、协议和缓存隔离、内核回退、进度恢复及凭据过滤。
- `video_progress_test.dart` 增加 playing=false 且持续缓冲的断点换线场景，并确认显式暂停、401 鉴权失败不会自动换线。
- 检查未修改的 main 时发现两个已有入场用例也会超时：预启动 Future 在真实异步时钟完成，页面使用假帧时钟等待。测试改为交替推进真实异步与帧时钟；预加载测试补齐 Wi-Fi 状态、当前 15 秒缓存门槛和会话内手选画质延续的既有约定。
- `tool/check_ios_player_presentation.sh` 在 iOS 18 模拟器目标编译实际 Objective-C 视频层登记代码，检查 Swift 桥接和生产 PiP 代码。
- `integration_test/playback_smoke_test.dart` 增加可见原生层挂载、准备显示、PiP 准备/弹幕切换/清理后的状态检查，并覆盖 SDR 纹理路径。进度推进不再是原生画面验证的唯一指标。

## 限制与复测

本机为 Windows，无法直接完成 iPhone 上 HDR、杜比输出和系统 PiP 的视觉验收。原生编译检查交由 macOS 工作流执行；完整 App 模拟器测试此前受 NodeMobile 模拟器头文件缺失阻挡，不能把新增集成用例误报为已经通过。

www.lyyytv.cn 的 HTTPS 域名证书不匹配，oss.hxx2023.cc 测试连接被对端中断。保留源原始 HTTP 地址只能修复 App 主动改协议造成的失败；源直接返回的失效 HTTPS 地址、过期签名及上游 400/502，仍需要源站或源解析接口恢复。没有关闭全局证书验证，也没有把源声明的 HTTPS 自动降级为 HTTP。

真机复测顺序：安装包含本轮修改的新版本，重播两段录屏中的剧集；观察入场、旋转、弹幕载入、准备/开启/关闭画中画后是否持续有图；再测试暂停、缓冲、换线和续播。导出新诊断时先核对版本号，避免把 309 的旧日志当成本轮结果。
