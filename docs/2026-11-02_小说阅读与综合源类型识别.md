# 小说阅读与综合源类型识别

## 行为

综合源按单个作品分流，不把整站或整个分类统一判成视频。漫画使用原漫画详情和阅读器，视频使用原视频详情和播放器，文字小说使用小说详情和文字阅读器。现有探索、搜索、收藏、历史、相关推荐中使用漫画或视频详情的入口均经过同一识别逻辑。

优先采用列表或详情明确声明的 `mediaType`（兼容 `contentType`、`kind`）。未声明时读取首章实际载荷：`images` 为漫画、`video` 为视频、`text` 为小说。网页解析请求判成视频，不在识别阶段打开网页播放器。类型识别失败在详情中报告错误，允许重试；无章节或暂无内容时保留原详情的空态。不会用标题、封面、简介猜测小说正文。

识别得到的章节内容按源实例、作品和章节保存最多 30 秒，阅读器或播放器消费一次，避免重复解析。视频网页已捕获的播放地址明确声明视频类型，避免识别消耗其一次性的选集结果。

## 小说

- 小说详情展示真实标题、作者、简介和目录，支持正倒序、收藏、继续阅读。
- 阅读器左右翻页、切换章节、目录跳转，可调字号、行距，支持系统/护眼/夜间背景。
- 按屏幕尺寸、字体缩放重新分页，进度记录正文字符位置，调整字号或重开页面后继续阅读。
- 小说和漫画在综合源原有库内保存各自的进度形状；源标识和作品标识共同隔离记录，不把内容迁移到其他板块，也不新增或恢复旧的小说数据库板块。
- 请求由页面管理，离开页面或换章取消旧请求；加载失败提供重试。

## 源返回值

建议在列表及详情提供类型，省去额外的识别请求：

```js
// 三类作品可出现在同一源中；category 仍是现有的 video/comic 存储板块。
{ id: 'book-1', title: '作品名', mediaType: 'novel' }
{ id: 'comic-1', title: '作品名', mediaType: 'comic' }
{ id: 'video-1', title: '作品名', mediaType: 'video' }

// content({id, chapterId}) 返回实际章节正文
{ kind: 'text', text: '第一段。\n\n第二段。' }
// HTML 正文也可使用以下形状，宿主转换段落并去除脚本/样式
{ kind: 'html', html: '<p>第一段。</p><p>第二段。</p>' }
{ kind: 'images', images: ['https://example.com/page.jpg'] }
{ kind: 'video', url: 'https://example.com/episode.m3u8' }
```

JS 及 Python Spider 适配器支持以上明确载荷；Python 的 `playerContent` 可按条目返回文字、图片或视频。猫源接受 `novel` 子站及明确的文字/图片载荷。HTML 只能作为正文交付，不能拿简介或一个网页 URL 代替正文。

仅返回视频 URL 的旧 CMS/Python 源仍只能播放视频。自动识别不会替源实现正文抓取、解密、登录或章节解析。未提供小说目录和正文的站点需要另外修改源；此次没有修改或发布第三方站点源，因此没有源仓库/CDN 版本需要同步。

## 验证与预览

自动测试覆盖同源三类内容、类型声明和无声明识别、失败、单次内容复用、HTML 正文、分页完整性、表情代理对、大字体、跨类型数据库重开、详情分流，以及阅读设置与续读。沿用漫画和视频详情回归与 Python 宿主测试。

Android 交互预览：`tool/novel_reader_preview.dart`。它明确标注本地示例正文，经正式视频详情入口自动识别到小说详情；正常应用入口与真实订阅不被该演示替换。

本次验证：121 项 Flutter 测试、30 项 Python 宿主测试全部通过；`flutter analyze --no-pub` 无问题。Android x64 调试 APK 构建、安装成功，虚拟机实际检查了自动分流、正文翻页与阅读设置。未执行 iOS 真机/模拟器构建，本次没有修改原生平台最低版本（仍为 iOS 18）。
