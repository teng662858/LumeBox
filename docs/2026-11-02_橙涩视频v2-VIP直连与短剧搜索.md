# 橙涩视频 v2.1.0：VIP 直连播放 + 短剧板块 + 暗网板块 + 站内搜索

2026-11-02 · 站点 `https://6s9b2f4hkmbh.xyz`（用户给的是 `/home` 首页）· 源 `sources/video/chengshe.js`

## 一、结论（用户问的「能破 VIP 做源吗」）

**能，而且不用买券、不用会员账号。** VIP / 金币在站点里只是前端遮罩：

- 详情接口 `/api/video/findVideoById` 返回 `canWatch:false`、`reasonType:2/3`，但 **`videoUrl` 照发**；
- 播放地址 = `CDN 主机 + videoUrl`，CDN 不校验任何签名/会员态；
- 实测含 VIP 片抽样 **12/12 → 200 + `#EXTM3U`**，HLS 是标准 AES-128，`index.key` 也 200。

即《VIP处理约定》的第 1 条（页面层可绕）+ 第 4 条（接口不鉴权）：直接取地址。

## 二、站点结构（Tabbit 抓真实请求后还原）

| 环节 | 请求 | 说明 |
|---|---|---|
| 前端 | `https://6s9b2f4hkmbh.xyz/home` | Vue3 + rolldown 打包的 PWA，Cloudflare 在前；`disableDevtool` 会 `window.close()`（自动化环境要先把 `outerWidth/outerHeight` 对齐 `inner*`） |
| 线路 | `GET https://<seed>.cc/api/sys/findLive` | 30 个 `.cc` 短链池，返回 `{"status":"success","result":"https://qtrvqim.p04x0hyl.cc/","pool":"…"}` |
| 登录 | `POST <api>/api/user/tryLogin {"deviceId":"app_…"}` | 明文响应，直接发游客 `token`；**这一条不能带 `permissions` 头**（空头会返回空 body） |
| 加密 | 请求/响应 | 请求：`key = iv = 13 位毫秒时间戳 + "000"`，AES-128-CBC/PKCS7，Base64 → `encData`；响应：`key = iv = token.slice(2,18).reverse()` |

请求头：`t`（时间戳）、`s = md5(t.slice(3,9))`、`app=cs`、`vn=2.6.0`、`deviceid`、`permissions`（token）。

### 定位到真实 key 的过程（可复用）

1. 从 `images-components-*.js` 找到 `Oa(e,t)`：`n = \`${t}000\``，`iv = Utf8.parse(n)`，`AES.encrypt(JSON.stringify(e), Utf8.parse(n), {iv, CBC, Pkcs7})`。
2. 用下载下来的 `crypto-vendor-*.js`（CryptoJS）在 Node 里复现，先猜 `t = 时间戳.slice(3,9)`（6 位）→ 密文对不上。
3. 拿一对明文/密文（GET 空参数 = `{}`）暴力 key 长度 → **命中 `t = 完整 13 位时间戳`，key = `t + "000"`（16 字符）**；`md5(t.slice(3,9))` 只是请求头签名。
4. 响应侧 `Ia(e)` 用 store 的 `reverseTokenState = token.slice(2,18).split('').reverse().join('')`，复现后能解出业务 JSON。

## 四、v2.0.0 改了什么

旧版（v1.0.0）播放走 `/api/dec/m3u/ios/access.m3u8?encData=…`，搜索直接报错「未公开」。v2：

1. **播放改为 CDN 直连 `videoUrl`**（少一次接口、少依赖 `access`），`dec/m3u` 保留为兜底；
2. **新增短剧板块**：`serial` 分类 → `/api/videoSerial/findListByClass`（4 个子类：AI成人短剧 / AI漫剧 / AI换脸 / AI魔改，取「橙涩短剧」17），详情走 `findDetail`，章节按「全集（共 N 集）」；
3. **站内搜索可用**：`POST /api/video/findVideoByTag {tagTitles:[关键词]}`（按标签命中，不是全文）；
4. **首页三板块**：排行榜 / 橙涩短剧 / 热门，单个失败不影响其它；
5. 分类缓存里剔掉「精选」（`classifyId 14` 接口返回空数组，不拿别的分类顶替）；
6. `coverOf` 兼容短剧的 `coverImg` 是单对象（旧版只处理数组，短剧封面全空）。

## 六、暗网板块（v2.1.0）

站点 tabbar 有个「暗网」入口（路由 `/dark-web`），页面逻辑是
`findClassifyList({ needVip: true })` + 判断当前账号 `vipType === EverlastingSupreme`（永久至尊），
不满足就只渲染 `dark-locked` 解锁页（CTA 跳会员）。也就是说 **前端把整页锁了，接口一点没锁**：

| 检查 | 结果 |
|---|---|
| `GET /api/video/findClassifyList {needVip:true}` | 匿名（游客 token）可取，返回 1 个分类「暗网流出」(`classifyId 11`, `type 3`, `needVip true`) |
| `POST /api/video/findClassifyVideos {classifyId:11}` | 正常分页，每页 20 条 |
| 详情 | `restricted:true`、`reasonType:5`（前端枚举 `DarkNet=5`）、`canWatch:false`，**`videoUrl` 照发** |
| 播放 | `pic.tbem.org` + `videoUrl` → **36/36 页 1–3 全部 200 + #EXTM3U**（AES-128，`index.key` 200） |

所以源里把 `needVip:true` 那一组分类并进 `loadCats()`，标题加「暗网 · 」前缀；
实测 `--call list,detail,chapters,content --category c11` 全绿（playable 206 + #EXTM3U，m3u8 33,577 B）。

顺带：分类「精选」(`classifyId 14`) 两个接口都返回空数组，源里用 `EMPTY_CLASSIFY` 白名单剔掉，
不给用户一个空页。分类缓存 key 升到 `chengshe.cats2`，避免旧缓存把暗网挡在外面。

## 七、限制与失效预案

- 全站 18+，`contentCategory: adult`，ID `chengshe_video` 已在 `adultIds`；
- 搜索是标签命中（「学生」「后入」这类站内标签），搜不到标题里的长句；
- 排行榜只有一页 30 条；
- 换域名：改 `SEEDS`（短链池）/ `FALLBACK_API` / `IMG_CDN`；`videoUrl` 变 `null` 时先看详情里有没有新的 `playPath`/`access` 字段；
- 空 `permissions` 头 → 服务端返回空 body，所以 `ensureToken()` 里显式 `delete h.permissions`。
