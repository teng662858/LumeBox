# 播放启动慢与四内核检查

本轮按用户要求检查点击播放、地址解析、缓存传输、内核装载、播放启动、暂停和跳转。
最低目标保持 iOS 18.0。四内核共享的磁盘缓存层存在可复现的首批数据阻塞，已修复；
AVPlayer 另有缓冲耗尽后的恢复缺口。修复了这些代码问题，不代表已经完成用户设备和
所有站点的实播验收。

## 证据与结论

| 证据 | 观察 | 结论与修复路径 |
| --- | --- | --- |
| E1：用户提供的 App 1.0.317 诊断包 | 同一 HLS 的 AVPlayer 两次约 21 秒出首帧，随后 `buffered-startup-stalled`；MPV 接管后约 0.85～1.14 秒进度开始推进 | 系统路径存在真实停滞；日志没有记录足够的分阶段数据，不能把 21 秒全部归到同一个原因 |
| E2：同一慢速服务器测试分别运行旧版和修复版 | 服务器发出 16 KiB 后暂停发送剩余数据；旧版 `cb4c7b63` 在等首批响应时 2 秒超时，修复版在服务器尚未发送剩余数据时就收到首批字节 | 共用缓存层先下载完整块/分片再返回播放器，是已复现的等待来源；改为边收边转发 |
| E3：`git blame` 与 `_fetch` 实现 | 聚合全部响应数据的路径来自 `73a4e5f8`（2026-11-10 加入共享磁盘缓冲），块大小 1 MiB | 可以定位这条等待路径的引入提交；不能据此断言所有历史播放故障均由该提交造成 |
| E4：原生 AVFoundation 恢复函数及 Apple 契约 | 关闭自动等待后，缓冲耗尽会使 AVPlayer 暂停；旧代码的缓冲范围更新只通知 UI | 缓冲覆盖当前位置、用户仍要求播放且没有未完成 seek 时，直接恢复当前 AVPlayer；保留暂停与倍速 |
| E5：详情页与 MPV 的实际调用链 | 无后缀/PHP 视频地址仍可能等待最长 10 秒的二次轨道检查；MPV 设置/装载会等待可选的播放信息读取 | 视频板块明确声明的视频直接进入播放；MPV 信息读取后台完成 |
| E6：Aether 命令队列与超时测试 | 原生 `load` 若不返回，后续 play/pause/重试会在同一队列等候 | 装载增加 30 秒上限，超时停止旧任务并拒绝旧代次事件，使重试可以继续 |
| E7：2026-11-12 本机源/CDN 抽样 | 瓜子源列表、搜索、详情、选集和取址接口返回成功；同一 CDN 的抽样 HLS 请求返回 HTTP 403 | 源接口成功与媒体地址可播放应分开判断。本次抽样不是诊断包中的同一集，不能据此推断手机当时的响应 |

E1 为用户本地 ZIP，未提交运行日志、完整媒体地址、账号信息或原始诊断数据。
E2 的回归名为 `slow ts delivers first bytes before the upstream finishes`；同时覆盖
MP4 整文件请求、远端带 Range 的 MP4 请求和 Apple HLS 首分片慢响应。

## 修复后各阶段的行为

四内核仍使用同一套源请求头、缓存和媒体兼容处理。标准媒体请求先向播放器转发字节，
磁盘写入跟在数据交付之后。PNG 包装的 TS 仅检查有限前缀；保留已经验证的 Range、
跨域敏感请求头裁剪、错误状态透传、空间不足降级和缓存清理代次控制。

Apple HLS 的可选编码探测等待上限为 500ms。没有获得肯定的 HEVC TS 识别结果时，
保留原始传输，不因可选检查继续阻塞播放清单。

`mediaInitialized` 单独描述装载完成。页面可以接手仍报告 buffering 的暂停媒体，
随后挂载显示面并发出 play，不用等一个只能在开始播放后才会清除的缓冲标志。
MDK 换媒体时同时清除旧进度、旧错误、时长和统计，避免把上一集状态带入加载判定。

| 内核 | 本轮处理 | 验证范围 |
| --- | --- | --- |
| AVPlayer | 缓冲更新后恢复停住的播放器；暂停、跳转、释放和速率能力均有保护 | 真实 Objective-C 编译；AVFoundation 替身运行真实恢复函数；Dart 控制链回归 |
| MPV | 装载完成与缓冲状态分开；可选信息读取不挡 play | 暂停媒体交接、请求头、缓冲和控制链回归 |
| MDK | 装载完成与缓冲状态分开；换媒体清空旧状态 | 共用加载入口、缓冲参数和播放器控制回归；原生媒体准备仍由 libmdk 执行 |
| Aether | 装载上限、旧事件隔离、队列恢复；加载时清空旧统计 | 挂起、超时、重试、旧事件拒绝和通道回归 |

## 实播验证的边界

首次[四内核模拟器任务](https://github.com/teng662858/LumeBox/actions/runs/43055653541)
在编译阶段因 `NodeMobile/NodeMobile.h` 缺失而终止，实际运行 0 项测试。这不是播放
测试通过，也不是证据表明四个解码器同时失败。仓库补入明确的 CocoaPods 混合配置，
保留原有 SPM 依赖，并将自维护构建配置的最低目标固定为 iOS 18。

复跑结果应以 Actions 中的 `KERNEL_SMOKE_OK` / `PLAYBACK_SMOKE_OK` 及完整任务结果
为准。模拟器本身也不能替代用户设备的 HDR、外部音频路由、网络 CDN 与长时播放验收。

目前仍需注意：本地猫源声明错误的分段长度继续走既有修复路径；HEVC TS 转 fMP4
仍需要原生重新封装一个完整分片；加密/不兼容封装、站点 403 和真实网络慢不由本轮
字节转发修复保证可播。没有扩大预读默认值，也没有通过缩短自动换内核时间来掩盖停滞。

Apple 行为依据：[自动等待与缓冲耗尽后的暂停](https://developer.apple.com/documentation/avfoundation/avplayer/automaticallywaitstominimizestalling)、
[立即播放已缓冲数据](https://developer.apple.com/documentation/avfoundation/avplayer/playimmediately(atrate:))。
