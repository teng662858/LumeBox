# 播放启动慢与四内核检查

本轮按用户要求检查点击播放、地址解析、缓存传输、内核装载、播放启动、暂停和跳转。
最低目标保持 iOS 18.0。四内核共享的磁盘缓存层存在可复现的首批数据阻塞，已修复；
AVPlayer 另有缓冲耗尽后的恢复缺口。修复了这些代码问题，不代表已经完成用户设备和
所有站点的实播验收。

## 证据与结论

| 证据 | 观察 | 结论与修复路径 |
| --- | --- | --- |
| E1：用户提供的 App 1.0.317 诊断包 | 同一 HLS 的 AVPlayer 两次约 21 秒出首帧，随后 `buffered-startup-stalled`；MPV 接管后约 0.85～1.14 秒进度开始推进 | 系统路径存在真实停滞；日志没有记录足够的分阶段数据，不能把 21 秒全部归到同一个原因 |
| E2：同一慢速服务器测试分别运行旧版和修复版 | 服务器发出 16 KiB 后暂停发送剩余数据；旧版 `cb4c7b63` 在等首批响应时 2 秒超时，修复版在服务器尚未发送剩余数据时就收到首批字节 | 共用缓存层先下载完整块/分片再返回播放器，是已复现的等待来源；改为边收边转发 |
| E3：`git blame` 与 `_fetch` 实现 | 聚合全部响应数据的路径来自 `73a4e5f8`（2026-11-10 加入共享磁盘缓冲），块大小 1 MiB | 可以定位这条等待路径的引入提交；不能据此断言所有历史播放故障均由该提交造成 |
| E4：原生 AVFoundation 恢复函数及 Apple 契约 | 关闭自动等待后，缓冲耗尽会使 AVPlayer 暂停；旧代码的缓冲范围更新只通知 UI | 缓冲覆盖当前位置、用户仍要求播放且没有未完成 seek 时，直接恢复当前 AVPlayer；保留暂停与倍速 |
| E5：详情页与 MPV 的实际调用链 | 无后缀/PHP 视频地址仍可能等待最长 10 秒的二次轨道检查；MPV 设置/装载会等待可选的播放信息读取 | 视频板块明确声明的视频直接进入播放；MPV 信息读取后台完成 |
| E6：Aether 命令队列与超时测试 | 原生 `load` 若不返回会阻塞队列；旧代次轮询还会清除超时报错，新增断言在修复前失败 | 装载增加 30 秒上限，超时停止旧任务并拒绝旧代次事件与轮询快照，使重试可以继续 |
| E7：2026-11-12 本机源/CDN 抽样 | 瓜子源列表、搜索、详情、选集和取址接口返回成功；随后定位诊断中同作品的当前第 1 集，取址约 382ms，普通 GET 与 Range 请求均得到 HTTP 403 | 取址成功、媒体可访问和内核可播放应分开判断。诊断中的完整地址已脱敏，不能保证当前返回的签名/地址与手机当时相同，也不能据此推断手机当时的响应 |

E1 为用户本地 ZIP，未提交运行日志、完整媒体地址、账号信息或原始诊断数据。
E2 的回归名为 `slow ts delivers first bytes before the upstream finishes`；同时覆盖
MP4 整文件请求、远端带 Range 的 MP4 请求和 Apple HLS 首分片慢响应。

## 修复后各阶段的行为

四内核仍使用同一套源请求头、缓存和媒体兼容处理。标准媒体请求先向播放器转发字节，
磁盘写入跟在数据交付之后。PNG 包装的 TS 仅检查有限前缀；保留已经验证的 Range、
跨域敏感请求头裁剪、错误状态透传、空间不足降级和缓存清理代次控制。
已知长度的长媒体每个完整块交付后继续落盘，不等整条响应结束；首块被容量淘汰后，
已保存的后续块仍能命中。未知长度响应只暂存有限首块，到 EOF 再确认总长度。
有回归检查这些行为，以及 MP4 地址实际返回 HLS 时仍改写相对子地址。

Apple HLS 的编码兼容探测保留原有的有限前缀读取，确定 HEVC TS 时仍转换为 fMP4。
慢速分片测试同时检查探测只读取前缀，不等待整个分片。网络本身没有提供前缀数据时，
仍可能发生等待；本轮没有通过放弃必要的编码判断来声称缩短这段耗时。

`mediaInitialized` 单独描述装载完成。页面可以接手仍报告 buffering 的暂停媒体，
随后挂载显示面并发出 play，不用等一个只能在开始播放后才会清除的缓冲标志。
MDK 换媒体时同时清除旧进度、旧错误、时长和统计，避免把上一集状态带入加载判定。

| 内核 | 本轮处理 | 验证范围 |
| --- | --- | --- |
| AVPlayer | 缓冲更新后恢复停住的播放器；暂停、跳转、释放和速率能力均有保护 | iOS 18 编译与真实恢复函数行为检查；MP4/HLS 2/2 实播，含可见图层、纹理与 PiP 准备 |
| MPV | 装载完成与缓冲状态分开；可选信息读取不挡 play | 控制链回归；MP4/HLS 2/2 视频实播，CI 使用定时静音输出 |
| MDK | 装载完成与缓冲状态分开；换媒体清空旧状态 | 缓冲参数和控制链回归；MP4/HLS 2/2 实播，原生准备由 libmdk 执行 |
| Aether | 装载上限、旧事件与轮询隔离、队列恢复；加载时清空旧统计 | 挂起、超时、重试和通道回归；MP4/HLS 2/2 实播 |

## 实播验证的边界

[最终任务](https://github.com/teng662858/LumeBox/actions/runs/43086570526)中 AVPlayer、
MDK、Aether、MPV 均为 2/2 通过，进程退出与整个工作流结果也均成功。下面的测量
来自本机 HTTP 标准样本，不能作为用户原视频的改善幅度；AVPlayer 两项未单独记录
装载耗时，不补造秒数。

| 最终原生用例 | 装载完成 | 从创建到进度超过 500ms |
| --- | ---: | ---: |
| MDK MP4 | 223ms | 1631ms |
| MDK HLS | 209ms | 1153ms |
| Aether MP4 | 83ms | 1463ms |
| Aether HLS | 82ms | 1001ms |
| MPV MP4（静音输出） | 61ms | 1365ms |
| MPV HLS（静音输出） | 83ms | 1016ms |

前几次四内核模拟器任务在编译阶段终止，实际运行 0 项测试，不能算作播放验证通过。
完整构建日志最终定位到 Node SDK 的架构选择：发布包只有 arm64 模拟器切片，Pods
目标却同时请求 arm64、x86_64，导致 CocoaPods 跳过 SDK 拷贝，先后出现头文件与
链接框架缺失。已将 Node 插件的模拟器目标限定为 arm64，并在 CI 中增加实际构建
设置断言；设备架构不变。仓库补入 CocoaPods 混合配置，保留原有 SPM 依赖，由
Flutter 统一安装，避免手动重复安装引起框架重名。自维护目标最低版本固定为 iOS 18。

[早期实播任务](https://github.com/teng662858/LumeBox/actions/runs/43069398485)曾停在
`Test starting…` 并超时；[分内核复跑](https://github.com/teng662858/LumeBox/actions/runs/43078189964)
已有 4 项实际播放通过，但整轮失败。取证发现冷启动调试连接超时、禁用 DDS 引起
截图比较器服务流错误，以及 MPV 模拟器音频设备无法初始化。这些失败没有计入最终
通过数。现保留 DDS、实时帧策略、分内核时限与取证；只对尚未进入 Dart 测试的冷
启动连接失败重试一次，不重试实际播放断言失败。

CI 的 MPV 显式选择 `ao=null`，保留音频解码与正常视频时钟，但不验证实际扬声器输出；生产代码和
普通手工测试不启用该选项。[mpv 官方说明](https://mpv.io/manual/master/#audio-output-drivers)
说明 null 输出不发声且保持视频播放速度。本轮不能据此声称 MPV 真机音频验收通过。

模拟器本身不能替代用户设备的 HDR、外部音频路由、网络 CDN 与长时播放验收。

目前仍需注意：本地猫源声明错误的分段长度继续走既有修复路径；HEVC TS 转 fMP4
仍需要原生重新封装一个完整分片；加密/不兼容封装、站点 403 和真实网络慢不由本轮
字节转发修复保证可播。没有扩大预读默认值，也没有通过缩短自动换内核时间来掩盖停滞。

Apple 行为依据：[自动等待与缓冲耗尽后的暂停](https://developer.apple.com/documentation/avfoundation/avplayer/automaticallywaitstominimizestalling)、
[立即播放已缓冲数据](https://developer.apple.com/documentation/avfoundation/avplayer/playimmediately(atrate:))。
