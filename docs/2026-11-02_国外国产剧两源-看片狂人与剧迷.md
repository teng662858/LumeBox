# 国外国产剧两源：看片狂人 + 劇迷

2026-11-02 · 新增 `sources/video/kpkuang.js`（id `kpkuang_video`，v1.1.0）、`sources/video/gimy.js`（id `gimy_video`，v1.0.0）

## 一、为什么是这两个站

目标是「面向海外/镜像在境外、国产剧集多、有多档清晰度线路」的影视站。批量探测（35 个候选域名）后只剩两条能稳定跑通五入口：

| 站 | 形态 | 国产剧 | 线路/清晰度 | 播放 |
|---|---|---|---|---|
| 看片狂人 `kpkuang.com` | macCMS「vfed」SSR，48 条/页真分页 | 国产剧/港台剧/日韩剧/欧美剧/海外剧/短剧细分，另有电影分类型 | 4–26 条线路：`4K/2160P`、`1080P`、`睿映HD`、`720高清云`、`高清资源库`… | m3u8 直链（资源站）/ 外链解析（腾讯/优酷/B站/Abyss/mixdrop） |
| 劇迷 `gimy.org` | Bootstrap SSR，24 条/页 | 大陸/港/台/韩/日/美 + 电影/综艺/动漫 | 单集 13–27 条线路（魔都/紅牛/極速/金鷹/愛坤…） | m3u8 直链，实测 1920x1080 |

被淘汰的几个（记录一下，避免下次重复踩）：
- `ttkan.co`（天天看）：全站 `403 __gatekeeper_challenge`（PoW 闸门，非 Cloudflare）。
- `ikanbot.com`（爱看机器人）：搜索页可取，`/play/<id>` 是 Cloudflare 挑战。
- `ddys.app`（低调影视）：首页输出的是加密/压缩块，无可解析 DOM。
- `yingshidao.com`（影视岛，海外、**带 has4k 标记**）：见第五节，接口要设备身份，留待后续。
- `6v520` / `hdmoli`：纯下载站（磁力/ED2K），没有在线播放。
- `4kdy.net` 520、`nunuyy.top` 跳广告、`libvio.me` 域名停用。

## 二、看片狂人（kpkuang.com）

```
栏目  /vodtype/{tid}/  +  /vodtype/{tid}/page/{n}/        48 条/页，页间 0 重叠
详情  /voddetail/{id}/                                    1.0–1.2 MB
播放  /vodplay/{id}-{sid}-{nid}.html
搜索  GET https://kpdata.flixfiend.top/esearch/index?kw=&ts=&callback=<jsonp>
```

1. **总览页与列表页不一样**：`/vodtype/1|2|37/` 是「总览」——一页里 10 个 12 条的小栏目（最新视频/动作片/喜剧片…），
   而且 `page/300/` 会取回 `page/2/` 的内容。所以本源只用它们的**子栏目**（13 国产剧、14 港台剧、15 日韩剧、
   16 欧美剧、20 台剧、21 泰剧、23 韩剧、30 海外剧、6–12 电影分类型、36/39–46 短剧细分、3 综艺、4 动漫、29 纪录片），
   这些是干净的 48 条列表，深翻到 `page/50` 仍有新内容、`page/900` 返回空 → `hasMore` 直接按条数判断。
2. **卡片**用 `<li id="listid_{id}_{n}">` 起头，锚点里 `title` + `data-original`（封面）。
   豆瓣封面（`img*.doubanio.com`）**要 Referer**（无 Referer 418），所以列表项带 `coverHeaders`；
   详情页优先用站内 `/upload/` 封面（`var def_cover`），不需要头。
3. **搜索被 Cloudflare 挡**（`/vodsearch/…` → Just a moment），改走站点自己的搜索接口：
   JSONP 返回 `{"code":1,"js":"<base64 的 JSON 数组>"}`，数组里是 `{id, data:{vod_name, vod_year, vod_area, vod_douban_cover, vod_pic}}`。
   沙箱没有 `atob`，源内自带纯 JS base64 + UTF-8 解码。接口对同 IP 有短时限流（5 秒级），连发会 429，源里给可读提示。
4. **播放地址**藏在播放页 iframe 的 `data-play` 属性里，格式是「随机字节前缀 + base64(真实地址)」，前缀长度随线路变
   （见过 `OPx` / `RAx` / `UFr` / `XIp`）。所以不按固定长度切，直接锚定 base64 里的 `aHR0c`（"http"）再解码。
   解出来是 m3u8/mp4 → `kind: video`；是 `v.qq.com` / `v.youku.com` / bilibili / mixdrop / abyss → `kind: webplayer`（播放页自带解析按钮）。
5. **线路排序**：详情页把线路名写在 `data-linename`，`data-lineid` 是资源站代号。排序 = 清晰度（4K/2160 > 1080 > 高清）
   + 资源站实测可用度（rym3u8 / moduplay / ikunyun / 360zy … 靠前，qq/youku/bilibili/bys/aby/dara/mixdrop 压到最后）。
   取前 4 条线路进 `chapters`，标题 `线路名 · 第N集`，用户在选集里换线即可。
6. **踩到的坑**：分集锚点里的可见文字前面有 56 个空格，`([\s\S]{0,80}?)</a>` 会漏掉大部分线路，改成 `{0,240}` 才全。

## 三、劇迷（gimy.org）

```
栏目  /tv/?country=cn|hk|tw|kr|jp|us&page=N   /movie/?page=N   /variety/?page=N   /anime/?page=N
搜索  /search?q=<词>&page=N                （搜索页卡片 class 顺序和列表页相反，解析要锚链接不锚 class）
详情  /video/{id}.html                     标题 /gimypic/{id}.jpg 封面 / 簡介 / 分集 /vplay/{id}/{ep}.html
播放  GET /_gimy_plays/{id}/{ep}           → {"video_plays":[{"play_data":"…index.m3u8","src_site":"mdzy"}]}
```

- 电影的分集 id 是 `default`，剧集是 `ep1…epN`；**老剧站点自己只挂 1 集**（如《後宮·甄嬛傳》只有 ep1），本源如实返回，不编造。
- `_gimy_plays` 每次给 13–27 条线路，全部是 m3u8。**但这些 CDN 时好时坏**：同一部片第一次探活 `hn.bfvvs.com` 404，
  第二次 `bfikuncdn.com` 200。所以 `content()` 会按顺序探活前 4 条（`#EXTM3U` + 200/206 才算可用），
  把可用的提到第一位，其余照样留在 `qualities` 里给播放器换线（实测换线后 1920x1080、BANDWIDTH 9.8M）。

## 五、4K 这件事，以及影视岛的接口地图（下一步）

这两个站**没有真 4K 线路**（扫了 20 条电影/剧集详情，线路名里没有 4K/2160；实测最优 1920x1080）。
要「1K/2K/4K」档位，站点侧只有 `4k影视`（已发布，网页播放器）和下面这个还没啃下来的：

**影视岛 yingshidao.com（海外，国内直连可开）**
- 页面：`tv.yingshidao.com` 是 Next.js SSR（首页/分类页 455 KB，卡片带 `4K`/`vip` 角标）；详情页是客户端渲染。
- 已经摸到的接口（都不需要登录）：
  - `GET /api/v1/search?q=<词>` → 结果里有 `has4k` / `has_hevc` / `coverUrl` / `id`（`mov_…`）
  - `GET /api/v1/video/detail?id=mov_…` → `{has4k, totalEpisodes, first_episode_id, region, tags, …}`
  - `POST /api/v1/security/signing-session` → `{token, key}`（搜索签名用，HMAC-SHA256 规范串在 `_next` chunk 里能还原）
- 卡住的地方：播放要 `POST /api/v1/video/playback/access`，返回 `PLAYBACK_DEVICE_REQUIRED` ——
  设备身份是 `ysd-device-continuity-v1` 那套签名 token（`security_device_token_v1` + 时间戳 + origin + 签名），
  还得看 4K 是否只给会员。要继续做这个源，下一步就是复刻 `device continuity` 签名。
