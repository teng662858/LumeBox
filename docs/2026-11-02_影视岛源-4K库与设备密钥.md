# 影视岛（tv.yingshidao.com）源：4K 库、分集接口与设备密钥

2026-11-02 · `sources/video/yingshidao.js` v2.0.0（id `ysd_video`）

## 一、站点与库

`tv.yingshidao.com`（官网 `yingshidao.com`，「身在海外」的华语影视站）。条目接口带 **`has4k`** 字段：
电视剧第一页 20 条里 12 条 `has4k: true`，是目前唯一「国产剧 + 真 4K 档位」的海外站。

分类：电影(1) / 电视剧(2) / 综艺(3) / 动漫(4) / 纪录片(5) / 少儿(6) / 短剧(7) / 微剧(10)。

## 二、开放接口（免登录，全部实测）

```
GET  /api/v1/video/category?categoryId=2&page=1[&type=tv-romance&regions=KR&years=2025]
GET  /api/v1/video/search?q=<词>&page=1
GET  /api/v1/video/detail?id=mov_…
GET  /api/v1/video/list?id=mov_…&page=1&limit=5000&include_free=1      ← 分集：id / episode_num / is_free / is_vip / intro_end_ms / outro_start_ms
POST /api/v1/video/playback/access   {episode_id, play_attempt_id, purpose:"PLAYBACK", ckey_prepare:{direct_guest:true}}
POST /api/v1/pingPlay/<episode_id>   （带 X-Playback-Token）
```

筛选三组都真实生效（`type` / `regions` / `years`），`filter_tags` 里直接给 id：

| 条件 | 首条 |
|---|---|
| 默认（电视剧） | 鉴定(2026/中国大陆/4K) |
| `type=tv-romance` | 一瓯春 |
| `years=2025` | 轻年 |
| `regions=KR` | 谎言 |

分集比例的实测：国产剧普遍**前 4–6 集免费**（`鉴定` 7 集免费 4、`尚公主` 22 集免费 6、`伟大的长征` 41 集免费 6），其余是会员档。

## 三、播放：两条路，各卡在哪

| 路径 | 结果 |
|---|---|
| guest `playback/access`（免费集） | 200 `decision:ALLOW`，返回 `play_url[1080p]` + `playback_token` + `device_token`，`locked_qualities` 里 4K 标 `FOUR_K_ENTITLEMENT_REQUIRED` |
| guest（会员集） | 403 `decision:DENY`，`next_action:MEMBERSHIP` |
| 取 `play_url`（/media/index.m3u8） | 必须带 Cookie `__Host-ysd_media`（access 响应就下发），否则 401 `browser playback cookie required` |
| 分片 `segment.ts` | 同样要 Cookie，否则 401 |
| 内层 CDN（vid.yingshidao.com/…1080p.m3u8?sign=） | 401 `playback authorization required`，换 UA/Referer/Origin/token 头都不行 |

本源的处理：`content()` 先做 access → 拼 Cookie → **自己先探一次 m3u8**，探活通过才把带 Cookie 头的直链交给播放器，
否则退回 `webplayer`。实测本机运行时探活就是 401（播放令牌与本次会话绑定、存活很短），所以现在默认走网页播放器。
如果以后 App 的播放器能把 `Cookie` 头透传到分片请求，这条路会自动生效。

**会员 / 4K 的硬门槛**：点播要设备密钥 —— WebCrypto ECDSA P-256 + `/ckey/assets/<hash>/ckey.wasm` 算 CKey，
签名串 `ysd-ckey-direct-v1\n…\n<episode_id>\n<play_attempt_id>\n<issued_at>\n<nonce>`；
而且账号登录态与设备公钥绑定，脚本侧新设备登录直接回 `DEVICE_KEY_SESSION_MISMATCH`（实测过你的账号，登录本身是成功的：
`channel:"email"` 200，`isVip:true`，`giftSupporterExpireAt` ≈ 7 天后）。
所以本源不代登录、不存密码，会员集与 4K 交网页播放器——在网页里登录一次，站内播放器自己算 CKey。

排查记录：purge 接口前几次返回 `"throttled": true, "throttlingReset": 993`——**节流窗口内的 purge 是空转**，所以之前一直没生效；

结论：jsDelivr 对 GitHub 分支（`@main`）的缓存是分区且最长 12 小时，purge 只保证部分边缘；急用时走 raw / pin / fastly 三条之一。

## 2026-11-02 v2.0.2：游客额度与网页选集修复

浏览器实测 `playback/access` 返回 401，跳转地址包含
`/playback-limit?action=LOGIN&reason=GUEST_IP_QUOTA_EXHAUSTED`。
这与截图的「游客试看已结束」一致，不能把网页 HTTP 200 当成视频播放成功。

- 删除源内游客 access / ping / 直链探测，避免在网页播放前另起随机设备请求播放授权。
- 播放统一交给站点网页，在同一浏览器上下文保留 Cookie、WebCrypto 设备密钥和站点的权益检查。
- 站点当前详情页脚本读取查询参数 `ep`，源现在下发 `?play=1&ep=<所选分集>`，修复所有集都打开同一地址。
- 源设置增加「登录影视岛网页」。遇到额度页，应点「已有账号，去登录」，利用站点 `returnTo` 回到影片。
- 不保存账号密码，不将配置 Cookie 复制到播放结果，不绕过会员、付费或游客额度限制。

验证：五入口在线检查通过；Node 回归覆盖分集保留、无游客请求、凭据不外传、镜像、空参数；两分类首条不同。
账号登录后的真机完整播放尚未验证；此版本修复会话衔接与选集，不声称解锁 VIP 或已实测整片播放。
