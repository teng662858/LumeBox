# 2026-11-01 两个BT影视 / 八号影视 会员核查（bttwo v2.0.1、bahaotv v1.0.1）

按 `docs/VIP处理约定.md` 的顺序逐条试过，结论先写：

| 站点 | 有没有会员墙 | 能不能破 | 结论 |
|---|---|---|---|
| 两个BT影视（bttwo.life） | 有：720/480 需会员、4K 仅客户端 | **不能**（服务端账号门禁） | 只取 1080 免费档，会员档给可读错误 |
| 八号影视（bhtv001.com） | **没有**（无付费墙） | 本来就能整片播 | 不需要破，源已直连 mp4 |

## 一、两个BT影视（bttwo）

### 1. 挡在哪层（实测回显）

同一个播放接口 `/video/play?p=<dataid>&v=<slug>&q=<清晰度>&s=<签名>&t=<毫秒>&k=<令牌>`：

| 请求 | 回显 |
|---|---|
| `q=1080` | `{"code":200,"quality_urls":[{"title":"4K","isvip":true,"locked":true,"url":"1"},{"title":"1080p","isvip":false,"locked":false,"url":"https://zijieapi.douyinbyte.com/m3u8/…m3u8"}]}` |
| `q=720` | `{"code":401,"message":"需要VIP会员才能观看，请先登录"}` |
| `q=480` | 同上 401 |
| `q=4k` | `{"code":403,"message":"4K清晰度仅支持客户端播放，Web端不支持"}` |
| 整片会员专享的条目（如 ch4r1kh05） | `q=1080` 也回 `401` |

签名本身不是障碍：`s = HMAC-SHA256(key=slug, msg="dataid:t:slug")[:32]`、`k = base64(xor("nbmovie2024secretkey", userlink))`
（v2.0.0 已逆出并在源里用纯 JS 复现，1080 直连 200 + `#EXTM3U`）。

### 2. 逐条排除的路子

| 路子 | 做法 | 结果 |
|---|---|---|
| 页面层可绕 | 播放页 HTML / `app.ultra.min.js` 里找 720、m3u8、quality | 页面里一个地址都没有，全部由 wasm 现算 |
| 换清晰度编码 | `q=1…5 / hd / sd / fhd / uhd / 2160 / 1080p / 720p / 480p / bluray / BD / "1080,720" / all` | 除 `1080`、`4k` 两个特判外，其余全部回落成 1080；没有一条能拿到 720/480 |
| 换客户端 | `okhttp`、`Dart`、自造 `nbmovie-app` UA；追加 `&client=1 / &app=1 / &platform=android / &type=app` | 仍然 401 / 403（4K 那条文案不变） |
| CDN 路径可推导 | 1080 实为 `https://zijieapi.douyinbyte.com/m3u8/<32位hash>.m3u8`，采样 6 条 | `md5(dataid)`、`md5(dataid+清晰度)` 等十余种拼法全部对不上；同 hash 加 `_720/-720/_hd/_sd` 等后缀一律 `404 token 不存在或已过期`（CDN 按路径签名） |
| 接口越权 | 站内脚本里能看到的接口：`/api/vod/<id>/hits|play|viewer`（统计） | 试 `/api/video/play`、`/video/playv2`、`/video/playall`、`/api/app/config` 全 **404**；wasm 只导出 `build_play_url(dataid, secret_key, quality, play_key)` 一个函数 |
| 页面层「下载」 | 播放页有「影片下载」入口 | 跳的是另一个 BT 站 `btbtla.com`，本站不提供磁力/网盘地址 |
| 同库镜像 | 4k影视、子子影视是同一套 CMS | 同样 `q=720 → 401`（子子影视另有 4K 403），镜像不解决问题 |
| 免费注册 + 越权 | `/api/register` 要 `username + email + password + email_code` | 需要邮箱验证码，属于「要用户账号」的范畴；按约定不做，也不伪造会员身份 |

### 3. 本次改动（v2.0.1）

1. `pickUrl` 从「取第一条未锁定」改成**按清晰度从高到低挑**（站点哪天放开 720 会自动用上，不会退档）；
2. `content()` 多返回一个 `qualities`（当前可用的免费档），播放器里能显示可选清晰度；
3. 401 的报错拆成两种：整片会员专享 / 只是这个清晰度要会员，文案带上站点原话；
4. 文件头写清「挡在哪层、试过什么、为什么取不到」（就是上面这张表）。

实测：`node tools/lume-source-check.mjs sources/video/bttwo.js` →
`content` 拿到 `https://zijieapi.douyinbyte.com/m3u8/cfe427ae….m3u8`，**200 + application/vnd.apple.mpegurl，30,061 B + #EXTM3U**。

## 二、八号影视（bahaotv / bhtv001）

### 1. 没有付费墙（实测）

抽样 8 条（电影 4 + 剧集 4）首集播放页，`player_aaaa` 全部是：

```
trysee=0  points=0  encrypt=0  from=iframe（部分 yg1）
url=https://xx.kanrenao.cn/v/ty/<sid>
```

iframe 页给 `var rand` + `var player`（base64），用 AES-128-CBC（key=`VFBTzdujpR9FWBhe`、iv=`rand`、Pkcs7）
解出来的 JSON 里就是真地址；实测 mp4 **206 + video/mp4 + `ftypisom`**，可整片播。

站内 `/label/vip.html`、`/label/new.html`、`/user/index.html` 一律返回「网站维护中......」（1143 B），
没有会员片库入口；详情页、播放页也没有「会员/金币/收费」字样。

### 2. 本次改动（v1.0.1）

只补了核查记录（文件头写明「本站在抽样范围内没有付费墙、不需要破」），逻辑没动，避免为改而改。
实测：`content` → `https://media-zjhz-fy-corp.zj6oss.ctyunxs.cn/CORPCLOUD/….mp4?x-amz-…`，
**206 + video/mp4，262,144 B（Range 探测）**。

## 三、结论

- **两个BT 的 720/480 破不了**：不是签名或前端的问题，是服务端按账号判会员，匿名只发 1080。
  继续硬来只有两条路——拿别人的会员身份（属于伪造账号，不做）或买会员（付费，不做）。
- **八号影视 没有会员墙**，现状就能整片播。
- 两个源都已按上面的改动重新发布（App 仓库 + 源仓库，raw 与 jsDelivr 双线路同版本）。
