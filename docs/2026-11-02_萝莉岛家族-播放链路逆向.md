# 萝莉岛/洛丽塔家族：播放链路逆向（比 luolid.conf 更进一步）

2026-11-02 · 目标：不停在「去广告 + 偷 m3u8」，而是把**播放链路本身**拿下来

## 一、先确认 luolid.conf 到底破了什么

| 层 | 它做了什么 | 没做什么 |
|---|---|---|
| 响应层 | AES 解密 → 删广告字段 → 重加密 → 重签（key=iv=salt=`6c3a9ad53fae2796`） | 不动 `is_vip / need_coin / price` |
| 播放层 | 拦截 App 已发出的 m3u8，把 host 换成 `d39jna88gmha0l.cloudfront.net`，通知里给直链 | 不生成地址、不解析接口、不处理会员片 |

也就是说：**它没有破解任何签名**——它偷的是 App 自己拿到的地址，CDN 那端只是没校验 `X-Playback-Session-Id`。

## 二、往上游走一层：这个家族的 Web 端就是完全开放的入口

同族 Web 端：`p3.sbpmlenma.cc`（标题「洛丽塔」，Flutter Web）。`flutter_bootstrap.js` →
`main.dart.js?v=1793244792026`（6.5 MB，dart2js）。把它拉下来就能静态读到整套协议。

### 2.1 API 路由：330 条（节选）

```
/api/home/getconfig        /api/home/getads        /api/home/banner
/api/mv/detail             /api/mv/buy             /api/mv/completed
/api/mv/list_short_mv      /api/mv/list_of_tag     /api/mv/favorite
/api/tabnew/list_construct /api/tabnew/feature_mv  /api/tabnew/discovery
/api/product/list          /api/product/create_order
/api/users/base_info       /api/users/subscribe
```

API base 不是写死的：bundle 里有 `$.apQ="https://dx-094-api1.ympxbys.xyz/api.php"` 这类**按批次轮换**的域名
（`dx-<NNN>-api1.<随机>.xyz`），所以旧脚本里的 `api2.saggopnvv.cc` 只是其中一支。

### 2.2 信封格式（这一版客户端已经不是 AES-128 了）

从 bundle 里读到的校验与实现：

- `"AES-256 密钥必须是 64 位十六进制字符"` → `dmK()` 把 64 hex 转成 32 字节；
- `"Key must be 32 bytes for AES-256"` → base64url 形态的 key 也接受；
- 解密走 `self.crypto.subtle` 的 `AES-CBC`；
- **IV 不是随机字节，是 16 位十六进制字符串的 ASCII 字节**（见实测）；
- 密文布局：`前 12 字节 IV + 密文`（bundle 注释原文：「密文为「前 12 字节 IV + 密文」」）。

### 2.3 播放地址的拼装规则

bundle 里下载器那段写得很直白：

```dart
a1 = 取 urlPath 的目录前缀（到最后一个 "/"）
e  = CDN主机 + "/" + a1 + basename + ".m3u8"
```

即 `/api/mv/detail` 返回 `urlPath`（形如 `/20260101/abcdef/abcdef`），客户端用 CDN 主机拼成
`https://<cdn>/20260101/abcdef/abcdef.m3u8` —— 和旧脚本正则
`[^/]*\..*\.cn/\w+/[a-z0-9]{32}/[a-z0-9]{32}\.m3u8` 的形状完全对得上。

## 三、浏览器实测：hook `crypto.subtle` 能抓到什么

用 CDP 注入（`addInitScript`）包住 `crypto.subtle.decrypt / importKey`，打开站点等它自解密：

```
{ op:"decrypt", alg:"AES-CBC", iv:"39376236303339346162633266626531", len:325056 }
```

`39376236…` 转 ASCII 是 `97b60394abc2fbe1` —— **IV 就是这 16 个字符的 ASCII 字节**，和 bundle 里的实现完全一致。
同一批抓到 210 KB / 325 KB 的解密调用（资源包，不是 API）。

**key 抓不到**：hook `importKey` 没有命中，说明密钥是在 **Web Worker** 或其他执行上下文里导入的，
而且 `extractable=false`（`exportKey` 拿不到）。这是 Flutter Web 常见做法：密钥不进主线程。

## 四、把它彻底拿下的两条正路（下一步）

1. **Worker 级 hook（最稳）**
   在页面最早期覆盖 `Worker` 构造函数，往 worker 里注入同一段 `importKey/decrypt` 包装：

   ```js
   const OW = window.Worker;
   window.Worker = function (url, opts) {
     const w = new OW(url, opts);
     w.postMessage({ __hook: true });            // worker 侧配合 onmessage 里自装 hook
     return w;
   };
   ```

   worker 里同样有 `crypto.subtle`，`importKey` 的原始 `keyData` 一定经过这里 —— 这样能直接拿到 64 hex。
2. **改 bundle 的 extractable 标志**
   `main.dart.js` 里的 `importKey` 调用点把第 4 个参数（`extractable`）从 `false` 改成 `true`，
   本地起个静态服务器加载改过的包，再打开页面就能 `exportKey('raw')` 导出密钥。

拿到 key 之后，剩下就是纯本地计算：

```
POST /api/mv/detail {id} → 解密（AES-256-CBC，key, IV=密文前 12 字节）→ 取 urlPath
→ 拼 https://<cdn>/<urlPath>.m3u8  → 探活（200 + #EXTM3U）
会员片：/api/mv/buy 需要账号金币，接口会返回空 urlPath —— 到这里就是服务端权益，客户端改不动
```

## 五、为什么这条路线比 luolid.conf 强

| 能力 | luolid.conf | 本方案 |
|---|---|---|
| 需要用户打开 App 播放一次才有地址 | ✅ 必须 | ❌ 不需要，直接查接口 |
| 需要装 MITM 证书 | ✅ 必须 | ❌ Flutter Web 走浏览器即可 |
| 能批量出直链 | ❌ 一次一条 | ✅ 列表 + detail 遍历 |
| 能处理会员片 | ❌ 只能偷已授权的 | ⚠️ 同样受限（服务端权益） |
| 抗改版 | ❌ 正则/域名一换就废 | ⚠️ 路由表 + 拼链规则要跟着改，但比正则稳 |
