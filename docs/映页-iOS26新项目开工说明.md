# 映页 · 原生 iOS 26 新项目开工说明

2026-11-12 · 给新仓库的第一份开发文档。用户创建独立项目后，将本文件交给新会话即可开始。本文可以单独阅读；旧仓库里的界面草图和图标是附加设计资料。

## 1. 已定方向与建议选型

**用户确定**：另开独立项目，最低支持 iOS 26.0；界面重新设计，App 端所有功能逻辑重新编写；内容源从外部导入，尽量兼容现有脚本和私有订阅；代码精简、操作快；视频提供三个内核。

**本稿建议**：沿用“映页”和松绿折纸播放键图标。以 Swift 为主语言，SwiftUI 写页面，UIKit 按需承担播放器显示面和复杂手势。使用 QuickJS 执行外部 LumeSource JavaScript。三个视频内核推荐 **AVPlayer、MPV、MDK**，其中 MDK 是本轮推荐的第三个，尚待用户选定。第一批按 iPhone 个人设备试用规划。

| 可以沿用的东西 | 新项目如何使用 |
| --- | --- |
| 已发布的外部源与私有订阅 | 保留脚本文件、订阅格式、稳定 ID、源入口参数和返回值。由用户导入后运行 |
| 设计稿、图标、旧版表现和已知问题 | 作为设计输入、兼容对照和验收样例 |
| 系统框架和第三方基础库 | 直接使用官方框架或锁定版本的上游库，记录来源、许可证、包体与用途 |
| 旧 App 的 Dart、Swift、Objective-C、插件桥和数据库服务 | 仅查看行为和数据格式。新仓库从空工程设计并实现页面、源宿主、播放器适配、缓存、资料库、导入和诊断。**旧版已用原生写过的播放器也重新写** |

独立仓库、Bundle ID、数据容器和签名配置保证新旧 App 可以并排试用。新项目无需 Flutter 引擎、Dart 桥或旧 App 的工程依赖。原评审稿里有关拆出旧控制器、移植旧桥及其工期估算的安排，已由本说明取代。

## 2. SwiftUI、QuickJS 和播放器怎样配合

用户点击一集时，SwiftUI 把作品和章节 ID 交给本次播放任务。Swift 宿主在专用执行队列调用外部源的 `content`，为脚本提供受控网络、解析、加密和按源存储，拿到媒体 URL、精确请求头、线路和类型后交给当前内核。播放期间进度、手势、音轨和错误由原生代码处理。这样脚本完成取址后就能让出执行资源。

先做一个 App target，按浏览、源、播放、资料库组织文件。页面只持有显示所需状态；源调用有超时和取消；一次播放只保留一个活动内核。三种内核共用一张播放页、一套选集和一套进度写入。优先把接口放在确实有多种实现的地方，例如播放内核，避免为每个类型同时建立协议、服务、管理器和转发对象。引入新库时记录它解决的实际缺口；第二种消费者或独立测试需求出现后再拆包。

## 3. 从空库到可用的外部源

1. **首次启动为空库。** 首屏给出“从文件导入”和“添加私有 GitHub 订阅”。安装包中不预装站点脚本、真实账号、默认内容库或自动订阅地址。测试夹具只进入测试目标。
2. **预览与安装。** 校验文件大小、身份头、源 ID、版本、内容类型及要求的宿主能力。显示新增、重复、更新、暂不支持和错误项。相同 ID 的本地修改遇到订阅覆盖时让用户选择；一次中断不能破坏已安装版本。
3. **运行与隔离。** 各源使用自己的配置、Cookie、镜像和存储。按现有契约实现 HTTP 重定向、二进制请求、DOM 解析和实际样本用到的加解密。限制运行时间、内存、响应大小和并发；死循环要能中断。QuickJS 的限制和中断接口见[上游手册](https://bellard.org/quickjs/quickjs.html)。
4. **更新与授权。** 私有 GitHub 通过只读授权取得清单及脚本；令牌放钥匙串，只发给受信任的 GitHub 接口。先下载和校验，再原子替换，失败继续使用上次可用版本。订阅更新与 App 发布独立。
5. **验证兼容性。** 首批建议挑用户常用的 5–10 个源，记录实际 ID、版本、依赖能力和结果。用固定响应检验 `categories/list/detail/chapters/content`，再验可选首页、筛选、分类分页、搜索、登录、封面和真实内容。分别报告“源返回地址”“媒体端可访问”“设备确实出画、出声”。

第一批优先支持现有 LumeSource JS。输出模型预留视频、图集、正文、音频及网页播放类型。Kazumi、TVBox 配置或远端接口可逐类实现；依赖 Node 模块、多文件加载、Python Spider 的源另列兼容项。QuickJS 本身只提供 JS 执行能力。遇到不兼容的导入，明确提示缺哪个运行时；若用户天天用的源依赖它，应在技术样机阶段评估。

## 4. 三内核的分工和使用体验

| 内核 | 用户选择它的理由 | 首轮验证重点 |
| --- | --- | --- |
| 系统 AVPlayer | 默认播放普通 HLS、MP4，承接系统媒体能力 | 真机首帧、缓冲恢复、后台音频、音频路由、画中画；HDR 和 AirPlay 单独验收 |
| MPV（libmpv） | 特殊封装、多音轨或复杂字幕需要另一种兼容路径 | 带字幕的 MKV、音轨选择、横竖屏画面方向、系统中断和退出释放 |
| MDK（推荐） | 在同一原生页面提供另一条硬解与显示路径，便于处理某个内核特有的渲染问题 | VideoToolbox 与 Metal 真机出图、首帧方向、色彩、seek、功耗及切回系统内核 |

MDK 上游提供 iOS、Swift 绑定、VideoToolbox 和 Metal 支持。旧项目的测试记录可帮助挑选样本。新项目应先验证 Swift 接入、设备/模拟器切片及其与 libmpv 的 FFmpeg 二进制能否共存，实测重复库造成的包体增量。原 Flutter 包的密钥不作为新原生 App 的授权依据；个人非商用或后续商业分发分别核对授权。样机阶段如发现链接或许可障碍，交付实测结论后再决定第三核。[MDK SDK 与授权说明](https://github.com/wang-bin/mdk-sdk)

播放器“更多 → 播放内核”列出三项。默认 AVPlayer，允许记住某个源的选择。手动切换应保留同集时间点、暂停意图和倍速，停止旧声音，按目标内核重新准备请求头和媒体。网络拒绝或签名过期时给“重新取址／换线路”；解码或渲染失败才提示“换内核”。避免三个内核轮流重复请求同一个失效 URL。画中画等能力按当前内核实际支持情况展示。

### AetherEngine 是否更适合作第三核

AetherEngine 是第三个位置的另一位候选。它面向 Apple 平台，提供 Swift 接口，采用 FFmpeg 解封装并支持 VideoToolbox 解码。若映页把直播时移、隔行电视源、复杂字幕或 HDR 片库列为常用场景，值得优先试它。具体输出取决于素材、设备和音频路由。[AetherEngine 上游功能与限制](https://github.com/superuser404notfound/AetherEngine)

旧 LumeBox 的模拟器记录里，Aether 与 MDK 都通过了 MP4/HLS 播放、暂停和跳转。旧 Aether 接入还出现过挂起的 load 阻塞 stop、迟到快照覆盖新状态的问题。它们为新接入提供了复现样本；当时没有设备崩溃堆栈，不能断定崩溃来自引擎本身。旧项目可查《2026-11-12_系统播放器与Aether卡死修复》和《2026-11-12_播放链路全面检查-report》。

第三核的决策放在 M0。用两个临时比较构建，分别组合 AVPlayer／MPV／MDK 和 AVPlayer／MPV／Aether。用同一台 iPhone、同一批片源，优先挑 AVPlayer 或 MPV 已经遇到问题的片，比较哪一个能额外播好这些片；再测加载中退出、横竖屏、字幕、内存峰值与安装体积。若两者表现相近，选适配代码更少、依赖和发布授权更合适的一方。后文以 MDK 作排期示例；若 Aether 更合适，替换第三个位置，日用包仍交付三个内核。

## 5. 用户会看到哪些页面

| 场景 | 第一版设计和验收行为 |
| --- | --- |
| 导航与品牌 | 完整规划为视频、阅读、资料库。视频试用阶段展示视频和资料库，阅读完成后加入。系统中文字体、稳定底色、松绿主操作，玻璃用于系统栏与浮层 |
| 首页与换源 | 视频和阅读两个首页的顶栏均显示“当前源名 ▾”，与搜索相邻；空库显示“导入源”。弹出面板标出当前源、常用源及管理入口。分别记住两个板块的当前源、浏览位置和筛选条件 |
| 浏览与搜索 | 有记录先显示继续观看／阅读，无记录直接显示可用内容。按当前源实际能力展示分类、搜索、分页和筛选，返回时恢复列表位置 |
| 详情与播放 | 主按钮写明集数和续播时间；线路与选集放在一起。播放器横竖屏都能返回、暂停、拖动和切核；错误时仍能操作，离开详情可取消正在进行的取址 |
| 漫画、图集、小说、有声书 | 漫画和图集优先保证缩放、翻页与页码恢复；小说按段落锚点恢复字号改变后的阅读位置；有声书支持队列、锁屏、定时与中断恢复 |
| 资料库、设置与离线 | 收藏、历史、下载集中管理，区分同名作品的来源。设置管理订阅、隐私、备份及缓存容量。无痕访问不写历史；离线可打开已完成的下载 |
| 辅助功能 | 主要动作有文字或 VoiceOver 标签，选中状态可用文字辨认。验证动态大字、深色模式、减少透明度、横屏安全区和返回按钮触达范围 |

## 6. 数据、隐私与可靠性

建议用 SQLite 建立新库，只存实际使用的字段；作品与章节保留板块、源 ID 和原始作品／章节 ID。签名 URL 会过期，不充当历史主键。收藏、逐集进度与设置各有单一写入入口，退出播放、后台切换和换集时保存对应章节。

旧数据导入是可选功能。旧版配置备份格式为 `lumebox-configuration`，现有导出 v2，恢复入口支持 v1/v2。先做只读预览，再按字段映射、重复项去重、事务提交。检查密码错误、损坏备份、取消、空间不足和再次导入。源脚本若来自用户主动选择的备份，仍经过外部导入校验。新 App 单独授权登录；诊断包仅记录阶段、耗时、内核和错误类别，隐去令牌、Cookie、媒体路径和查询参数。

下载任务与临时缓存分别管理。完成文件核对后再写入可离线索引，被系统回收的缓存允许重建；重试或取消不能留下“已完成但打不开”的条目。iCloud 同步、旧离线文件迁移和可选模型按后续版本排期。

## 7. 怎样判断代码精简、运行快

| 约束 | 验收方法 |
| --- | --- |
| 启动先呈现本地界面 | 启动不等待全量订阅更新、逐个源探活或初始化三个内核。建议目标：指定真机 Release 构建，20 次冷启动，本地首屏可操作 P95 ≤ 2 秒 |
| 只付当前操作的成本 | 用户选中时才加载解释器或创建对应播放实例。快速切源、换集或退出后，无旧请求覆盖新页面、无两路声音。记录首次进入和重复进入的耗时 |
| 字节到达就可消费 | 必要探测限于有限前缀。受保护的 MP4 Range 和慢速 HLS 分片测试中，上游尚未结束时播放器已经收到首批数据 |
| 列表与阅读顺滑 | 图片按显示尺寸解码、分页加载、有限预取和可取消任务。固定封面列表或大图章节连续滚动，用 Instruments 比较卡顿与内存峰值；检查反复退出后缓存是否有界 |
| 播放测到用户看见画面 | 分别记录点击、解析结束、媒体首字节、首帧和进度推进。建议每核每种本地受控 MP4/HLS 样本各 20 次，记录中位数与 P95，初始首帧预算为装载后 2 秒。真实 CDN 与本地样本分开报告 |
| 代码规模可解释 | 一次播放只有一个活动会话，三个内核共用页面和历史；每个新增依赖记录引入原因和包体差值。评审删除重复状态、重复请求和用不到的依赖，而不是用行数当作性能指标 |

上述数字是样机的设计预算。M0 固定设备、系统、媒体和构建方式，取得基线后再定正式门槛。每个内核连续切换与释放至少覆盖 20 次，并抽查 30 分钟长播、真实音频及设备温升。完整工作流按里程碑或受影响范围运行，日常推送只跑对应检查。

## 8. 实施顺序和每阶段的交付物

| 阶段 | 开发范围 | 看得到的完成条件 |
| --- | --- | --- |
| M0 原生技术样机 | 新 iOS 26 工程、空库、本地外部 JS 导入、QuickJS 最小宿主、AVPlayer 首条链路；并行项为 MPV／MDK 原生链接与包体试验 | 真机从文件导入一个原有源，找到一个节目并出画出声；超时脚本可停止；记录三核共存可行性、授权与性能基线 |
| M1 视频日用版 | 私有订阅、单源搜索、分页、详情、三核适配、换线、收藏、续看和诊断 | 全新安装后通过外部订阅观看，退出再开能续播。三核各播同组 MP4/HLS，手动切换保持进度；另测字幕、特殊封装、方向与声音 |
| M2 阅读与音频 | 阅读首页和换源、漫画图集、小说、有声书、书架及基础离线 | 每种内容用真实外部源完成一次完整流程；重启后位置正确，电话中断和视频/听书切换后音频归属正确 |
| M3 完整性 | 备份正式导入、下载恢复、用户常用的其他源格式、隐私与无障碍 | 给出功能与源兼容清单；用户可以核对备份条数、回滚导入，离线打开作品 |
| 后续增强 | 按使用频率决定跨源聚合、公共弹幕、云同步、翻译、超分、片头识别等 | 每项单独列出依赖、磁盘或功耗代价及用户收益，再进入开发 |

**排期依据。** 全部重写和三核交付改变了旧草案的工作量。首轮先评估三个未知数：常用外部源所需的宿主能力、MPV/MDK 的原生二进制共存、真机安装与取证条件。M0 后按实际完成的一个源、一个播放器闭环及剩余能力清单重新估算。Mac/Xcode 构建环境、iOS 26 或以上真机、可用于试装的签名与一组可重复媒体样本是实机验收所需资源。

## 9. 新项目第一条任务

用户开好项目并发出开始指令后，可以直接粘贴：

> 按《映页 · 原生 iOS 26 新项目开工说明》在当前独立仓库做 M0。全新编写 Swift 原生界面和 App 逻辑，内容源只从外部导入。先以 SwiftUI、QuickJS 和 AVPlayer 跑通“空库 → 文件导入现有 JS 源 → 详情 → 真机播放”，同时评估 MPV 与推荐的第三核 MDK。交付可安装的样机或明确的构建验证结果、实际测试的源版本、三核共存结果、首帧耗时和下一阶段估算。

有旧项目访问权限时，可从 LumeBox 的 `docs/lumesource-guide.md` 核对源契约，从 `docs/iOS26界面草图.html` 和 `docs/brand/yingye-icon.png` 取设计资料。首批源从用户提供的外部文件或私有订阅取得。正式 Bundle ID、签名身份、优先源名单与分发渠道在新项目启动时填入；凭证进入设备钥匙串或构建环境。
