# 懂片帝源（`video/dongpiandi.js`）

2026-11-03。站点：懂片帝 / 懂片帝AI（`https://dongpiandi.ai`，标题「懂片帝AI - 懂片AI找片、片单与播放」）。
定位是**AI 找片 + 片单 + 播放**的聚合前端：自己不做片库，把各家聚合资源站（红牛、新浪、极速、豪华、
ikun、无敌、魔都、西瓜…）和官方 CDN（bytevod / bytetos）的线路编排到一部作品上。

形态是 **React SPA + 同源 `/v1/*` JSON 接口**：首页 HTML 只有 4 KB，`<div id="root">` 之外没有内容，
所有数据都得走接口。站点前面是 CloudFront，实测直连可开（`network: "direct"`）。

## 一、签名（不通这一关什么都取不到）

每个 `/v1/*` 请求都要三个头，少一个就回
`401 {"error":{"code":"invalid_request_signature","message":"Missing request signature."}}`：

| 头 | 值 |
|---|---|
| `x-ai-movie-timestamp` | `Date.now()` 毫秒 |
| `x-ai-movie-nonce` | 16 字节随机 hex（32 字符） |
| `x-ai-movie-signature` | `HMAC-SHA256(SIGN_KEY, msg)` 的 hex |

```
msg = METHOD + "\n" + pathname + search + "\n" + timestamp + "\n" + nonce
SIGN_KEY = 8b9a908a05eac640e1ee06f52acaa741bfe4ba9e004eeffdbeb635e532e06666
```

- 算法出自 `/assets/movie-card-runtime-*.js` 的 `Aa` / `Ta`（key 是模块里的 `Jo="…"`）。
- **只校验这三个头**：`x-ai-movie-client-name` / `client-version` / `build-version` /
  `protocol-version` / `site-host` 都不填也能过 —— 站点换前端版本不影响本源，不用跟着改版本号。
- 签名后的 `pathname + search` 必须与真实请求路径逐字一致，所以源里所有查询参数都自己
  `encodeURIComponent`，不让宿主做二次编码。
- 设备时钟偏差会让签名失真：源里遇到 `invalid_request_signature` 时按响应 `Date` 头校正
  `clockSkew` 再重试一次（只校一次，避免死循环）。
- 站点换 key 时：把新 `main-*.js` 里的 `Jo="…"` 抄进源的 `SIGN_KEY` 即可。

## 二、接口（全部 GET/POST JSON）

| 用途 | 路径 | 关键参数 |
|---|---|---|
| 首页板块 | `/v1/feed/home` | `cursor`（预览只回 8 个板块，`meta.total_sections=11`） |
| 列表 / 搜索 / 榜单 | `/v1/browse/catalog` | `q` / `kind` / `genre` / `area` / `language` / `year` / `sort` / `hot_list_key` / `page` / `limit≤20` |
| 分类与筛选表 | `/v1/runtime/bootstrap` | 读 `catalog_ui.catalogs[].rows[].options[].params` |
| 详情 + 分集 | `/v1/catalog/{id}` | 返回 `episodes[]`，每条带 `token` |
| 线路表 | `/v1/playback/resolve/{token}` | 返回 `line_options[]`（本片 13–32 条） |
| 票券换址 | `POST /v1/playback/resolve-line?view=compact` | body `{ticket}`，成功 201 |
| 游客会话 | `POST /v1/users/anonymous` | 本源默认不用（票券线路匿名也能换） |

`limit` 上限 20，传更大也只会回 20 条；分页用 `page`（`pagination.has_more` 判「还有」）。

## 三、分类与筛选（都实时跟站点）

- 分类 id 直接用**站点查询串**：`all`、`kind=movie`、`kind=series`、`kind=anime`、
  `kind=variety`、`kind=short_drama`、`kind=documentary`、`kind=sports`、
  `sort=trending&window=day`、`hot_list_key=tv_korean` … `hot_list_key=movie_nowplaying`。
  `list()` 解析这段串直接拼给站点，所以分类之间内容确实不同（实测首条 id 全不相同）。
- 首页板块的「更多」用 `section.browse.params` 转成同一套编码（丢掉 `page`/`limit`），
  点进去就是普通列表分页 —— 不需要为每个板块写分支。
- `filters()` 读 `/v1/runtime/bootstrap` 的 `catalog_ui`，按当前分类的 `kind` 取行：
  分类 / 地区 / 语言 / 年份 / 排序（短剧还多「状态」「形式」两行，站点标了 `enabled:false` 的选项跳过）。
  选项 id 里编码站点真实参数（`genre:喜剧`、`area:中国大陆`、`sort:updated_desc`）。
- **genre 不支持多选**：`genre=古装,爱情` 会退化成模糊匹配，源里取第一个。

## 四、播放（两层线路，默认不碰额度）

`line_options[]` 里两种线路：

1. `resolve_mode:"direct"` + `url` 本来就是 `http(s)://…m3u8|mp4`（第三方聚合资源站，占绝大多数，
   实测 200/206 + `#EXTM3U`）→ **不需要登录、不扣额度**，本源默认走这条。
2. `resolve://<ticket>`（官方 1080P/4K、bytevod/bytetos）→ 要 `POST /v1/playback/resolve-line`
   换真实地址，按站点词元计费；默认只在直链一条都没有时才兜底。

**为什么不逐条探活**：App 单次调用预算 3–5 秒，而聚合资源站的 CDN 里总有一两条已经挂掉、
要等宿主 6 秒超时才回（实测某集 4 条串行探活把 `content` 拖到 16 秒，直接判超时）。
所以改成「按实测稳定性排序 + 一次 resolve 直接给地址」：

- 权重 = 站点 `preference_weight` + 资源站稳定性修正（hongniu/xinlang/jszy/hhzy/ikun/subo 稳定 +300，
  ffzy/suoni/niuniu 常挂 −260，dbzy/maotai/jinying 偏低）；官方 mp4 直链本来权重最高。
- 排序后前 5 条进 `qualities`（label 用资源站名），默认播第一条，别的线路用户可在播放器里切。
- 正常情况 `content` 只要 **0.2–0.9 秒**，不会再撞预算。

## 四·二、账号要不要填（2026-11-03 用真实账号实测）

结论先给：**不填也能用全部片库**。

| 场景 | 登录前 | 登录后 |
|---|---|---|
| 线路表（嫁金钗第 1 集） | 34 条（25 直链 + 9 官方票券） | **完全一致**：provider / 权重 / `token_scenario` 逐条相同 |
| 4K 票券（`新4K-限时等级专属`） | `resolve-line` → 201 + 真地址 | 同 |
| 4K 海外（`4K海外-官方C`） | 201 + 真地址 | 同 |
| 1080P 官方 S/V/B | 201 + 真地址 | 同 |
| `/v1/users/me/quota` | 401 `User session is required` | 200 |
| `/v1/midnight-theater/*` | 401 `midnight_session_required` | 403 `midnight_confirmation_required`（要先确认 18+） |

所以登录多出来的只有**站内那套账号功能**（每日词元额度、收藏、播放历史、午夜剧场），
对「能不能看、能不能换 4K」没有任何影响。本源把账号做成**可选**：

- **登入接口**：`POST /v1/users/password/login`，body `{account, password}`（字段名是 `account`
  不是 `username`，传错回 400 `validation_error`；登录不要验证码，注册才要 `captcha`）。
  成功 201，`Set-Cookie` 里给 `ai_movie_session=ums2_…`（HttpOnly，一年有效）。
  同一条响应里还会先塞几个 `Max-Age=0` 的空 cookie 覆盖旧值，所以取 cookie 要按
  `ai_movie_session=ums2_` 前缀匹配，不能取最后一条。
- **会话**存 `LumeSource.fs`（`session.json`，按账号隔离，换账号自动失效），
  下次调用直接复用；401 时清掉重登一次。
- **登录失败不阻塞播放**：密码错只写一条 `login_fail.json`（含凭据指纹 + 30 分钟 TTL），
  期间不再白试登录，票券照样按匿名身份换得到地址。
- **线路偏好**（`lineMode`）：`direct`（默认，直链优先，免费）/ `official`（先换官方票券，
  画质更好、扣词元，失败回落直链并把直链一起塞进 `qualities`）。
- **设置页两个动作**：`检查账号与额度`（强制登录一次，显示昵称 / 等级 / 今日词元用量）、
  `退出站点登录`（清会话）。实测输出：

```
账号：teng233（林间小太阳2017）
等级：练气1层（member）
今日词元：已用 0 / 上限 100 万，剩余 100 万
额度重置：2026-11-03T16:00:00.000Z
```

`/v1/users/me/quota` 关键字段：`used_tokens` / `limit_tokens` / `remaining_tokens` /
`reset_at`，另有 `level_benefits`（含 `official_line`：同一影片只计一次词元、不限下载投屏）
与 `economy.service_estimates`（官方蓝光约 66 次）。

## 五、交付形态

- 板块 `video`；`contentCategory: "movie"`（与同架构的看剧AI 源一致：主站是综合影视聚合，
  成人内容只在站内分类里出现，不是成人专站）。
- 章节 id 用站点的 episode token（`t:<token>` 前缀），`content` 直接拿它换流，不需要再请求详情。
- 单集内容（电影/短剧）章节标题用站点 `remarks`（「高清」「全1集」），多集用 `第N集`。
- `detail()` 把演员/导演/类型拼进简介，封面用 `poster_url`（站点走 `gimg0.baidu.com` 代理，
  直接 200 + `image/webp`，不需要额外请求头）。

## 六、实测（2026-11-03）

| 项 | 结果 |
|---|---|
| `home()` | 8 个板块 × 12 卡，651 ms |
| `list()`（16 个分类两两对比） | 首条 id 全不同，280–520 ms |
| `list()` 搜索「流浪地球」 | 11 条，首条「流浪地球2」 |
| `filters()` | 5 个 kind × 4–7 行的真实选项 |
| `chapters()` | 龙岭迷窟 18 集 / 嫁金钗 55 集 / 雪迷宫 32 集 |
| `content()` | 213–899 ms，直链 206 + `#EXTM3U` |
| 真 QuickJS 沙箱 | 签名头与 Dart 侧 HMAC 逐字一致，列表解析 2/2 |
| 账号登入（v1.1.0） | 真沙箱里 `settingsAction('checkAccount')` 登录成功、`/v1/users/me` 带 `ai_movie_session` Cookie、额度文案正确；`logout` 清掉会话 |
| 密码错误 | 只写 `login_fail.json`（30 分钟内不再重试），票券改按匿名换、播放不中断 |
| 会话复用 | 同进程第二次 `content` 不再发登录请求 |
| 官方优先模式 | 首条线路变 `海外-官方C` 票券，`qualities` 追加 4 条直链 |

## 七、限制

- 接口依赖站点签名 key；站点大改前端（换 key）时本源要跟一次 `SIGN_KEY`。
- 「午夜剧场」（`/v1/midnight-theater/*`）是站点自己的 AI 成人片单，要账号 + 成人确认；
  本源不接这一块，只做公开片库。
- 只有「官方线路优先」或直链全挂时才消耗站点词元（账号等级 1 = 每日 100 万）；
  直链全挂会抛可读错误，不编造地址。
- 站点是 CloudFront 分发，若某地线路被拦在「源设置 → 换网址」里填可用域名即可（脚本按
  `LumeSource.config.domain` 拼地址）。
