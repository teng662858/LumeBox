# LIBVIO（libvio.app 系列）：站点侧地域封锁，无法在本机做源

2026-11-01 · 结论：**没有产出可用的源**，原因是站点封锁，不是解析失败。

## 实测

| 域名 | 角色 | 结果 |
|---|---|---|
| `libvio.app` / `libviofabu.com` / `libfabu.com` / `libviogroup.github.io` | 发布页 | 200，正常 |
| `libvio.host` | 真实站 | **403 `Access denied by geographic restriction`** |
| `www.libvio.to` | 真实站 | **403 同上** |
| `libviobd.com` | 真实站 | **403 同上** |

换了桌面 UA、移动 UA、`Accept`、`Referer`、完整 `Sec-Fetch-*` 头，三个真实域名一律 403，
响应体只有一句 `Access denied by geographic restriction`。这是**按出口 IP 的地域封锁**，
不是反爬挑战（对比同批的 kkys03 是 850 + JS 挑战，过掉就能进）。

## 域名来源

发布页把域名做了 XOR 混淆（key `lv2025`），解出来是：

```
LIBVIO / libviogroup.github.io / libviofabu.com / libvio.app / libfabu.com
https://libvio.host / https://www.libvio.to / https://libviobd.com
help@libvio.com
```

发布页自己也写「投屏说明：点击夸克网盘资源链接…」——站点大量内容走网盘，网页端可播范围有限。

## 为什么没写源

按项目约定「不编造、不假装能直连」：

- 站点结构（列表/详情/播放路径、播放器类型、是否有签名）**在本机一条都取不到**，
  只靠猜测写出来的解析器无法验证，等于交付一个跑不通的源；
- 地域封锁不是可以靠脚本绕过的技术限制（那需要换出口网络），本源里也不做这种事。

`sources/video/libvio.js` 保留了一个**如实版**：域名/发布页/错误提示都写对，
一旦在放行的网络下使用就能按苹果CMS常规路径工作；被拦时明确抛
「站点按地区限制访问…不是源失效」，不会静默返回空列表。**该源没有进订阅**
（`lume-source-check` 在本机是 FAIL，这是预期结果）。
