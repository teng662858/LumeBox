# LIBVIO：域名已换代 + 浏览器校验，2.0.0 做成直连源

2026-11-01 · `sources/video/libvio.js`（`libvio_video` v2.0.0）

> 上一版记录写的是「站点地域封锁、做不了」。**那个结论不完整**：真实站换了域名，
> 而且挡住脚本的不是地域封锁，是 CDN 的浏览器校验。本轮重查后做成了。

## 1. 域名换代

旧记录里的三个域名全部停用，返回的是**停车页**（不是封锁页）：

| 域名 | 现状 |
|---|---|
| `libvio.host` / `www.libvio.to` / `libviobd.com` | 403 `Access denied by geographic restriction`（旧站，已下线） |
| `libvio.cc` / `libvio.me` / `www.libvio.host` / `libvio.io` | 200，但内容是 **「域名暂时停止使用通知 / Domain Suspended」** |
| **`www.libvio.io`** | **200，真实站** |

停车页里写着「备用线路 01 www.libvio.to / 03 libvio.io NEW」，并明确提示
「如果所在地区完全无法打开，请使用 VPN 访问」——所以旧域名的 403 确实有地域因素，
但**新域名 `www.libvio.io` 已经可以直接访问**。

## 2. 真正的拦路点：CDN 浏览器校验

```
HTTP/1.1 403 Forbidden
x-cdn-challenge: required
content-type: text/plain

403 Forbidden: browser verification required
```

curl / 普通 HTTP 客户端一律 403（换 UA、Referer、Sec-Fetch-* 都一样）。
**但在浏览器里打开，页面会自己过校验**，之后：

- 同源 `fetch` 直接 **200**：首页 40 KB、列表 16 KB、详情 22 KB、播放页 27 KB；
- 说明是「一次校验、会话复用」，不是每个请求都要重新验证。

按项目约定（`docs/2026-10-21_手机端源接口.md`「识别到验证页时返回 NEED_WEBVIEW_VERIFY，
验证码和登录仍由用户完成」），本源：

```js
throw new Error('NEED_WEBVIEW_VERIFY：LIBVIO 需要先完成站点的人机校验（HTTP 403 x-cdn-challenge）。'
  + '请在网页视图里打开 ' + base() + path + ' 完成校验，之后会自动重试。');
```

App 会拉起内置网页视图，**由用户本人**完成站点校验；拿到会话后自动重试同一次调用，
后续调用都带着走。**本源不伪造 UA/指纹、不逆向挑战算法、不绕过任何校验。**

## 4. 播放

播放页里 `var player_aaaa={...,"url":"https://v.vimsec.app/.../MobLand.S02E01.mp4","from":"vr2"}`
——**地址是明文**（`encrypt` 字段为 3 但 `url` 未加密），直接就是正片 mp4。

实测：
- `v.vimsec.app` 直链 → **206 `video/mp4`**，`content-range: bytes 0-1023/893901075`（893 MB）；
- 播放器 iframe（`/vid/plyr/vr2.php?url=...`）里 `<video>` → **readyState=4、duration=2934s、networkState=1**，即真的能播。

多线路全部保留（`<h3>` 线路名 + 各自分集列表）。

## 6. 限制

- **首次使用要在网页视图里过一次站点校验**（之后复用会话）；命令行/无网页视图环境无法自动通过。
- 站点另有**夸克/迅雷网盘线路**，不在线播放，本源不列。
- 站点没有排序控件，只有地区/年份筛选。
