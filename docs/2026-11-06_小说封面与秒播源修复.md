# 小说封面、列表加载与秒播源

## 行为变化

- 爱丽丝书屋 1.2.0：列表返回前不再逐本请求详情补图。列表中没有图片的条目返回详情定位页与 `coverHeaders.x-lume-image-page-selector`；新版 App 的封面队列按需读取指定图片、缓存实际图片字节。现成的首页封面继续直接加载。
- 第一版主 1.0.2：纯文字列表及搜索结果按站点已验证的书号路径补封面，统一 HTTPS 并带 Referer。原站缺图仍显示占位。
- 次元姬 1.0.1：推荐条目使用 resourceId/contentName，不再将 regionId/id/name 栏目容器误识别为书籍；排除活动横幅，保留真实封面请求头。
- 八叉书库 1.0.1：兼容 normal-image1 卡片，纯文字更新列表按需取详情封面；部分原站图片 HTTP 404，无法从源端恢复。
- 酷18 1.0.1：图片板块按需取帖子内容首图；文字板块不批量访问详情补图；正文无图的帖子保留占位。
- 西瓜书屋 1.0.1：补充列表懒加载图片提取和请求头。抽查原站三张封面均返回 HTTP 404，原图失效并非 App 解码失败。
- 月亮小说 1.0.1：封面占位与作者头像分开识别。原站新书列表 30 条都只有 cover-placeholder，无真实图片，不拿作者头像充当封面。
- 69书吧 1.0.1：正文解码 emsp/ensp/thinsp/nbsp、数字实体与一层被转义的空格实体，去掉段首 HTML 缩进符号并保留自然段。
- 秒播 1.0.0：站点 edge-ov12.00h.quest，发布页 mmss.pro；39 个分类、分类分页和关键词搜索路由；页面使用双层 Base64，封面是 Base64 后循环 XOR。`xor-base64` 在原生图片解码线程处理。播放使用站点网页播放器，未将 bkplayer 令牌假报为媒体直链。

## 验证

- 爱丽丝、第一版主、次元姬、八叉、酷18、西瓜、月亮及秒播五入口实站通过；69书吧正文通过真实 QuickJS 合成页面回归，未声称绕过 Cloudflare 完成全站实测。
- 8 个源各取两个分类，首条 ID 均不同，确认参数确实落到站点。
- 爱丽丝、第一版主、次元姬各抽查 3 张封面均为 200 且可解码；秒播 3 张密文封面还原为 JPEG；八叉样本中有原站 404，酷18部分帖子无图；西瓜样本原图 404。
- 原生测试覆盖慢详情不阻塞列表、定位封面缓存、跨域不携带页面授权、无图及非 HTTP 图片停止解析、数字/空格实体、推荐容器过滤、封面卡片布局和双层页面包装。
- 图片定位页及 xor-base64 需要安装本轮新版 App；只更新源无法让旧 App 获得新的宿主图片能力。iOS 编译和真机播放效果仍需安装新包验证。

## 发布

所有修改源同步到既有源仓库并重新生成订阅。用户随后确认源仓库保持私有，App 使用私有 GitHub 订阅；因此通过授权 GitHub Contents API 下载并核对脚本 SHA-256、清单版本。未恢复公开可见性，也不将已跳过的公共 CDN 工作流表述为刷新成功。远端已有的源删除操作合并保留，订阅同步移除失效引用。
