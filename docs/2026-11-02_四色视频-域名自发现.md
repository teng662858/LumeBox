# 2026-11-02 四色视频 1.1.0：换域名两次后做「域名自发现」

## 现象

App 里「四色视频」首页报：

```
首页加载失败 · 脚本错误: 已知域名都取不到页面（/index/home.html）
域名只剩进入页：https://www.zie2.com
站点 3 天换一次域名，请到「源设置 → 打开发布页」看最新地址
```

上一版（1.0.4）的四个域名 `z2g9w.top` / `x5p2n.top` / `u6k0m.top` / `zie2.com` 全部不可用：
前三个**整站只剩一张 4513 字节的「进入页」**（所有路径都回它，连 `/assets/js/*.js` 都是），
`zie2.com` 本机 TLS 仍然握手失败。

## 这一轮的真实域名

用站点家族自己的「跳转服务」挖出来的，不是猜的：

```
GET http://good.0827.la/?u=<b64 https://www.zie2.com>&p=<b64 /index/home.html>
→ 302 https://www.x3l6j.top
→ 302 https://www.q5h7m.top/enter/index.html
```

`www.y1c5w.top` 与 `www.q5h7m.top` 两台同内容：首页 75 016 B / 3 个板块 / 30 张卡，
`/juqing/lists.html` 20 条，`/search/…` JSON 10 条，play 页 `decodeString` 照旧，
m3u8 200（`s4.dt188.site` 与 `4sv.0827.la` 两台都 200）。

怎么找到跳转服务的：搜到跳板页 `af284.com`，它的 HTML 里就是这段 JS——

```js
var strU = window.atob("aHR0cDovL2dvb2QuMDgyNy5sYTo4MDgw") + "/?u=" + btoa(origin) + "&p=" + btoa(path);
```

`atob` 那段解出来是 `http://good.0827.la:8080`。实测 443/80 都能用；
**证书 2026-11 起已过期**（`certificate has expired`），所以源里用 http。

## 改动

### App：`reply.url` 回报最终地址（`lib/core/js/lume_js_engine.dart`）

HTTP 桥以前只回 `status/headers/body`，302 跟完之后脚本不知道该停在哪台主机，
只能靠页面形态猜「这是进入页」。现在：

- `_fetch()` 的返回值加 `'url': response.url`（`LumeHttpResponse.url` 本来就是跟随重定向后的最终地址）；
- `fetch` 垫片把它透出为 `response.url`，宿主没给就退回请求地址。

这是通用能力，所有源都能用：换域名的站点请求一次「会跳转的发布页/跳转服务」，
读 `response.url` 的 origin 就是当前域名。文档同步到 `docs/lumesource-guide.md`「网络」。

### 源：1.1.0（`sources/video/d9y1w.js`）

1. **域名**：`SITE` → `https://www.y1c5w.top`，`mirrors` → `y1c5w.top` / `q5h7m.top` / `zie2.com`。
2. **域名自发现**（`discoverHost()`，见脚本 〇·二）：已知域名全废时按种子
   `zie2.com` → `af284.com` 请求 `http://good.0827.la/?u=…&p=…`，读 `reply.url` 的 origin，
   再用 `hostWorks()` 探一次 `/index/home.html`（200 + `video-item` + 不是进入页），
   通过就 `rememberHost()` 缓存 12 小时；失败写 `discover.json` 退避 10 分钟，避免每次进首页多两跳。
3. **发布按钮换成跳转服务**：`settings.publishPage` 从「旧域的 /help/help.html」（打不开）改成
   `http://good.0827.la/?u=<b64 zie2.com>&p=…` —— 网页视图会一路跳到现在能用的域名，点「进入」就到首页。
4. 取页逻辑收敛成 `fetchFrom()`（单台取页 → `{ok|gate|error|fatal}`），`getText()` 最多两轮：
   已知主机一轮 → 自发现拿到新域名再一轮；错误信息提示改用新的「打开最新地址」按钮。
5. 注释与媒体 CDN 说明按 2026-11-02 复测更新（play 页这回给的是 `s4.dt188.site` 优先）。

## 验证

```
node tools/lume-source-check.mjs sources/video/d9y1w.js
```

五入口全绿：`home` 3 块 / `categories` 27 / `list` 20 条 `hasMore` /
`detail` 标题与封面 / `chapters` 2 条 / `content` → `4sv.0827.la/…/index.m3u8`
探活 `200 #EXTM3U` 32 918 B。分类、翻页、搜索另测：`juqing:麻豆传媒` 首条 `juqing-439026`、
`shipin:` 首条 `shipin-439052`、`page 2` 首条 `juqing-438873`、`关键词 麻豆` 21 条。

**自发现实测**：把副本的 `SITE`/`mirrors`/身份头全部换成死域（`z2g9w` / `x5p2n` / `u6k0m`）再跑，
请求链是 `3×进入页 → good.0827.la → q5h7m.top/index/home.html`，五入口依旧全绿，
`content()` 的 Referer 也跟着变成 `https://www.q5h7m.top/`。

`test/d9y1w_source_test.dart` 三个用例（AES/列表/搜索/双线路、进入页换镜像、跳转服务自发现），
`_RouteHttp` 增加 `urls` 覆盖来模拟 `reply.url`；`dart analyze` 无问题。

## 限制

- 自发现依赖站方的 `good.0827.la` 与两个种子（`zie2.com` 永久地址 / `af284.com` 跳板）。
  站方若把跳转服务也换掉，脚本就只能靠 `MIRRORS` + 手选域名；此时用「打开最新地址」按钮
  或邮件 `liumangtu@mail.com` 拿一次新域名，手填进镜像即可。
- 站点自己的 `*.top` 域名当种子会被跳转服务回 `code:1007`（只认跳板/永久地址），所以种子是写死的那两个。
- 详情页仍然没有简介与封面（这是站点本身的结构），封面/日期来自列表缓存。
