## 一、次元姬是怎么破的（Tabbit 真浏览器 + CDP 抓包）

前两轮卡在「`bookDetails?params=<密文>` 打开只落回首页外壳」。这次换路子：

1. **先用真浏览器看它到底渲染了什么**：Tabbit 打开首页，枚举链接，发现章节是**明文路由**
   `/chapter/{bookId}_{chapterId}.html`（35 个样本）。
2. **跑通 SSR**：用**桌面 UA** 请求 `/chapter/8476_2612521.html`，`__NEXT_DATA__` 里直接有
   `chapterContent`、`bookChapter`、`bookId`、`chapterId`、`recommendBookList`
   （手机 UA 只给空壳，这一点坑了很久）。
3. **摸清路由**：从加载的 chunk 列表里读出 Next 的页面目录——
   `/index`、`/tags`、`/tags/{tagId}`、`/book_detail/{bookId}`、`/chapter/{params}`、
   `/library/card/{params}`、`/rank/card/{params}`。除带 `params` 密文的两个（书库/榜单）外都能直接取。
4. **正文是密文**：`chapterContent.content` 形如 `behxnomMm8QAYsdjdRdU/XdXQ0ZDtA+cEc8cNotNQx2Ij6hqmBkuJP7Xn76OhokkBau5X8glvL4g`，
   每 80 字符换行，明显是 base64 密文。
5. **逆出算法**：`_app` 里有个函数 `N(e)`：
   ```js
   e = e.replace(/\n|\r/g, "");
   var t = s().enc.Utf8.parse(i.rk);
   return s().DES.decrypt(e, t, {mode: ECB, padding: Pkcs7}).toString(Utf8);
   ```
   `i` 是 `./config/index.ts` 模块，里面 `rk` 的 getter 返回 `l`：
   ```js
   l = "ZUreQN0Epkpxh3pooWOgixjTfPwumCTYWzYTQ7SMgDnqFLQ1s9tqpVhkGf02we89moQwhSQ07DVzc3LWupRgbVvm29aYeY7zyFN"
   ```
   DES 只用前 8 字节 → 密钥 **`ZUreQN0E`**，ECB + PKCS7。
6. **验证**：Node 用 `--openssl-legacy-provider` 跑 `des-ecb` 解出
   「　　感谢编辑清茶和各位书友一直以来的支持……」441 字，跟页面显示完全一致。

## 二、源里怎么落地

- **解密在源内完成**：App 沙箱没有 crypto 模块，所以 `sources/comic/ciyuanji.js` 里内联了一份
  纯 JS 的 DES（IP/FP/E/P/PC1/PC2/S 盒 + 16 轮 Feistel + base64 + PKCS7 去填充 + UTF-8 解码），
  跟着 `rk` 前 8 字节走。它和 CryptoJS 的 `DES.decrypt` 结果逐字一致（离线回放校验过一遍）。
- **必须桌面 UA**：`Mozilla/5.0 (Windows NT 10.0; Win64; x64) …Chrome/156…`，手机 UA 只回空壳。
- **站点结构**：
  - 首页 `/index` → `regionList` 7 个区块（板块名多是「PC站第一行」这类排版名，源里换成「轮播推荐/推荐 N」）
  - 分类 `/tags` → 67 个标签（带 bookNum）；`/tags/{tagId}` → 该标签下的书（实测 20 本）
  - 详情 `/book_detail/{id}` → `book`（书名/作者/字数/简介/一级二级分类/完结状态）+ `bookChapter.chapterList`
  - 正文 `/chapter/{bookId}_{cid}.html` → `chapterContent`（含 `isFee`/`isBuy`，付费章直接报错说明）
- **没做的**：`/library/card/{params}`、`/rank/card/{params}` 的 `params` 也是密文（AES，密钥是 config 里的 `u`），
  本源没去碰——分类用标签已经够用。
