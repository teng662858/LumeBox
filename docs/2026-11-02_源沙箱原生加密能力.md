# 2026-11-02 源沙箱原生加密能力（tools.aes / hmac / xor + 同步 atob）

日期：2026-11-02 · 改动：`lib/core/js/source_tools.dart`、`lib/core/js/source_bridge.dart`、
`tools/lume-source-check.mjs`、`sources/video/akmh.js`、`test/source_tools_test.dart`

## 一、起因

做 18ak 漫画源时，为了解 `AES-256-CBC` 的响应，在源里手写了约 10 KB 纯 JS 加密内核
（S 盒 / 密钥扩展 / MD5），跑一次要几十到上百毫秒。其实**宿主编译期就带着 pointycastle 与 crypto 包**，
`LumeSource.tools.*` 一直是原生实现，只是文档里没写全、写源时没用。

## 二、现在源里可以直接调的原生能力

| 调用 | 能力 | 备注 |
|---|---|---|
| `tools.digest(algorithm, text)` | md5 / sha1 / sha224 / sha256 / sha384 / sha512 | 返回小写 hex |
| `tools.aes({key, iv, data, mode, encrypt, padding})` | **CBC / ECB / CTR / GCM** | key/iv/data 都是 base64，返回 base64；GCM 解密输入是「密文 + 16 字节 tag」；`padding:'none'` 关 PKCS7 |
| `tools.hmac({algorithm, key, data})`（新增） | HMAC-MD5/SHA1/SHA256/SHA384/SHA512 | 返回 hex，key/data 可走 utf8 或 base64 |
| `tools.xor({key, data})`（新增） | 按密钥循环异或 | 输出 base64；KKAV 的 XOR2、618 的 `0x80` 混淆可直接换掉手写循环 |
| `tools.rsa({pem, data, encrypt})` | PKCS#1 v1.5，单块 | 已有 |
| `tools.inflate(data, raw)` | zlib / raw inflate | 已有 |
| `tools.base64Encode/Decode`、`tools.urlEncode/Decode` | 文本编解码 | 已有 |
| `atob` / `btoa`（新增） | **同步** latin1 base64 | 桥接垫片注入，和浏览器语义一致；做 key/iv 编码不用再自己拼表 |

仍然没有（这些是真限制，不是不想给）：Node 的 `Buffer` / `crypto`（只有猫源沙箱叠加）、
`TextEncoder/TextDecoder`、端口 / 进程 / `require`。单次调用 3–5 秒与指令上限依旧。

## 三、改动明细

1. `source_tools.dart`
   - `aes` 分支从「CBC/ECB」扩到 **CBC / ECB / CTR / GCM**；
     CTR 用 `CTRStreamCipher.processBytes`（长度任意，不填充），GCM 用 `GCMBlockCipher` + `AEADParameters`
     （tag 128 位，解密输入含 tag）。
   - 新增 `hmac`、`xor` 两个 operation。
2. `source_bridge.dart`
   - JS 侧 `LumeSource.tools` 补 `hmac()` / `xor()`；
   - 桥接模板里注入同步 `atob` / `btoa`（纯 JS、幂等，`if (typeof globalThis.atob !== 'function')`）。
3. `tools/lume-source-check.mjs`
   - harness 的 `tools.aes` 从「未实现」改成真实现（node:crypto 的 aes-*-cbc/ecb/ctr/gcm），
     并补 `hmac` / `xor` / `inflate`。**这很关键**：源一旦用了原生能力，离线校验工具必须能跑，
     否则 App 上能用、CI 上红。
4. `sources/video/akmh.js` v1.0.0 → **v1.1.0**
   - 删掉 10 KB 纯 JS 加密，签名改 `tools.digest('md5', …)`、解密改 `tools.aes(...)`、
     key/iv 用 `btoa`。源体积 20 736 → 10 452 字节，行为不变（五入口 + 播放探活全过）。

## 五、给写源的人的三条结论

1. **先查有没有原生**：摘要、AES、HMAC、XOR、RSA、inflate、base64 都别自己写；
   纯 JS 只在「原生没有 + 算法很怪」时才用（例如站点自定义的 XOR2 + FNV-1a 变体）。
2. **`tools.*` 是异步的**（返回 Promise），入口函数本来就在 `async` 里，直接 `await` 即可；
   `atob/btoa` 是同步的。
3. 用了原生能力之后，记得同步更新 `tools/lume-source-check.mjs` 的 harness，
   否则本地 `node tools/lume-source-check.mjs` 会报「未实现」而不是真跑。
