## 播放签名（逆向结果）

播放页每个分集有自己的 slug 和 dataid（`/play/ch4qhla8l`，`dataid=41045`）。前端用
`/static/wasm/nbmovie_wasm.js` 的 `build_play_url(dataid, slug, 清晰度, userlink)` 生成
`/video/play?p=&v=&q=&s=&t=&k=`。三个参数全部还原（wasm 反汇编 + 运行时 hook 校验）：

- **`s` = `HMAC-SHA256(key=slug, msg="<dataid>:<t>:<slug>")` 的前 32 个 hex 字符**
  - wasm 里是标准 HMAC 的 ipad/opad 两轮压缩；数据段的 `nbmovie2024secretkey` 只用于 `k`，不参与 `s`；
  - 改 `s` 任意一位 → `403 你没有权限`。
- **`t`** = 毫秒时间戳；与站点 `<meta id="nb-st">` 差毫秒级即可，不需要对齐站点时钟。
- **`k` = `base64(xor("nbmovie2024secretkey", userlink))`**，`userlink` 取播放页 `x-data` 里的值
  （游客也有，形如 `X1VUXENZ…`）；`k=0` 也能过（游客等价）。

video 沙箱没有 `crypto`/`Buffer`/`atob`，所以源里带了一份纯 JS 的 SHA-256 + HMAC + base64
（已与 Node `crypto` 对拍一致）。

## 清晰度与 VIP（不绕过）

| 清晰度 | 站点响应 | 本源处理 |
|---|---|---|
| 1080 | 200，直出 m3u8 | **使用** |
| 720 / 480 | `401 需要VIP会员才能观看，请先登录` | 不用，抛可读提示 |
| 4k | `403 4K清晰度仅支持客户端播放，Web端不支持` | 不用，抛可读提示 |

即：站点本身就把 1080p 开放给游客，本源只取这一档；**没有伪造 VIP，也没有绕付费墙**。

## 结构

- 全量片库 `/filter?page=N`（24 条/页，真分页，实测到第 228 页）
- 栏目 `/movie` `/tv` `/anime`（服务端单页；`?page=` 不换内容）
- 筛选 `/filter?classify=&types=&areas=&years=&tags=&sort_by=&order=desc`
- 搜索 `/search?q=`（首次可能空，源里会摸一次首页再重搜）
- 详情/播放 `/play/<slug>`

## 限制

- 720/480 需站点 VIP，4K 仅官方客户端；本源只提供 1080p。
- 栏目页（电影/剧集/动漫）站点只有一页，翻页请用「全部影片」。
- 综艺栏目站点本身为空。
- 与 4k影视（4kvms.org）同一套 CMS，内容高度重合，两条源可互为备份。
