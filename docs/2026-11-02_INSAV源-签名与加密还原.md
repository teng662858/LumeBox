# 2026-11-02 INSAV 源：从「暮色」App 到可用源

日期：2026-11-02 · 源：`sources/video/insav.js`（`insav_video` v1.0.0）
样本：「暮色」 App（`com.look.mbox` / avbox 1.0.1）的 `insav`（`ic_app_insav.png`）模块

## 一、三件必须先解决的事

### 1. API 主机不是网页域

App 的 `shared_prefs` 里只有 `flutter.insav = https://dcuj77.com/`，但那是 **React SPA 的网页域**：
`POST /api/*` 一律 **405**，`GET /api/*` 回落成 HTML。

真接口在另一个随机域（这一轮是 `pqtn95.com`）。定位方法（不需要证书、不需要 hook）：

```bash
# 模拟器关掉 Private DNS，把 53 劫持到宿主自己的 DNS 记录器
adb shell "settings put global private_dns_mode off"
adb shell "iptables -t nat -A OUTPUT -p udp --dport 53 -j DNAT --to-destination 10.0.2.2:5354"
node .tmp_probe/dns-proxy.mjs 5354 223.5.5.5     # 记录 QNAME 再转发

# 在 App 里点进 INSAV（首页图标 → 有码/无码/动漫/4K tab）
adb shell "input tap 974 1060"
# 捕获到：pqtn95.com
```

> 备注：Android 的 DNS 代理会把域名映射成 `198.18.0.x`，`/proc/net/tcp` 里看不出域名，
> tcpdump 抓 53 也只有 `198.18.x`；**劫持到宿主**才拿得到可读的 QNAME。

### 2. 请求体整体加密

参数先算签名，再整体 AES 后放进 `{"post-data": "..."}`：

```
key = "0XxdjmI55ZjjqQLO3nI7gGqrBP0Vz9jS"   (32 字节 → AES-256)
iv  = "RWf23muavY" + suffix                (10 + 6 = 16 字节)
      请求用 header 的 suffix（固定 "NWSdef"）；响应用响应体自带的 suffix
```

### 3. 签名：抄错一个字符就永远「签名错误」

```
encode_sign = md5( 参数按 key 排序拼 "k=v&" + "NRkw0g3iJLDvw5tJ5PuVt5276z0SOuyL" )
```

`sign_key` 中间是 **`5tJ5`**。我从压缩后的 bundle 里第一遍抄成了 `5t5P`，
所有变体（大小写 / base64 / 无尾 `&` / 拼接顺序…）全部回 `code:1001 签名错误`。

**怎么定位的**：用 Tabbit 打开 `https://pqtn95.com/`，在 `addInitScript` 里 hook
`XMLHttpRequest.open/send`，抓到页面自己发出的真实请求体，再用已知的 key/iv 解密——
拿到**真实的参数与真实 sign**：

```json
{"site":1,"device":2,"timestamp":1793634009066,"page":1,"limit":12,"type":1,
 "encode_sign":"68d26a44e0ec43c88009521be7b43714"}
```

然后拿这个 canon 串去和 bundle 里所有 32 字符常量做 md5 对照，一次就撞出正确 sign_key。

## 二、接口（全部 POST，body 是 post-data）

| 接口 | 参数 | 说明 |
|---|---|---|
| `video/indexLists` | `site, page, limit, type` | `type=1` 列表、`type=3` 免费放送 |
| `video/info` | **`vid`** | 参数名是 vid；传 `id`/`video_id` 都回「视频不存在」 |
| `video/getVideoUrl` | `vid` | **需要登录态**（游客 token 过期 → `code:2000 登录已失效`） |
| `tag/lists`、`actor/lists`、`banner/lists`、`config/lists` | — | 未使用 |

`site` 才是分区（不是 type）：

| site | 分区 | total（type=1） |
|---|---|---|
| 1 | 有码（www） | 60 |
| 2 | 无码（wuma） | 60 |
| 3 | 动漫（dm） | 20 |
| 4 | 4K | 20 |
| — | 免费放送（type=3） | 15 |

bundle 里对应的导航表：`[{有码区,www},{无码区,wuma},{动漫区,dm},{4k区,4k}]`。

## 三、封面

条目里的 `thumb` 是相对路径（`/ms/syms/…/xxx_ver.jpg`），在 `pqtn95.com` 上 404。
真图在图片 CDN：`https://yik.yanyunhome.com` + 同一路径，实测 **200 image/jpeg 51927 B**。
（`panorama` 字段直接就是完整 URL，可直接用。）

## 四、播放：需要登录，所以走网页

`video/getVideoUrl` 对未登录会话返回 `code:2000 登录已失效，请重新登录`；
暮色 prefs 里的 `token_insav`（`0bd7ef19…`）也已过期，device=1/2、header/body 多种传法都试过。
注册接口要 username/password/captcha，不适合自动。

所以 `content()` 返回 **webplayer**：`https://pqtn95.com/video/info?vid=<id>`，
由站内网页播放器播。要原生播放，得先补一套登录（游客或账号）。

## 六、可复用的经验

1. **先分辨「网页域」和「接口域」**：这类站的 prefs 只存网页域，接口域靠 DNS 劫持抓最省事。
2. **签名抄错是静默失败**：报错永远是「签名错误」。拿真实请求的明文反查常量，比猜算法快得多。
3. **参数名要照抄**：`vid` 不是 `id`，这类差异不会在错误信息里体现（只会说「视频不存在」）。
4. **能登录才考虑原生播放**：否则 webplayer 是诚实且可用的降级。
