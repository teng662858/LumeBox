# PY 源播放链路排查与橘汁 JS 备用源

本轮针对用户提供的五个 PY 文件及诊断包检查播放链路。诊断 App 为 1.0.314，当前选择 Aether。问题包含源站无效地址、实际媒体封装、图片包装的 TS 分片和缓存响应处理，不能归为一个「Python 不支持」。已修宿主与播放器，并新增免注册的橘汁 JS 源；山楂和红果的抽样播放仍受接口返回异常影响。Windows 上的验证不能替代安装新版后的 iPhone 解码验证。

## 范围与输入

- 授权依据：用户明确要求排查 LumeBox 与五个源，必要时转为 JS。只执行正常分类、详情、选集、取流及有界媒体探测。
- 本机 case：`work/python-source-global-audit/scope.md`、`timeline.md`，原始网络记录仅留本机，不进入 Git。
- 原始 PY 文件保持不变；未发布文件内的共享账号、密码、历史记录接口或自动更新代码。
- 报告类型为协议互操作分析，`flavor=null`，不涉及安全漏洞或 ATT&CK 结论。
- 诊断 ZIP SHA-256：`bfe3cdba0b7eb22bf41fdc2bdcf09e199bf3722802554fb40e901f6ad4d0d9d1`。

## 调用路径与变更

P-001（`path_type=callflow`）：PY/JS 取流 → 校验有效地址（E-003 / F-008）→ 按字节识别媒体（E-003 / F-001）→ HLS 重写与已确认 PNG/TS 剥头（E-005 / F-006）→ Apple HEVC 按需重封装 → 当前内核加载 → 封装错误切 MPV（E-001 / F-003）。残余风险是失效签名、服务端拒绝、网络超时和实机解码差异。

P-002（`path_type=callflow`）：橘汁会话公钥 → 宿主 RSA/AES → protobuf 二进制 POST（F-004）→ 分类/列表/完整选集 → 原站取流（F-005）。只采用脚本内的公共协议常量，不复制账号、登录或共享历史接口。

Python 宿主还保留有限的源内「播放失败 / 解析失败」输出，用于空播放地址的可读错误；过滤 URL 和敏感字段，避免反复只看到笼统的「未返回播放地址」。检查工具增加二进制请求、RSA 和 MKV/DASH 签名支持；指定只测 list 时，不再因未请求 chapters 而误报失败。
