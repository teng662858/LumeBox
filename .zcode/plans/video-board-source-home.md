# Lume Box · 视频板块首页 = 当前图源的内容展示页

来源：用户反馈——图源脚本跑通、条目能列出来之后，希望「把这个视频网站的展示页
放到视频版块首页」，而不是藏在图源管理的「浏览」里。

## 一、结构变化

视频板块从「一个播放器页面」变成与小说 / 漫画同一套页签外壳的**两页签板块**：

| 页签 | 内容 | 说明 |
|---|---|---|
| **浏览**（首页） | 图源条（当前图源，可切换）+ 分类 chips + 搜索 + 条目列表 | 复用板块图源浏览面板（`SourceBrowsePane`），与 `SourceHomePage` 同一份实现 |
| **播放** | 播放器本体（URL 输入、控制栏、HUD、齿轮、画中画、内核切换） | 原有 Phase1 能力一行未改，只是从「整页」变成「页签」 |

- 页签条与内容区抽成 `BoardTabs`（`features/shell/board_tabs.dart`）：小说 / 漫画的
  「书架 / 探索」与视频的「浏览 / 播放」共用同一套排布与视觉；
- 浏览面板 `SourceBrowsePane` 从 `SourceHomePage` 里拆出（面板 + 宿主页两分）：
  面板负责「解析当前图源 → 图源条 + 浏览面」，页面骨架（AppBar / 右上角入口）
  由宿主给。`SourceHomePage` 保留为薄壳（图源条里的「图源管理」入口 + 返回后自动
  重解析），视频板块把面板放进自己的首页；
- 浏览器条目点击加了回调（`BrowseView.onItemTap`）：宿主不传就是通用口径（进详情
  页），视频板块传自己的「点条目就起播」。

## 二、点条目 → 起播（视频板块）

`SourcePlayback`（`features/video/source_playback.dart`）先判「条目自带地址」：

| 情形 | 行为 |
|---|---|
| 条目 id 是地址（视频类脚本常见的 `{title, url}`，`url` 会落到 id 上） | **直接起播**，不问详情 / 章节 |
| 条目 id 不是地址（作品 id） | 取剧集：`chapters(id)` → 只有一集不弹面板、多集弹「选择剧集」→ `content(id, chapterId)` 的视频地址 → 起播 |
| 取不到地址（脚本没实现剧集 / 内容不是视频） | 如实提示缺哪个函数或哪一步不对，不静默失败 |

- 地址判定是纯函数：协议白名单（http/https/file/rtmp/rtmps/rtsp/udp/tcp）+ 绝对路径
  （`/a.mp4`、`D:\a.mp4`）按本地文件处理；**纯 id 不认**——否则「脚本缺方法」会被
  误报成「文件不存在」；
- 起播后自动切到「播放」页签，并把地址回填到播放器的地址栏（手动重开同一地址可用）。

## 三、边界与未做

- 从图源管理页的「浏览」（通用浏览页）点条目仍进详情页——那是管理侧的通用查看口径；
  「点开就播」是视频板块首页的行为，两者不混；
- 视频源的「作品 → 剧集」链路依赖脚本实现 `getDetail/getChapters/getContent`；只给
  列表（`getList` 带 url）的脚本走直接起播这条路；
- 播放历史 / 追剧日历、播放器内联在列表上方的小窗播放都未做（Phase3 预留）。
