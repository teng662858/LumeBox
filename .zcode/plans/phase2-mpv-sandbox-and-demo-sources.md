## 一、MPV 切换：从「点不动」到「一定有出口」

### 现象与定位

用户报的现象有两条，其实是同一个状态：**切到 MPV 后 `_player` 停在了 null**。

- 「视频板块转圈」= 播放页 `_player == null` 时只画了一个 `CircularProgressIndicator`；
- 「右上角播放器设置消失」= 那**整条控制栏**（含齿轮、地址栏、弹幕开关）都在
  `player != null` 的分支里 —— 播放器没就绪，连「改设置、换内核、重贴地址」
  这些出路一起被收走了，用户只剩重启应用。

能停在 null 的代码路径有三条（都在本轮收口）：

1. **内核起不来**：`launch` 返回 null（连兜底 AVPlayer 也失败）时只
   `setState(_player = null)` 就返回，页面没有任何说明；
2. **重建中途抛错**：例如设置库写失败会把「已建好的播放器」丢掉，
   实例泄漏、页面永远等待；
3. **原生初始化是同步阻塞调用**：Dart 无法抢占式中断它，等待期间界面只有转圈，
   没有任何交代。

### 改动（`lib/features/video/video_page.dart`）

- 播放页 =「画面区四态 + 控制栏常在」：设置库不可用 / 准备失败 / 正在准备 / 就绪；
  控制栏在任何状态下都渲染，**齿轮与地址栏始终可用**；
- 准备态：`正在准备 <内核> 播放器…` + 说明（MPV 首次要装载原生库）+「切回 AVPlayer」；
- 失败态：可读原因 +「重试」+「切回 AVPlayer」；
- `_rebuildPlayer` 异常安全：任何路径都收敛到终态；建出来但没采用的实例一律
  `dispose`；落库失败只记日志并继续接线；`_rebuildSeq` 保证连续切换时只有最后
  一次结果算数、过期实例被释放；
- 重试走 `_rebuildPlayer` 而不是 `_applySettings`：失败那次不改配置，
  设置里可能已经是同一个内核，走 `_applySettings` 会因为「内核没变」而不重建
  （点了重试却原地不动——这是本轮自查时抓到的一个真 bug）；
- 「播放器设置」图标由 `Icons.tune` 换成 `Icons.settings_outlined`
  （原先与「弹幕设置」一模一样，两处都难认）。

### 熔断重试入口

`PlayerKernelPicker` 支持给「失败但可重试」的内核挂一个「重试」按钮；
`player_settings_page` 与全局设置的逃生入口（`PlayerKernelSection`）都接上，
点击先 `clearMpvInitFailure()` 再重评估可用性——**只恢复可选，不自动切换**。

### 验证

`test/player_switch_recovery_test.dart`（7 例，全部用注入的假工厂驱动页面状态机）：
内核起不来 → 失败卡 + 重试 + 切回 + 齿轮与地址栏仍在（传输键禁用）；
设置库不可用 → 同样留着重试与设置入口；MPV 抛错 → 自动回退 AVPlayer 且有画面；
失败态点重试 → 真的重建一次并解除熔断；设置页里熔断可重试恢复可选；
接续失败（load 抛错）不空转；连续切换 → 过期实例被释放、以最后一次选择为准。

### 边界（如实记录）

原生库装载与创建是**同步 FFI 调用**：若底层真的在装载阶段挂住，那一小段时间
UI 线程仍会被占住（这是 FFI 的固有性质，不是本层能绕开的，代码里也一直这么写着）。
本轮保证的是「一旦拿到结论就收敛到终态」；若真机上仍出现整屏卡住，
运行日志里会有 `[player] <内核> 初始化耗时 … 超预算` 或 `初始化失败：本次运行内
不再提供` 这样的记录，可据此判断是装载阶段挂住还是别的环节。

## 二、JS 沙箱安全复测：三条性质放回生产路径

既有用例（`deadloop_timeout_test` / `context_isolation_test` /
`section_category_test` / `malicious_script_test`）分别在沙箱 API 与导入路径上
逐条验证；本轮新增 `test/js_sandbox/security_audit_test.dart`（5 例），
把它们放回**同一条生产链路**（`LumeJsEngine` + 真实 `LumeSourceHost`，
真 QuickJS），并补上此前没覆盖的攻击面：

| 性质 | 新增验证 | 结论 |
|---|---|---|
| 死循环超时销毁 | **定时器内死循环**：脚本把卡死排到操作结束之后（`setTimeout(() => { for(;;){} })`），而不是在调用里卡死 | 冻结 **359ms** 后被回收（策略上限 4s，指令计数先到），上下文判废并留日志；同一引擎下一次调用重建上下文、自动重放脚本后可用 |
| 上下文隔离 | **同一 id 落在两个板块**：两个引擎各持各的上下文与沙盒存储 | 同名全局变量与同名存储路径互不可见、反向写入不互相覆盖；沙箱身份自带板块前缀 |
| 板块隔离校验 | **JS 侧伪造存储身份**：脚本把别人的沙箱身份写进调用参数 | 身份由 Dart 侧盖章，JS 传什么都不算数——读到的仍是自己的存储；身份不符的宿主调用在入口被拒且不触达网络与存储 |

另有一条「一个来源的异步卡死不牵连另一板块来源」的对照。

**结论**：文档要求的「超时销毁 / 独立 JSContext / 板块隔离」在生产路径上成立，
本轮**未发现需要修复的漏洞**；证据（冻结时长、判废日志、重建代数）都留在用例里。

## 三、示例源脚本：三份可真跑的模板 + 导入到展示的端到端验证

新增三份示例源（`assets/test_sources/`，测试从磁盘读、不进 App 资源包）：

| 脚本 | 板块 | 演示的能力 |
|---|---|---|
| `demo_novel_source.js` | 小说 | JSON 接口 + 分页 + 搜索 + **沙盒存储缓存**（`LumeSource.fs`）+ 正文返回文本 |
| `demo_comic_source.js` | 漫画 | **HTML 列表页正则解析**（沙箱里没有 DOM）+ 相对地址补全 + 正文返回图片列表 |
| `demo_video_source.js` | 视频 | JSON 接口 + 独立搜索接口 + 选集（线路）+ 播放直链与**防盗链请求头** |

三份都带头部元信息与运行时 `category`（板块自报），并把「非 200」「坏 JSON」
「该章没有内容」翻译成可读错误；`BASE_URL` 在脚本顶部，用户改成自己的测试站点即可。

**端到端验证**（`test/js_sandbox/demo_sources_test.dart`，8 例）：测试现场用
`HttpServer` 起一个本机示例站点（接口形状与脚本文档一致），把 `BASE_URL` 替换成
它，然后走**真实链路**：

```
SourceRegistry 导入 → 组合根打开真实引擎 → JS 沙箱调用 →
宿主网络层 HTTP → 示例站点 → 正则 / JSON 解析 → JsDataSource 契约 → 业务页渲染
```

覆盖：三份脚本的分类 / 列表 / 分页 / 搜索 / 详情 / 章节 / 正文（三种内容形态）
契约断言；沙盒存储缓存第二次不再打站点；站点 404 时抛出可读原因；
小说源导入漫画板块被拒（对照：导入小说板块成功）；
三个板块的**板块首页真实渲染**（源条 + 分类 + 列表条目 + 切分类后重新解析）。

两个测试装置上的坑（已解决并注释在代码里）：
`flutter_test` 会把进程内的 `HttpClient` 换成「一律 400」的替身（要显式摘掉才能连
本机站点）；真实 HTTP 的连接池在假时钟里会留下 keep-alive 空转定时器
（收尾时 `LumeNet.closeSharedClientForTesting()` 收掉，该入口是本轮新增的
`@visibleForTesting` 方法）。
