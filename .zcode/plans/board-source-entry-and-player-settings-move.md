# Lume Box · 板块页右上角入口修复（图源管理）+ 播放器设置迁移 + 图源操作补齐

来源：用户反馈的 UI 路由 Bug——视频页右上角点进去是「播放器设置」，看不到任何
图源；导入成功的图源因此没有任何入口可用（源在库里，但没法启用）。

## 一、问题与修复

| 现象 | 根因 | 修复 |
|---|---|---|
| 视频页右上角是三横线（`Icons.tune`）＝播放器设置，点进去没有图源列表 | 视频板块把「播放器设置」放在了 AppBar，而**四个板块本来就没有图源管理入口** | 四个板块统一为「**图源管理**」+「+」；播放器设置搬走（见下） |
| 小说 / 漫画板块同样没有图源管理入口 | 同上（业务页 `SourceHomePage` 里才有 `Icons.tune` 入口，板块页没接） | 小说 / 漫画 / 视频三块都接上 `SourceSectionPage(section: …)` |
| 猫源板块 | 该板块页本身就是图源管理页 | 标题统一为「猫源 · 图源管理」，口径与其他板块一致 |

**播放器设置迁移**（用户给的两种方案都落了一条）：
- 视频板块的**播放控制栏**加齿轮 `⚙️`（与文档草图 2 的 `[⚙️]` 一致）——在播放上下文里改参数最顺手；
- **全局设置**（底部 Tab「设置」）新增「播放器设置」入口（内核 / 倍速 / 字幕，写视频板块自己的库）；
- 全局设置里上一轮的「播放器内核 · 故障逃生入口」内嵌区块**保留不动**（逃生场景点得最少），文案补一句指向完整设置。

## 二、图源管理页补齐（任务书列的「启用 / 禁用 / 编辑 / 删除 / 导出」）

| 能力 | 落点 |
|---|---|
| 启用 / 禁用 | 行内 `Switch`（原有） |
| 编辑（重命名） | 行内「更多」→ 重命名；`SourceManager.rename` → `SourceRegistry.rename`（**只改库里的展示名**，脚本、版本、启停状态与运行时都不动；脚本里声明的 `LumeSource.name` 保持原样，更新脚本也不会被覆盖） |
| 导出 | 行内「更多」→ 导出脚本：弹窗展示脚本全文 + 一键复制（`SourceManager.exportScript` → `SourceRegistry.scriptOf`） |
| 删除 | 行内「更多」→ 删除（保留二次确认） |
| 浏览 | 行内「更多」→ 浏览（停用时不可点） |

行内控件从「Switch + 浏览 + 删除」三个并排收成「Switch + 更多」——手机窄屏不会
把按钮挤成一片，四项操作语义也更清楚。

口径说明：这里的「编辑」= **重命名**（文档「图源导入/导出模块规范」里的
「图源重命名」）；**脚本内容编辑器**不在本轮范围（文档把它列在图源可视化编辑器
一项里）。

## 三、测试与边界

- 新增 `test/board_source_entry_test.dart`（4 例）：小说 / 漫画 / 视频三块右上角
  都有「图源管理」且点进去是**本板块**的管理页（标题「板块 · 图源管理」）；视频页
  AppBar **不再有**播放器设置；管理页能看到图源、能启停、四项操作都在「更多」里；
- `test/source_manager_test.dart` 新增 3 例（重命名成功 / 空名不提交 / 导出并复制，
  含剪贴板往返），既有用例按「更多」菜单口径更新；
- `test/settings_page_test.dart`：断言全局设置里的「播放器设置」入口可达完整设置页；
- 可测性：`NovelPage` / `ComicPage` 增加 `runtimeAvailable` 注入点（与设置页同一
  口径），非 iOS 平台也能驱动完整板块交互；生产行为不变（为空时仍取平台判定，
  Android / Windows 依旧只有骨架）。

验证：`flutter analyze` 零告警；全量 **431 例**通过。
