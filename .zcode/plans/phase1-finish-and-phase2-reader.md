# Lume Box · Phase1 收尾 + Phase2 补齐（PiP / 连播 / 备份恢复 / 缓存策略 / 阅读增强）

来源：一次批量交付，覆盖用户点名的五项——图源总管理批量备份恢复、缓存容量与过期
策略、视频跨集自动连播、iOS 原生 PiP、Phase2 阅读体系补齐。

## 一、iOS 原生 PiP（`ios/Runner/PipController.swift`，新增）

Dart 侧的方法通道契约（`lumebox/pip` + `lumebox/pip/events`）早就就绪，缺的是 Swift
实现。本次补齐：

- 用 `AVPictureInPictureController(contentSource:)` 绑定 `AVSampleBufferDisplayLayer`
  ——这是 iOS 15+ 给**非 AVPlayer 内核**（本项目的 MPV / MDK）准备的官方通路；
- AVPlayer 内核不走这里（它自带 `playerLayer` 通路，由 video_player 插件在原生侧处理）；
- `isSupported` 三条件：系统 ≥ iOS 15 + 设备支持 + **内容源已就绪**。第三条是关键：
  帧转发没接上时说「支持」，按钮会亮着但点了没反应；
- `start` 在内容源缺失时**如实报错**（`noContentSource` + 可读原因），不假装成功；
- 事件（entered / exited / restored / failed）与播放控制委托（播放 / 暂停 / 进度条 /
  跳转）都接好，接上帧转发即可生效。

Dart 侧配套：`PipException` 把原生的 `code` / `message` 带到界面——一句「画中画失败」
帮不了用户，要说清是系统版本、设备能力还是内容源未就绪。异常类放在 `pip.dart`
（`pip_channel.dart` 依赖它，反过来会成环）。

新 Swift 文件已登记进 `project.pbxproj`（否则不参与编译）。

## 二、视频跨集自动连播（`video_page.dart`）

- 播完（位置 ≥ 时长 − 1 秒）自动取下一集并起播；**时长未知时一律不连播**（宁可不跳，
  也不半途跳走）；
- 只在「从图源条目起播」时连播：手动贴地址没有剧集列表，自然不连；
- 控制栏新增开关（`skip_next` 图标，默认开），关掉即不跳；
- 防重入锁 `_advancing`：播完的多次快照回调只触发一次连播；
- 取不到下一集地址时**安静停下**，不弹提示打扰（用户没要求跳集）。

## 三、图源批量备份 / 恢复（`core/source/source_backup.dart`，新增）

文档第 4 条最后一项。格式：`{format: 'lume.sources', version, createdAt, sections}`。

三条纪律：
- **Cookie 绝不进备份**：UA / 代理属于用户配置随备份走，但 Cookie 是登录凭据，
  导出文件可能被分享，带上等于泄露账号（恢复时该字段留空，有专门用例钉住）；
- **恢复走与导入完全相同的校验路径**（脚本载入 → 元信息 → 落库），因此坏脚本进不来；
- **板块隔离**：备份里板块 id 非法、或平台无运行时，该板块整批跳过，不硬写错板块。

恢复会写回启停状态与网络覆盖（UA / 代理），并区分「新增 / 覆盖」计数。
UI 在总管理页：备份（弹窗展示 + 一键复制）、恢复（粘贴 + 从剪贴板读取 + 二次确认）。

## 四、缓存容量上限与过期策略（`features/settings/section_cache.dart`）

文档要求「各板块过期时间、最大容量、缓存策略独立配置」。

- `SectionCachePolicy{maxBytes, maxAgeDays}`，**0 = 不限制**（不配置就不动用户缓存）；
- `prune`：先删过期文件（超 `maxAgeDays` 未访问），再按**最久未访问先删**（LRU）
  回收直到降到容量上限以下；
- 访问时间取 `accessed` 与 `modified` 里较晚者——部分平台不更新 accessed，缓存场景
  下写入即访问，两者等价；
- **只碰可清理目录**：`cache/` 与 `reading_cache/images`；用户保存的图片
  （`reading_cache/exports`）绝不在范围内（有专门用例，用「上限 1 字节 + 1 天过期」
  的极端策略验证它仍存活）；
- 策略**按板块存**（各板块自己的阅读库 `reading_setting` 表），不是一份全局配置；
- UI：缓存页每行显示策略摘要，点开档位化配置（容量 0/50/100/200/500/1024 MB、
  过期 0/3/7/15/30 天），保存即按新策略修剪一次。

## 五、Phase2 阅读体系补齐

| 能力 | 落点 |
|---|---|
| **小说书签**（新增 `novel_bookmarks.dart`） | 存**字符偏移**而非页码——页码随字号 / 行距 / 视口变化，偏移不会，换排版后书签仍落在同一句话上。顶部工具栏书签按钮（有则实心、无则空心），书签面板可跳转 / 删除；按作品存（`novel.bookmarks.<itemId>`） |
| **章节内查找** | 书签面板顶部输入框，命中计数 `3/12` + 上下跳转；无结果如实说「无结果」 |
| **自动翻页** | 面板开关 + 间隔档位（5/10/15/20/30/60 秒）；到章尾自动进下一章，最后一章停下并关掉定时器（不空转）；间隔记住 |
| **漫画图片分享** | 长按图片改为选择面板：保存图片 / 复制图片地址。**刻意不引入分享插件**——复制地址粘到任意 App 都能用，不为一个分享按钮加原生依赖 |

## 七、边界与未做

- **PiP 帧转发**：内核把解码帧交给 `AVSampleBufferDisplayLayer` 这一步未接（MPV 侧
  需要原生帧回调），因此真机上画中画按钮会如实报「内容源未就绪」；控制器生命周期、
  通道契约与错误口径都已就位；
- **分享**：只做「保存 / 复制地址」，未接系统分享面板（需原生依赖）；
- 缓存策略未做后台自动执行（只在保存策略与进缓存页时修剪）；
- 备份未含阅读进度与书架（文档只要求图源备份；恢复阅读数据属另一件事）。
