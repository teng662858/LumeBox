# Lume Box · 订阅 `.js.md5` 约定：导入时取实体脚本并校验

来源：真机实测反馈。用户把 `https://9280.kstore.vip/cat/index.js.md5` 填进
「猫源 → 右上角 + → 订阅链接」，界面报「订阅里没有可导入的图源脚本」。

## 一、问题

`.js.md5` 是猫源生态的既有约定：**清单文件里放的是脚本的 MD5 校验值（32 位
十六进制），脚本实体在去掉 `.md5` 后缀的同名地址上**。原始实现把清单正文当
「脚本或地址清单」判断，正文既不是脚本也不含地址，于是判定为「没有可导入的
图源脚本」。

实测该订阅：清单 `6c7379bc24a23ec5b923ecf6f9c9d331`，`index.js` 6,487,143
字节，MD5 与清单一致——约定成立，是实现漏了这一形态。

## 二、改动

| 落点 | 内容 |
|---|---|
| `lib/core/util/md5.dart`（新增） | 纯 Dart 的 MD5（RFC 1321）。**不引依赖**：算法固定且短，测试对着标准向量（空串 / `abc` / 中文 / 55·56·64·65 字节边界）逐个核对 |
| `lib/features/source/add_source_button.dart` | 订阅拉取结果从「纯文本」改为「字节 + 文本」（[`SourceFetchResult`]）：校验必须用原始字节，不能拿解码后的字符串算。`_scriptsAt` 支持三种形态：① 正文是脚本 → 直接收下；② 正文是 MD5 校验值 → 去掉 `.md5` 后缀取实体、核对 MD5 后收下；③ 正文是「一行一个地址」的清单 → 逐个再拉（清单里的地址同样支持 `.md5`）。用 `visited` 集合挡住互相引用的清单，避免导入卡死 |
| 弹窗文案 | 订阅页签说明补上 `.js.md5` 的处理口径 |
| 失败口径 | MD5 不一致时明确报「MD5 校验不一致（清单 X，实际 Y）」，而不是把半截 / 被改写的脚本导进去 |

## 三、验证

- `test/md5_test.dart`（4 例）：标准向量、跨块边界、`parseHex` 形态
  （大小写归一 / 允许首尾空白 / 长度不足拒绝）；
- `test/add_source_button_test.dart` 新增 4 例：`.js.md5` 取实体并校验通过、
  MD5 不一致拒绝导入、清单里嵌套 `.js.md5` 也按约定解析、清单互相引用不死循环；
- 临时真机联通核对（不提交）：对真实订阅执行「清单 → 去后缀取实体 → 校验」，
  校验一致（6,487,143 字节）。

## 四、与本脚本的关系

该订阅**能被正确导入的前提**是「校验通过 + 脚本能被沙箱载入」。本脚本是
**服务型猫源**（`createServer` / `.listen` / 导出 `{start, stop}`），按架构文档
属不支持范围，因此导入的最终结果会是可读的失败提示（原因见「设置 → 运行日志」），
属于设计口径而非缺陷。详见 `cat-node-polyfill-expansion.md` 第四节。
