# Lume Box · 图源「测试连通性」+「更新订阅源」

来源：文档 Phase1「图源管理 UI 增加：每个板块独立图源管理页：添加本地JS文件、添加
远程订阅链接、图源开关、删除图源、**测试图源**」；第 4 条「图源总管理支持**批量
测试所有图源**、**批量刷新全部订阅源**」。

## 一、测试连通性

### 端口与实现

`SourceManager` 新增 `testConnectivity(sourceId)`，返回三态而非两态
（`SourceTestResult` / `SourceTestStatus`）：

| 结论 | 含义 | 为什么要单独一态 |
|---|---|---|
| `ok` 可用 | 首屏取到了条目 | 附条目数、分类数、耗时 |
| `empty` 无内容 | **脚本能跑，但首屏为空** | 多半是图源改版；与「脚本报错」的处理方式完全不同 |
| `failed` 不可用 | 打不开（脚本载入失败 / 网络异常 / 平台无运行时） | 带可读原因 |

实现走的是与浏览**完全相同**的数据源接口（`open` → `categories` → `list`），
因此「测试通过」等价于「浏览能出内容」；分类失败不算致命（拿不到分类就当图源
没有分类，与浏览面同一口径）。

**只读**：不动当前图源、不进页面、不改库——有专门用例钉住这一条。

### UI

- 图源管理页：每行「更多 → 测试连通性」；结论同时落在**列表行上**（可用 / 无内容 /
  不可用），不只弹 Toast——用户往往要连着看好几个源，弹窗一过就没了；
- 图源管理页右上角「批量测试连通性」：**只测已启用的源**（停用的测了只会报
  「已停用」），逐个串行（网络层有并发限制，但测试会真实打目标站，串行更稳、
  进度可见），结束给汇总「可用 N · 无内容 N · 不可用 N」；
- 图源总管理页：同样提供批量测试，**跨四个板块**逐板块逐源。

## 二、更新订阅源

### 前置：记下订阅来源

库 schema 升到 **v4**：`source` 表加 `origin_url` 列（订阅导入时写入，本地导入留空；
迁移容忍列已存在）。`SourceRecord.isSubscribed` / `SourceDescriptor.subscribed`
据此判断。

导入链路把来源地址一路带到底：弹窗返回 `_ImportPayload`（脚本清单 + 来源地址）
→ `importScript(script, originUrl:)` → `SourceRegistry.import(script, originUrl:)`
→ `setSourceOrigin`。清单类订阅记的是**用户填的那个地址**（而不是展开后的实体
地址），这样下次更新仍走同一套 `.js.md5` 校验。

顺带把订阅解析从 UI 抽到 core：`SourceSubscription`（`lib/core/net/source_subscription.dart`）
统一处理三种形态（`.js.md5` 校验清单 / 正文即脚本 / 地址清单），**导入与更新共用
同一份实现**——更新时同样会校验 MD5，不会因为走另一条路径而放松。

### 更新

`SourceManager.updateFromSubscription(sourceId)` → `SourceUpdateResult`（四态）：

| 结论 | 触发 |
|---|---|
| `updated` | 拉到新脚本并覆盖成功 |
| `unchanged` | 拉到的脚本与现有内容一致（如实说「已是最新」，不谎报更新） |
| `skipped` | 本地导入没有订阅地址 / 平台无运行时 |
| `failed` | 网络异常、MD5 校验不符、脚本不合法 |

三条纪律：
- **覆盖走与导入完全相同的校验路径**（脚本载入 → 元信息 → 落库），因此更新后拿到
  的必然是一份能跑、id 合法的脚本；
- **新脚本换了 id 视为失败**：如实报「订阅里的脚本换了图源 id」，不静默覆盖
  （否则用户以为更新成功、实际多出一个源）；
- **更新不动用户配置**：来源地址与网络覆盖（UA / Cookie / 代理）属于用户设置，
  不随脚本内容丢失——有真实引擎用例钉住。

### UI

- 图源行内标「订阅」；「更多 → 更新订阅源」只对订阅源可用（本地源置灰）；
- 图源管理页右上角「刷新全部订阅源」（只在有订阅源时出现）：逐个更新，汇总
  「更新 N · 已最新 N · 失败 N」。

## 三、边界与未做

- 批量操作为**串行**：测试与刷新都会真实打目标站，串行 + 网络层并发限制一起构成
  双重保护；未做「并发批量测试」（那是文档第六条的并发额度该管的事，不该在 UI 层
  自己开并发）；
- 未做：更新后自动测试连通性（用户可手动点）、订阅源的「有新版本」提示、
  图源总管理的批量备份 / 恢复（仍待办）。
