## 四、FFI 内存回收表现（用户特别要求）

`test/js_sandbox/ffi_memory_observation_test.dart`（只观测、不做通过判定，
因为已知泄漏本轮不修）。

### 4.1 正常创建 / 销毁 50 轮

```
在册 JSContext    : 0 → 0        （差值 0 ✅）
JSRuntime 放弃回收 : 3 → 53       （差值 50）
进程 RSS          : 132MB → 141MB （差值 9MB）
每轮泄漏 runtime   : 1.00 个
```

### 4.2 失控销毁重建 20 轮（最坏路径）

```
代数              : 1 → 21       （每轮 +1 ✅ 确实重建）
在册 JSContext    : 1 → 1        （差值 0 ✅）
JSRuntime 放弃回收 : 53 → 73      （差值 20）
进程 RSS          : 141MB → 151MB （差值 10MB）
每轮泄漏 runtime   : 1.00 个
```

### 4.3 读数解读

- **受我们控制的对象回收干净**：`JSContext` 在两条路径上差值都是 **0**，
  说明「判废 → 销毁 → 重建」这条链没有句柄堆积，这是本轮安全修复的核心目标，成立。
- **已知泄漏有确定速率**：**每次上下文销毁漏 1 个 `JSRuntime`**（严格 1.00/轮）。
  这正是 `deferred-todo.md` 记录的插件 `stringifyFn` 泄漏（两处 `JS_FreeValue`
  被上游注释掉，且该变量是全局的，直接打开注释是错的），因此 Dart 侧只能
  `reclaimRuntime = false`、只记账不释放。
- **对内存的实际影响**：约 **0.2MB / 轮**（9MB÷50、10MB÷20 一致）。按图源重度使用
  （一次会话导入+切换+失控重建 100 次）估算约 20MB 量级——**可感知但不致命**，
  与既有结论（「低概率、需长跑才显现」）一致。
- **结论**：本轮**不处理**（按要求只做记录）。已记入 `deferred-todo.md` 下轮候选，
  并附上本报告的可比较基线数字（1.00 个/轮、0.2MB/轮），将来修复后可直接对照。

## 五、真机手动复测清单（本机不可行，交给 iPhone 执行）

**为什么本机做不了**：真机复测需要 macOS + 完整 Xcode + 真机/模拟器；
本机为 Windows，`ios_preflight` 的 macOS、`xcode-select`、`xcodebuild`、`simctl`、
模拟器设备五项全部不可用。安装包为 unsigned IPA，也需先经 Sideloadly + 自有证书重签名。

以下每一步的**自动化等价验证均已通过**（第二、三节），真机只需确认
「iOS 系统交互与触摸路径」这一层：

### A. 安装与启动
1. 用 Sideloadly + 自有证书重签名 `LumeBox-unsigned.ipa` → 安装到 iPhone。
2. 打开 App：应正常启动，底部 5 个 Tab（小说 / 漫画 / 视频 / 猫源 / 设置）。
   - 若闪退：记录 iOS 版本与机型，附 `设置 → 错误报告` 导出的日志。

### B. 清单 1 · 死循环（真机路径）
3. 任一板块右上角「+」→ **本地文件** → 选一份死循环脚本
   （形如 `var LumeSource = {id:'t',name:'t',async list(){while(true){}}};`）。
   - 预期：**导入成功**（导入不阻塞）。
4. 进入该源并触发加载。
   - 预期：**UI 不永久卡死**，约 1–5 秒内出现超时/失败提示；
   - 预期：返回后 App **仍可正常操作**（切 Tab、再进该源都能用）。
   - 若 UI 真的卡死：记录卡死时长、是否能返回、是否最终恢复。
5. 连做 3–5 次第 4 步。
   - 预期：每次都能恢复，不出现越用越卡。
   - 观察内存：反复触发后 App 不应被杀（对应第四节 0.2MB/轮的泄漏速率）。

### C. 清单 2 · 图源导入冒烟（iOS 系统交互路径）
6. 「+」→ **本地文件** → 一次**多选** 2–3 份脚本（iOS 系统文件选择器多选）。
   - 预期：文件选择器支持多选；导入结果弹窗**逐条**列出「已导入 / 已覆盖」。
7. 「+」→ **订阅链接**：填入一个订阅地址 → 拉取并导入。
   - 预期：显示「正在拉取第 N 个地址…」，导入成功。
8. 「+」→ **从剪贴板**：先复制一段脚本，再点此按钮。
   - 预期：弹**系统「允许粘贴？」授权条**（这是设计如此：只在用户点按钮时读剪贴板）；
     允许后自动填入并提示「已从剪贴板填入脚本」。
9. 导入后：启用 / 停用 / 切换图源，各执行一次加载。
   - 预期：无闪退、无永久转圈；切换后能正常出内容。
10. 打开 `设置 → 错误报告`，确认无未预期的 error 级记录。

### D. 异常记录要求（若发现）
记录：**机型 + iOS 版本 + 复现步骤 + 截图/录屏 + `设置 → 错误报告` 导出日志**。
特别留意：闪退（是否有崩溃堆栈）、UI 卡死（持续多久、是否自动恢复）、
异常报错（原文文案）、以及反复操作后的内存表现（是否被系统杀掉）。
