# Lume Box · 本轮变更预览：QuickJS-NG 沙箱抽象封装层

## 一、先说三条实测结论（我直接加载插件编译出的 QuickJS 桥 DLL 跑出来的，决定了设计走向）

1. **插件没有导出 `JS_SetInterruptHandler`**（quickjs 本体符号被 hidden 可见性隐藏，PE 导出表里查不到该名字）。实测 `while(true){}` 无法中断，只能靠杀进程结束。
2. **但内存上限是硬限制**：`for(;;) a.push(new Array(10000).fill("x"))` 在 304ms 内抛 `InternalError: out of memory` 并中止本次求值。
3. **`jsFreeRuntime` 在 Debug 构建会 abort**：quickjs 的 `assert(list_empty(&rt->gc_obj_list))` 被触发——插件每次 `JS_NewContextDartBridge` 都往 runtime 泄漏一个全局 `stringifyFn`。实测 Debug 下进程 exit=3（abort），**Release 下 exit=0**；只调 `jsFreeContext` 则 30 次创建/销毁循环稳定 exit=0。
   → 结论：**现有 `lume_js_engine.dispose()` 在 Debug 构建会崩溃**，本轮顺手修掉。

另外实测确认可用的能力：多 Context 互相隔离（A 的全局变量在 B 里 `typeof` = undefined）、`jsGetException` 能取到 `Error: boom` / `TypeError: ...` 等真实错误文本（现有代码把错误信息全丢了）、async/await + 微任务排空正常、多 Context 共用一个原生回调并按 `ctx` 指针精确分发。

## 二、新增 `lib/core/js/sandbox/`（纯底层，不含任何图源业务）

| 文件 | 职责 |
|---|---|
| `sandbox_policy.dart` | `SandboxPolicy`：超时（默认 4s，强制收敛到 3–5s）、内存/栈上限、指令计数上限、宿主调用数/微任务轮数/求值次数/结果大小上限、`allowHostAccess`（默认 false）；`standard`/`strict` 两档预设 |
| `sandbox_result.dart` | `SandboxResult` 密封类 + `SandboxErrorKind{timeout, instructions, memory, script, hostDenied, protocol, disposed, unsupported}`；统一 JSON 信封编解码（需求 6：脚本执行结果以 JSON 回传 Dart） |
| `sandbox_host.dart` | 需求 4 的抽象代理接口：`SandboxHost.invoke(SandboxHostRequest)` + `DenyAllSandboxHost`（默认拒绝一切）；JS 侧只暴露 `LumeBridge.invoke(method, payloadJson)`，无 require、无文件、无 socket |
| `sandbox_polyfill.dart` | 需求 5：`SandboxPolyfill` 接口 + `PolyfillRegistry`（注册/去重/依赖序拼接 bootstrap，本轮默认空实现，不写垫片业务代码） |
| `sandbox_guard.dart` | 需求 2：原生中断通路（可用时按 deadline + 指令计数中断；`interruptAvailable=false` 时降级并只告警一次）+ Dart 侧预算记账 |
| `sandbox_context.dart` | 需求 1：单个隔离 JSContext 封装——runtime/context 创建、prelude 注入、求值、异常提取、微任务有界排空、`isPoisoned`、`destroy()`（freeContext 恒执行；freeRuntime 仅在安全构建下执行） |
| `lume_sandbox.dart` | 外观：`create/load/call/eval/dispose`；需求 3 的**污染即弃**——超时/异常/超预算后标记 poisoned，下次调用销毁旧上下文并重建**全新 generation**，永不复用 |
| `sandbox_manager.dart` | 需求 1：多沙箱注册表，按 id 隔离、`release`/`disposeAll` |
| `sandbox_scope.dart` + `sandbox_lifecycle.dart` | 需求 7：`SandboxScope` 按 owner 持有沙箱，逆序销毁；`SandboxScopeOwner` mixin 挂在 `State.dispose()` 上，页面退出自动销毁（只做生命周期接线，不加任何可见 UI） |
| `sandbox.dart` | 统一 export 桶文件 |

## 三、修改

- `qjs_bindings.dart`：新增惰性库解析 + `Qjs.overrideLibrary()`（测试/宿主注入）、`Qjs.isAvailable`、`jsGetException` 绑定、`Qjs.canFreeRuntime` 与安全销毁入口；保留现有全部 API。
- `lume_js_engine.dart`：**下沉为沙箱之上的薄适配层**。新增 `LumeSourceHost implements SandboxHost`（`fetch` → `LumeHttp`），对外 API（`isSupported/create/loadScript/metadata/call/dispose`）完全不变 → `source_registry.dart` 与各页面零改动。
- 删除 `js_guard.dart`（并入 `sandbox_guard.dart`）。

**补充两项 UI 小改**（按你的选择）：`GlassScaffold` 增加可选 `title`（默认仍为 Lume Box）；板块页标题＝小说/漫画/自定义视频/猫源，浏览页/详情页＝`小说 · 示例源` 形式（`DetailPage` 增加一个 `sourceName` 入参，由 BrowsePage 传入）；详情页章节项 `onTap` 弹 SnackBar「阅读器尚未实现」。

## 四、明确不做

Phase2 阅读器与 Phase3 高级功能；任何 Polyfill 垫片实现体；沙箱内的图源业务；MPV/MDK；不新增任何 pubspec 依赖。

## 五、关于「卡死」这条安全规范的诚实说明

该插件构建没有原生中断通路，**纯 CPU 死循环（不分配内存）无法被阻止**——这是插件层面的硬限制，不是设计选择。本轮的防护边界是：内存上限（硬，实测可中止）、栈上限、宿主调用/微任务/求值次数/结果大小预算（全部经 Dart，可真正取消并中止）、以及污染上下文永不复用 + 主动销毁重建。原生中断通路代码保留，插件一旦导出该符号即自动升级为真正的「超时 + 指令计数」中断。彻底隔离 CPU 死循环需要「每沙箱独立 isolate + 超时弃用整个 isolate」，涉及插件全局桥表的线程安全问题，建议作为后续单独立项，本轮不做。

## 六、验证方式

`flutter analyze` 零问题；`flutter test` 全绿（现有 8 项 + 新增沙箱套件）；新增两套测试：`test/sandbox_test.dart`（纯 Dart：策略收敛、JSON 信封、默认拒绝宿主、污染→重建、dispose 幂等、预算上限）与 `test/sandbox_native_test.dart`（真实引擎可用时才跑，Windows 走构建产物 DLL、iOS 走 `DynamicLibrary.process()`，验证多上下文隔离、内存上限中止、真实错误文本、销毁后重建、连续销毁稳定性）。
