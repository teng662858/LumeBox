# Lume Box · 视频播放进度记忆 + 首页「继续观看」

来源：文档「播放器补充约束」第 1 条——**视频记忆到集数 + 播放时间点**（漫画记忆
章节 + 页面位置，小说记忆章节 + 文字偏移，三者各自独立存储）。上一轮把视频板块
首页做成图源展示页后，看完一集退出就找不回来，这是最明显的体验缺口。

## 一、进度形状

`ReadingProgress` 密封类新增第三支 `VideoProgress`（`lib/core/reading/reading_models.dart`）：

| 板块 | 位置含义 | 落在哪一列 |
|---|---|---|
| 漫画 `ComicProgress` | 页序号 | `position`（`fraction` 存页内比例） |
| 小说 `NovelProgress` | 章节内字符偏移 | `position`（`chapter_length` 存章节字数） |
| **视频 `VideoProgress`（新）** | **播放毫秒** | `position`（`fraction` 存总时长毫秒） |

复用既有 `reading_progress` 表与 `library_item`（书架即「看过的作品」），因此
**不需要改库结构**——三支共用一张表，靠板块与形状区分。视频的「章」就是剧集，
选集列表的下标即 `chapterIndex`。

新增能力：
- `VideoProgress.isFinished`：≥95% 视为看完（时长未知时恒为 false——不凭空说人家看完了）；
- `VideoProgress.ratio` / `describe()`（`第 3 集 · 12:34 / 45:10`）；
- `withChapter`：切集时时间点归零；
- `ReadingLibrary.videoProgress(itemId)` / `continueWatching(limit)`。

## 二、录制与恢复（视频页）

| 时机 | 行为 |
|---|---|
| 起播（点条目 / 点继续观看） | 绑定作品身份 `VideoPlayTarget`；随后**恢复上次位置**（同一集才恢复；已看完或换集则不恢复） |
| 播放中 | 每 5 秒落一次盘（`_progressTimer`），且与上次落盘位置相差 < 2 秒时跳过（省掉无意义写库） |
| 暂停 / 停止 / 播放出错 | 立即落盘（`_onSnapshotChanged` 里检测「播放 → 非播放」） |
| 切集 / 换作品 | 先把上一部落盘，再开始新的 |
| 退出板块 | dispose 里最后落一次盘 |

两个实现细节值得记一笔：
- **dispose 顺序**：进度必须在「摘监听、清空 `_player`」之前落盘，否则读不到播放
  位置（第一版就踩了这个坑，测试当场抓出来）；
- **dispose 期间不 setState**：`_saveProgress` 会刷新「继续观看」列表，但销毁中
  元素已 defunct，加了 `_disposing` 守卫。

作品身份用 `VideoPlayTarget`（新文件）表达：有 `sourceId` / `itemId` / 剧集。
**手动贴地址不记进度**——没有作品身份，记了也无从还原。

## 三、首页「继续观看」

`ContinueWatchingSection`（新组件）放在首页浏览列表上方：

- 只在有播放记录时出现（没有记录整块隐藏，不占版面）；
- 每条显示作品名、`第 N 集 · 已看 / 总长`、进度条；已看完的标「已看完」；
- 点整条即续播（按记录里的**剧集 id** 找回同一集，图源章节改名或重排也能定位；
  id 找不到才回退按序号）；
- 长按移除记录（连同书架条目一起撤下，与书架「长按删除」同一套手感）。

## 四、边界与未做

- 视频进度**只记图源条目**，手动地址不记（理由见上）；
- 猫源板块的进度形状仍未定义（站点切换等形态未定），如实返回 null；
- 未做：跨集自动连播（播完自动下一集）、播放历史页（继续观看只是最近 10 条）、
  记录条数上限与清理策略。
