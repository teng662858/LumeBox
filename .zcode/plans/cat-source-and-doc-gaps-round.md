> 用户给的任务：先修 `9280.kstore.vip/cat/index.js.md5` 这个猫源，再按顺序补齐文档
> 点名的六项缺口（沙箱超时可配 → 批量刷新订阅源 → 图源分组与失效标记 →
> 主题跟随系统 → 调试面板 → 字幕与硬解开关）。

## 一、那份猫源订阅到底是什么（实测定性）

### 1.1 先确认订阅链路本身没问题

```
GET https://9280.kstore.vip/cat/index.js.md5  → e5b9b774af06f3014f4cf0087cdf07a9
GET https://9280.kstore.vip/cat/index.js      → 6,486,569 字节
md5sum index.js                               → e5b9b774af06f3014f4cf0087cdf07a9  ✅ 一致
```

订阅与 MD5 校验链路**完全正常**——问题在脚本本身。

### 1.2 放进真实沙箱：在哪一步失败

```
脚本大小: 6482903 字符
载入结果: false，耗时 1136ms
失败原因: 脚本错误: Error: 猫源沙箱不支持「dns」：沙箱不提供进程、线程与底层网络
          （域名解析也不开放）：网络请求走 fetch / LumeSource.http（宿主桥接层）…
```

### 1.3 但它不是图源脚本，是自建服务端

不满足于「报了个 dns」，把包拆开看了它的真实形状：

| 证据 | 实测结果 |
|---|---|
| 导出形态 | `module.exports = {start, stop}` —— **服务端入口**，不是图源契约 |
| 自报名 | `app: {name: "CatVodSpiderios", version: "0.1.0"}` |
| 路由数量 | **167 条**（`/spider/<key>/<type>/{home,category,detail,play,search}`、`/full-config`、`/proxy/*`、`/danmu*`、`/website/api/*`…） |
| 监听端口 | `.listen({port, host})`，实测起在 `127.0.0.1:9988` |
| 宿主桥 | `globalThis.messageToDart`（×23）——**它自己那套宿主桥** |
| require 模块 | `http2` / `net` / `tls` / `dns` / `worker_threads` / `fastify` / `axios`… |
| 网盘集成 | 夸克 / UC / 百度 / 115 / 123 / 189 / 139 / 光雅 / 迅雷 / 直连 |

**决定性验证**：本机用 Node 24 真的把它跑起来了：

```
CatVodSpiderios listening on http://127.0.0.1:9988
GET  /health        → 200 {"ok":true,"name":"CatVodSpiderios"}
GET  /full-config   → 200 13769 字节，video.sites 共 94 个站点
POST /spider/wogg/3/home     → 200（栏目：玩偶电影 / 剧集 / 动漫 / 综艺…）
POST /spider/wogg/3/category → 200（70 条真实片单，pagecount=168）
POST /spider/wogg/3/detail   → 200（vod_play_from: 夸克原画$$$夸克极速）
POST /spider/wogg/3/search   → 200（搜索「庆余年」命中 6 条）
POST /spider/wogg/3/play     → 500（网盘未登录；这是**它自己的**前置条件）
```

### 1.4 结论与出路

**定性**：这份订阅是 **CatVodSpiderios 自建聚合服务端**的打包产物，**不是图源脚本**。
它需要端口、进程、DNS 与自有宿主桥——iOS 沙箱**按设计**不提供这些（架构文档明令
禁止 Node / 端口 / 进程），**补垫片也跑不起来**。这与上一轮对另两份订阅的定性一致。

**出路**（架构文档写明的「降级备选：远端 Node 代理模式」）：服务跑在电脑 / NAS 上，
App 侧用薄壳脚本经宿主网络层转发。本轮把那个薄壳写出来了。

## 二、桥接薄壳（`assets/test_sources/catvod_bridge_source.js`）

用法三步：电脑上启动服务端 → 改脚本里的 `BASE_URL` → 导入**猫源**板块。

| 契约 | 映射 |
|---|---|
| `categories()` | 站点清单（`/full-config`）× 各站点栏目（`/home`）→ `站点 · 栏目` |
| `list({categoryId, keyword, page})` | `站点key\|栏目id` 拆开 → `/category` 或 `/search` |
| `detail({id})` | `站点@作品id` 拆开 → `/detail` |
| `chapters({id})` | `vod_play_from` × `vod_play_url` 摊平成「线路 · 集名」 |
| `content({id, chapterId})` | `/play`（线路名 + 剧集 id）→ 播放地址 |

**真机实测（本机跑真实服务端）**：

```
导入: true
分类数: 120
用分类: nodejs_wogg|1  玩偶|4K · 玩偶电影
列表条数: 70, hasMore=true
  首条: nodejs_wogg@/voddetail/132285.html | 一瞬之间
  详情: 一瞬之间
  章节数: 4
  首章: 夸克原画 · [1.1GB]Instante.2026.1080p.中英字幕.mp4【一瞬之间（2026）阿根廷】
```

### 写薄壳时踩到的两个坑（都修了，也写进了文档）

**坑 1：别在一个调用里逐站点取栏目。**
第一版 `categories()` 逐站点问 `/home`。真实服务端 94 个站点、每个 0.4–0.9 秒，
直接撞穿沙箱 4 秒预算（实测 `list` 报「调用超时」）。改为**按需解析 + 落缓存**：
分类页每次只补一批，列表页只解析自己那个站点。

**坑 2：连不上时要用「不重试」的请求探测。**
宿主网络层对 GET 这类幂等请求会自动重试（默认 3 次 + 退避）。服务端没开时整条
链路要 **7.8 秒**才抛错（实测），而沙箱预算是 4 秒——**沙箱先超时**，用户看到的是
笼统的「调用超时」，不是脚本里那句「连不上自建服务、去确认地址」。
改用 POST 探测（POST 不参与重试，约 2 秒即返回）后，可读提示才真的能送到用户眼前。

> 这个坑是**通用**的：任何「需要可读网络错误提示」的脚本都该这么写。
> 已写进 `docs/lumesource-guide.md` 的附录 B。

**测试**：`test/catvod_bridge_test.dart`（9 例）用本地替身服务端复刻 CatVod 的接口
形状，覆盖导入 / 分类 / 列表分页 / 搜索 / 详情 / 选集 / 播放 / 两种错误提示。

## 三、文档点名缺口的补齐

### ① JS 沙箱超时全局可配

文档第 4 条要求设置页能配「全局并发、全局 UA、全局代理、**JS沙箱超时**等」。

- 新增 `lib/core/js/sandbox_settings.dart`：3 / 4 / 5 秒三档（文档钉死的区间），
  落盘 `<应用支持目录>/sandbox_settings.json`，四板块共用；
- 引擎装配从 `LumeSandboxSettings.policy` 取策略（此前写死 `SandboxPolicy.standard`）；
- **只开放超时这一项**：内存 / 栈 / 指令计数 / 宿主调用数是防死循环的兜底，
  调大等于关掉保护。栈上限尤其危险——`SandboxPolicy` 注释里记着实测：1MB 会让
  进程当场死亡。页面里写明了「为什么这些不能改」，免得用户以为是自己没找到入口。
- 测试 12 例，其中一条专门逐项核对「改超时不会顺带动其余上限」。

### ② 批量刷新全部订阅源

图源总管理页工具栏新增刷新按钮：一次刷新四板块所有带订阅地址的源。

- 只处理**有订阅地址**的源（本地导入的跳过并说明）；
- 刷新前确认（会覆盖多份源）；逐板块逐源**串行**（不并发轰炸订阅站）；
- 汇总「更新 / 已是最新 / 失败」计数，有失败则逐条列出原因（模态弹窗，不是几秒就没的 Toast）；
- 覆盖口径与单源刷新一致：脚本 / 名称 / 版本换新，启停状态与网络配置保留。
- 测试 6 例（含「本地导入的源一个都不碰」「一条失败不中断整批」「按板块隔离」）。

### ③ 图源分组 + 失效标记

文档「图源导入/导出模块规范」：「图源重命名、图源分组（视频组/漫画组/小说组）」+
「图源损坏标记（标记失效源，不再自动重试）」。

- **分组**：用户自定的分组名（如「主力 / 备用」），只影响本板块列表的归类显示。
  刻意**不预设**「视频组 / 漫画组 / 小说组」——本 App 的板块已经是物理隔离的一层，
  再拿板块名当分组没意义；分组的用处是**同一板块内**按用户习惯归类。
  跨板块依旧完全隔离（跨板块看不到也改不到，有用例）。
- **失效标记**：连续失败 3 次即标记失效，**不再参与自动重试**（批量测试 / 批量刷新
  跳过它），列表标出「已失效（连错 N 次）」，菜单多一项「恢复」。
  阈值取 3：一次失败可能是网络抖动，连错三次才值得判定坏了。
  手动单测仍允许——用户想亲眼确认是合理的。
- **schema v4 → v5**：加三列（`source_group` / `failure_count` / `broken_at`）。
  旧库自动升级、数据一条不动；迁移不产生告警（有专门用例）。
- 测试 22 例（分组隔离、阈值边界、恢复、重开板块仍在、跨板块改不动、v4 旧库升级）。

### ④ 主题跟随系统

文档「全局主题补充」：「全局主题跟随系统；单独给阅读器独立主题」。

- 色板抽成 `LumePalette`（浅色 / 深色两套），`LumeTheme` 保留原静态名按当前亮度
  转发。**为什么不做成 ThemeExtension**：全仓库 300+ 处 `LumeTheme.textPrimary`
  这类引用、其中 78 处在 `const` 里，逐个改的改动面覆盖每个页面而收益只是「写法更
  现代」。代价（颜色读取依赖进程级当前亮度）与约束写在了类文档里。
- `MaterialApp` 加 `darkTheme` + `themeMode: ThemeMode.system`，并在 `builder` 里把
  实际生效的亮度回写、按亮度换 key（否则只换 ThemeData 不重建的页面会留着旧颜色）。
- **深色不是白底换黑底**：分层规则原样保留（底比卡更暗、玻璃半透明、卡片柔和阴影），
  语义色换成深底上可读的版本，状态栏图标跟着反。
- **阅读器不受影响**：小说 / 漫画阅读页读各自的阅读主题，与全局色板无关。
- 测试 12 例（两套色板的分层方向、文字对比度 ≥4.5:1、语义色可读性、状态栏明暗、
  默认仍是浅色、阅读器独立性）。

### ⑤ 调试面板

文档「调试日志规范」：「内置调试面板（仅开发者模式开启，正式构建隐藏）：JS 脚本执行
日志、网络请求日志、超时记录、报错堆栈、QuickJS 上下文创建/销毁记录、内存占用简易
统计、网络请求抓包预览（请求头、响应状态码）」。

- 新增 `lib/core/util/debug_request_log.dart` + `developer_mode.dart` +
  `lib/features/settings/debug_panel_page.dart`；
- 抓包挂在网络队列（所有 HTTP 的唯一出口），记方法 / 状态 / 耗时 / 来源 / 字节数 /
  请求头（**脱敏**：Cookie / Authorization / Set-Cookie 只留存在与长度）；
- **默认不收集**：要开「开发者模式」再开「请求抓包」；数据只留内存 200 条、
  不落盘不导出，关开关即清空；
- 运行环境区展示在册 JS 上下文数、放弃回收的 runtime 数、日志缓冲、全局网络参数。
- **关于「正式构建隐藏」**：本项目是自用工具，把入口藏起来只会让人找不到排障手段。
  真正要防的是「不知情时被收集」，那由「默认关闭 + 只留内存 + 不导出」保证。
  这个取舍写在了 `DeveloperMode` 的类文档里。
- 测试 20 例（默认不收集、开关生效、缓冲上限、关闭即清空、脱敏、落盘往返、页面交互）。

### ⑥ 字幕完善 + 硬件解码开关

文档：「外挂字幕（srt/ass），字幕轨道切换、字幕字号/颜色/描边，字幕延迟调节，
和弹幕参数面板分开」+「播放器增加硬件解码开关，部分设备硬解 HEVC 失败时可以切软解」。

- 字幕新增**颜色**（白/黄/绿/青，都不透明）、**描边**（无/细/粗）、**字号新增特大档**、
  **延迟**（±10 秒滑杆，0.1 秒精度）；
- 新增**硬件解码开关**（默认开）；
- **哪些真实生效（如实声明）**：
  - MPV 内核下**字号 / 颜色 / 描边真实生效**——media_kit 的字幕层是 Flutter Widget
    （`SubtitleViewConfiguration` 收完整 TextStyle），描边用多层阴影模拟；
  - **延迟与硬解当前只记录、不生效**：media_kit 的公开 Dart API 没有暴露 libmpv 的
    `sub-delay` 与 `hwdec` 写通道（`setProperty` 是私有的，`PlayerConfiguration`
    里也没有 hwdec 项）。设置值正常落库，等有通道时生效。设置页与引擎注释都写明
    这一点——**不假装支持**。
- 测试 18 例（模型归一、落库往返、旧库缺键回退、页面交互、字幕关闭时样式不可改）。
