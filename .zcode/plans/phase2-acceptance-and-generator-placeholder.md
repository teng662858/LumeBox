## 二、验收清单的自动化核验（逐项）

### 2.1 三套独立 demo 脚本 + 板块隔离

`flutter test test/js_sandbox/smoke_test.dart`（一条命令跑完，跑完打印汇总表）：

```
[冒烟汇总]
  · 小说 demo：分类 2 个 · 列表 2 条 · 正文 24 字 ✓
  · 漫画 demo：分类 3 个 · 列表 2 条 · 本章图片 3 张 ✓
  · 视频 demo：列表 1 条 · 选集 2 个 · 播放地址 https ✓
  · 跨板块拒绝：3 组全部被拦下并给出跨板块原因 ✓
  · 死循环：instructions 判定 · 代数 1→2 · 重建可用 ✓
  · 上下文隔离：同名存储跨板块读不到（小说侧为空）✓
```

三份脚本各自绑定板块（头部 + 运行时都声明 `category`），**跨板块导入在导入阶段
就被拒**，不会出现「导入成功、点开才报内容类型不对」。四组跨板块组合
（小说→漫画 / 小说→视频 / 漫画→小说 / 视频→漫画）全部断言过。

**「不会跨板块读取内容」的证据链**（三层，都有用例）：

1. **导入层**：`category` 与目标板块不符即拒绝，零落库
   （`test/js_sandbox/section_category_test.dart` 6 例）；
2. **记录层**：库内记录带归属标记，跨板块记录在列出 / 加载 / 启停 / 删除四条
   路径上都按「不存在」处理（`test/section_database_test.dart`）；
3. **运行时层**：同一份脚本、同一个 id 落在两个板块 → 各自的 `fs` 存储互不可见
   （冒烟第 3 条）。

### 2.2 MPV 播放器边界

`test/player_switch_recovery_test.dart`（7 例）+ 本轮新增 2 例，覆盖用户报的两个
现象（「一直转圈」「右上角设置入口消失」）以及它们的各种读法：

| 场景 | 断言 |
|---|---|
| 两个内核都起不来 | 「播放器准备失败」+「重试 / 切回 AVPlayer」+ **控制栏齿轮在** + 顶栏「追剧日历 / 源管理」在 |
| 设置库打不开 | 同上（重试 + 设置入口都在） |
| MPV 抛错 | 自动回退 AVPlayer，页面有画面、齿轮可用、顶栏入口不受影响 |
| 失败态点「重试」 | 真的重建 MPV（解除熔断 → 第二次成功） |
| 熔断中的 MPV | 设置页里可「重试」恢复可选（不必重启 App） |
| 接续失败（applySettings / load 抛错） | 不空转：画面仍在 + 说明可重试 |
| 连续快速切换 | 过期重建的实例被释放、界面显示最后选中的内核 |
| **换内核摘监听**（本轮新增） | 被换下的实例**不再持有页面监听**（否则旧快照仍会改写进度 / 连播 / Dock） |
| **反复来回切换**（本轮新增） | 四轮切换后，只有最后一个实例持有监听，其余全部为 0 |

「杀 App 重进视频板块」这条对应的是**状态重建**：`_boot()` 在 `initState` 里跑，
库打不开时给可读提示 + 重试出口（有用例）；设置库与阅读库**分开打开**，
前者失败不拦播放。真机上再切一次即可确认触摸路径。

### 2.3 JS 沙箱安全（死循环超时销毁）

`test/js_sandbox/deadloop_timeout_test.dart` + `security_audit_test.dart` +
`malicious_script_test.dart`（10 例攻击矩阵）：

- 纯 CPU 死循环 `while(true){}`：**1 秒内被回收**，判定为 `instructions` 或
  `timeout`（哪个预算先到取决于机器负载，两条都接受），上下文销毁、重建后可用；
- 导入死循环脚本**本身不阻塞**（导入期只做语法与元信息校验，不跑方法体）；
- 一个源失控**不牵连**其它源；
- 反复触发 5 次：每轮都收得回来，代数逐轮递增（1→2→3→4→5），
  `JSContext` 在册数不累积；
- **App 不会崩溃**：以上全部在独立 isolate 里观测，主进程始终存活
  （纯 CPU 空转会把调用线程占住，这正是必须开 isolate 观测的原因）。

已知遗留（如实记录，本轮不处理）：插件 `stringifyFn` 泄漏导致每次上下文销毁漏
1 个 `JSRuntime`（≈0.2 MB/轮），详见 `deferred-todo.md` 下轮候选。

### 2.4 Venera 漫画源全流程

`test/js_sandbox/venera_bridge_test.dart`（6 例，真 QuickJS + 本机示例站）：

- **脚本识别**：从文本里读出 `class X extends ComicSource` 的类名，且**先剥注释
  与字符串**（真实脚本注释里常写着示例类名，不剥会认错）；
- **JSON 型源**：`key/name/version` 成为图源身份、板块自报为漫画、导入小说板块被拒；
- **全链路**：分类（explore）→ 列表 → 搜索 → 详情 → 章节 → 图片；
- **HTML 型源**：`querySelectorAll('div.list > a.item')` 抓列表 + 详情 + 图片；
- **能力边界**：`Convert.md5('abc')` = 标准向量（宿主计算）；`sha256` 与 `login`
  点名报错（不静默返回空）；`saveData/loadData` 往返成功；
- **HtmlDocument 子集**：`.类` / `[属性=值]` / `#id` 命中，伪类明确报错。

### 2.5 图源导入错误提示

`test/js_sandbox/import_guard_test.dart` + `test/source_import_failure_test.dart`：

- 服务端类模块（`http2` / `net` / `dns` / `child_process`…）：点名模块 + 说明
  「需要端口与进程，**补上这个模块也跑不起来**」+ 给出该走的路（fetch / `LumeSource.http`）；
- 零图源入口的脚本：导入阶段判定「这不是本 App 的图源脚本」，说明它像什么
  （别的客户端的扩展程序包）、本 App 的源脚本该怎么写；
- 语法错误：原样带出引擎的 `SyntaxError` 原文；
- id 不合法：点名是哪个字符、哪个码位（长破折号与全角符号会被拒）；
- 跨板块：点名两个板块，并告诉用户该导入哪个板块。

**本轮在这条链路上发现并修掉了一处误报**（见下节 Bug 1）。

## 三、验收中发现并修复的三处 bug

三处都不是「功能没做」，而是**边界没收干净**，且都属于用户看得到假信息 /
页面状态被作废对象改写这一类。每处都配了回归用例，并**验证过「把修复回退后用例
必然失败」**（否则用例是空的）。

### Bug 1 · 普通语法错误被误报成「自建服务端程序」

- **现象**：一份 `SyntaxError: Unexpected token in internet explorer` 形状的报错，
  提示里会多出一段「若这是需要 node 运行的自建服务端程序，它不是源脚本……」
- **根因**：`_serverCapabilityPattern` 用的是**子串匹配**，`internet` / `network` /
  `magnet` / `genetics` 里的 `net` 全都命中。
- **为什么比不给提示更糟**：用户会照着提示去改网络写法，而真正的问题是少了个括号。
- **修法**：改为**整词**匹配（两侧用非标识符字符作边界，`net::ERR_` 与
  `net.createServer` 仍能命中）。
- **落点**：`lib/core/js/source_registry.dart`。

### Bug 2 · 全新板块库记四条假的「迁移失败」告警

- **现象**：每个板块**首次**打开都往日志里写四条
  `迁移 source.origin_url 跳过: duplicate column name: origin_url`。
- **根因**：建表用的 schema 已经带了后续版本追加的全部列，迁移段却仍按「旧库」
  逐列 `ALTER TABLE ADD COLUMN`，撞 duplicate 后每条写一条 warn。
- **影响**：用户从「设置 → 错误报告」导出的日志里常驻一堆并不存在的故障，
  排障时先被这四条带偏（真机上很容易被当成「数据库坏了」）。
- **修法**：记住「本次是新建库」，跳过迁移段；**旧库（v1/v2/v3）路径一行未改**
  （有专门用例钉住仍会补列并回填板块归属）。
- **落点**：`lib/core/db/section_database.dart`。

### Bug 3 · 换内核时摘错了监听回调

- **现象**：来回切换播放内核时，页面可能莫名落一次播放进度、或底部导航的显隐
  被已作废的播放器改掉。
- **根因**：挂上去的是 `_onSnapshotChanged`（负责落进度 / 判连播 / 改 Dock 显隐），
  摘的却是 `_syncDockForPlayback` —— **挂 A 摘 B 等于没摘**。旧实例在释放过程中
  吐出的快照仍会被页面当成当前状态处理，来回切换还会累积多个「幽灵订阅者」。
- **修法**：摘掉当初挂上去的那个回调。
- **落点**：`lib/features/video/video_page.dart`。

**回归测试**：`test/phase2_acceptance_regression_test.dart`（8 例）。
其中 Bug 3 的用例刻意用「记账版通知者按**监听者身份**计数」——
若只记次数递减，`removeListener` 对没注册过的回调是静默 no-op，
「摘错了人」反而会被记成摘干净了，用例就永远抓不到这个 bug（这一步调试过）。

## 四、图源生成器（可视化爬虫模块）：占位框架

### 做了什么

| 项 | 落点 |
|---|---|
| 设置页入口「图源生成器（开发中）」 | `lib/features/settings/settings_page.dart` |
| 静态占位页（UI 骨架 + 按钮弹「功能开发中」） | `lib/features/settings/source_generator_page.dart` |
| 预留数据表 `crawler_config` | `lib/core/generator/generator_database.dart` |
| 测试（13 例） | `test/source_generator_test.dart` |

**页面骨架**按「可视化爬虫」将来的分区摆好，与数据表字段一一对应：

- 目标网址区：网址输入、分页参数名、编码（UTF-8 / GBK）；
- 正则 / 选择器配置区：列表规则、详情规则、正文规则、附加请求头（JSON）；
- 生成与预览区：「预览抓取结果」「生成图源脚本」两颗按钮 + 一句边界说明
  （生成的脚本会走对应板块的正常导入链路，不绕过板块隔离）。

所有输入框**只读**（用 `AbsorbPointer` + `readOnly` 而不是 `enabled: false`：
后者在浅色主题下整体灰掉，看不出「这里将来是个输入框」）；所有按钮点击弹
「功能开发中」，并给出当下可用的替代路径（手写脚本 + 开发文档）。

### 三条定死的边界（后续迭代请沿用）

1. **入口留在全局设置页**，不新增底部 Tab —— 底部 5 个主 Tab
   （小说 / 漫画 / 视频 / 猫源 / 设置）保持不变。生成器是工具附属功能，
   不是主阅读板块，放设置页逻辑更顺。
2. **生成器库 `generator.db` 落在应用支持目录根部**，不进 `sections/<id>/` ——
   它不是任何板块的数据，放进板块目录会被误读成板块资产，与四板块隔离的口径冲突。
   有用例断言这个落点。
3. **生成出来的图源必须走目标板块的正常导入链路**（`SourceRegistry.import`），
   本模块**不提供任何直接写图源表的入口** —— 板块隔离由那条链路把关，
   不在这里开口子。

### 明确没做什么（本轮范围）

不发请求、不解析页面、不生成脚本、不写图源 —— **零爬虫业务逻辑**。
Phase2 已交付的图源、沙箱、播放器逻辑**一行未改**（本轮对它们的改动只有
第三节那三处 bug 修复）。

6. **设置页**：确认「图源生成器（开发中）」入口在设置页底部，点进去是占位页、
   按钮弹「功能开发中」。

异常记录要求：机型 + iOS 版本 + 复现步骤 + 截图/录屏 +
